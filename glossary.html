📖 Glossary

The 120 WordPress terms used in this course, from the Abilities API to WP_Query, in alphabetical order. Each entry says what the term means in WordPress 7.1 and links to the lesson that teaches it.

Jump to: A · B · C · D · E · F · G · H · I · L · M · N · O · P · Q · R · S · T · W

See also the Cheat Sheet (commands, hooks and functions on one page), Common Errors (what each message means) and Troubleshooting (environment problems).

A

Abilities API

A registry of things a site can do, described for other programs (and AI models): wp_register_ability() on wp_abilities_api_init with a label, description, category, input and output schema, execute_callback and permission_callback. Abilities can be listed and run through the REST namespace wp-abilities/v1. In core since WordPress 6.9; the course adds pagesco/check-stock. See Lesson 7.3 and Lesson 9.2.

Action

A hook that marks a moment: do_action( 'init' ) runs every callback added with add_action(), and nothing is returned. Use an action to do something at the right time (register a post type, print the store notice). Compare filter. See Lesson 2.3.

Activation, Deactivation and Uninstall

The three moments in a plugin's life with their own code: register_activation_hook() and register_deactivation_hook() (called at the top level of the main file, with __FILE__) and the file uninstall.php, which runs when the plugin is deleted. Activation sets things up (roles, tables, rewrite rules); only uninstall removes stored data. See Lesson 5.1 and Lesson 8.3.

add_theme_support()

Tells WordPress which optional features a classic theme handles, such as title-tag, post-thumbnails, html5 or automatic-feed-links, called on after_setup_theme. Block themes get most of these automatically. See Lesson 4.3.

admin-post.php

The wp-admin endpoint for your own form and link handlers: a request with action=pagesco_books_toggle_stock fires the hook admin_post_pagesco_books_toggle_stock (and admin_post_nopriv_… for visitors who are not logged in). The handler checks a nonce and a capability, does the work and redirects. See Lesson 5.3.

AI Client

WordPress 7.0's provider-neutral way to ask an AI model: wp_ai_client_prompt( $prompt )->generate_text() returns a string or a WP_Error. No provider ships with core; a provider plugin and an API key (Settings > Connectors) make it answer. See Lesson 9.2.

apiFetch

WordPress's JavaScript wrapper around fetch() for the REST API (wp.apiFetch, script handle wp-api-fetch). In wp-admin it adds the root URL and the X-WP-Nonce header for you, so requests run as the logged-in user. See Lesson 7.1.

Application Password

A separate, revocable password for programs that call the REST API with HTTP Basic authentication (curl --user "maria:xxxx xxxx …"). Created under Users > Profile or with wp user application-password create. WordPress offers them only over HTTPS or on a site whose environment type is local. See Lesson 7.1.

Archive

A page that lists posts: a category, tag, author, date or post type archive (/books/ when a post type has has_archive). In the template hierarchy, archive is the fallback for all of them. See Lesson 3.1 and Lesson 5.2.

Attributes (Block)

The data a block keeps, declared in block.json. An attribute with a source (html, text, attribute) is read from the saved HTML; one without a source is stored as JSON in the block comment. PHP's parse_blocks() only sees the comment attributes. See Lesson 6.2.

Autoloading (Composer)

Loading a PHP class file automatically the first time the class is used. The plugin's composer.json maps the namespace PagesCo\Books\ to src/ (PSR-4), so PagesCo\Books\Admin\SettingsPage lives in src/Admin/SettingsPage.php, with exactly that capitalization. See Lesson 5.1.

Autoload (Options)

Whether an option is loaded with all the others in one query on every request. Values in WordPress 6.6 and later: on, off, auto, auto-on, auto-off; add_option() without the argument picks auto. Large or rarely used options belong off autoload. See Lesson 2.2.

B

Block

One piece of content or layout in the block editor (a paragraph, an image, the Book Card). Saved in post_content as HTML between comment delimiters; a block type is registered from its block.json. See Lesson 2.1 and Lesson 6.1.

Block Bindings

Connecting a core block's attribute (paragraph or heading text, list-item text in 7.1, image URL, button link) to a value from a source, through metadata.bindings in the block's comment. Core sources include core/post-meta; plugins add their own with register_block_bindings_source(), as the course's pagesco/book. See Lesson 6.3.

block.json

The metadata file of a block type: apiVersion (3), name, title, category, attributes, supports, textdomain, and the files WordPress loads (editorScript, style, render, viewScriptModule). PHP and JavaScript both register the block from it. See Lesson 6.1.

Block Markup

How the editor saves blocks in post_content: HTML wrapped in comments such as <!-- wp:paragraph --> … <!-- /wp:paragraph -->, with attributes as JSON in the opening comment and dynamic blocks self-closing (<!-- wp:pagesco/book-list /-->). The core/ namespace is left out. See Lesson 2.1.

blocks-manifest.php

A PHP file that wp-scripts build --blocks-manifest writes into build/blocks/, holding every built block's block.json as an array. wp_register_block_types_from_metadata_collection() registers them all from it, so a new block needs no PHP change. See Lesson 6.1.

Block Supports

Ready-made features a block switches on in block.json ("supports": { "color": …, "spacing": …, "typography": … }): WordPress adds the controls, stores the choices and prints the classes and styles through useBlockProps() or get_block_wrapper_attributes(). See Lesson 6.2.

Block Theme

A theme built from HTML templates of block markup (templates/index.html), template parts and theme.json, editable in the Site Editor. Twenty Twenty-Five and the course's pagesco are block themes. Compare classic theme. See Lesson 3.1 and Lesson 3.2.

Block Validation

The editor's check, on loading a post, that each static block's saved HTML matches what its current save() would produce. A mismatch shows "Block contains unexpected or invalid content" unless a deprecation recognizes the old markup. See Lesson 6.2.

Block Variation

A preset of a block's attributes with its own name in the inserter, such as the Book List's "New Arrivals". Declared in JavaScript or, as in the course, in a PHP file named by "variations": "file:./variations.php" in block.json. See Lesson 6.3.

Build (npm run build)

Compiling a block's sources in src/blocks/ (JSX, SCSS) into the files WordPress loads in build/blocks/, with @wordpress/scripts. WordPress reads only build/: after a change in src/, rebuild (or keep npm start running). See Lesson 6.1.

C

Callback

A function passed to WordPress to call later: a function name as a string ('pagesco_render_store_notice'), a closure, or an object method as array( $this, 'method' ). Hooks, shortcodes, REST routes and settings all take callbacks. See Lesson 1.3.

Capability

A named permission such as edit_posts or manage_options; roles are bundles of capabilities. Check them with current_user_can(). A meta capability takes an object ID (current_user_can( 'edit_post', 30 )) and is mapped to the right primitive capability for that user and that post. See Lesson 2.1 and Lesson 5.3.

Child Theme

A theme whose style.css names a parent with Template: twentytwentyfive (the parent's folder name). It overrides only the files it contains (templates, parts, patterns) and merges its theme.json over the parent's; its functions.php loads before the parent's. See Lesson 3.4.

Classic Theme

A theme made of PHP templates (index.php, header.php, singular.php) that print the whole page with the Loop and template tags, and that must call wp_head(), wp_body_open() and wp_footer() itself. A classic theme that also has a theme.json is informally called a hybrid theme, as pagesco-classic becomes in Module 4. See Lesson 3.1 and Lesson 4.1.

Coding Standards (WPCS)

The WordPress Coding Standards: tabs, spaces inside parentheses, Yoda conditions, snake_case with a prefix, escaping and nonce rules. PHP_CodeSniffer (PHPCS) checks code against them with the WordPress ruleset; the plugin's phpcs.xml.dist configures it, composer lint runs it, composer lint:fix (phpcbf) fixes what it can, and // phpcs:ignore Rule -- reason documents an exception. See Lesson 1.3 and Lesson 8.1.

Conditional Tags

Functions that answer questions about the current request from the main query: is_front_page(), is_home(), is_singular( 'post' ), is_page( 'about' ), is_category(), is_search(), is_404(). Before the query runs they always return false. See Lesson 4.1.

Context (Interactivity API)

Data that belongs to one element and its children, written on the server with wp_interactivity_data_wp_context() into a data-wp-context attribute and read in JavaScript with getContext(). Compare state, which is shared by the whole page. See Lesson 6.4.

Core

The files WordPress itself ships: everything outside wp-content/ (and wp-config.php). Never edit core: wp core verify-checksums finds the change and the next update overwrites it. See Lesson 1.1.

Core Web Vitals

Google's three measures of a page's experience: Largest Contentful Paint (loading, good under 2.5 s), Interaction to Next Paint (responsiveness) and Cumulative Layout Shift (visual stability). Lab tools measure them on your machine; field data comes from real visitors. See Lesson 8.2.

create-block

The official scaffolding tool, npx @wordpress/create-block@latest. The course adds blocks to the existing plugin with --no-plugin --target-dir=src/blocks/<slug> --namespace=pagesco --textdomain=pagesco-books, --variant dynamic for a server-rendered block, and --template @wordpress/create-block-interactive-template for an interactive one. See Lesson 6.1, Lesson 6.3 and Lesson 6.4.

Custom Post Type

A new kind of post registered with register_post_type() on init, such as the course's book: its own admin menu, URLs (/books/dune/), templates and REST route (/wp/v2/books), stored in the same wp_posts table. See Lesson 5.2.

Custom Table

A database table of a plugin's own, such as wp_pagesco_events, for data that does not fit posts, terms or options (many rows with typed columns, queried by those columns). Created with dbDelta() and named with $wpdb->prefix. See Lesson 5.5.

D

dbDelta()

The function (in wp-admin/includes/upgrade.php) that creates a table or adds missing columns and indexes so the table matches a CREATE TABLE statement. It never renames or drops; run it from activation and from a version check when the stored schema version is older: the plugin keeps its version in the option pagesco_books_db_version and adds explicit steps for renames. See Lesson 5.5.

debug.log

The file wp-content/debug.log, where WordPress writes PHP errors and error_log() lines when WP_DEBUG and WP_DEBUG_LOG are on. Watch it with tail -f wordpress/wp-content/debug.log. On a server, give it a path outside the web root. See Lesson 1.2 and Lesson 8.1.

Deprecation (Block)

An entry in a block's deprecated array that describes an older version (its attributes, supports and save()), so posts saved with the old markup still validate; migrate() can turn old attributes into new ones. Newest first. See Lesson 6.2.

Directives

The data-wp-* attributes of the Interactivity API: data-wp-interactive (the store namespace), data-wp-context, data-wp-on--click, data-wp-bind--hidden, data-wp-class--is-selected, data-wp-text and more. WordPress processes them on the server too, so the first HTML is already right. See Lesson 6.4.

doing_it_wrong ("called incorrectly")

WordPress's notice for an API used the wrong way or at the wrong time: "Function X was called incorrectly. … (This message was added in version …)". Shown only with WP_DEBUG on; during REST requests it goes into an X-WP-DoingItWrong response header instead. See Lesson 4.1 and Lesson 8.1.

Drop-in

A file with a reserved name placed directly in wp-content/ that replaces a part of core, such as object-cache.php (a persistent object cache), advanced-cache.php (page caching) or db.php. See Lesson 2.2 and Lesson 8.2.

Dynamic Block

A block whose front-end HTML is produced by PHP on every page view (its render.php), so it always shows current data. It saves only its comment and attributes. Compare static block. See Lesson 6.3.

E

Enqueue

Adding a stylesheet or script to the page through WordPress (wp_enqueue_style(), wp_enqueue_script()) on wp_enqueue_scripts, admin_enqueue_scripts or login_enqueue_scripts, with a handle, dependencies and a version, instead of printing a tag yourself. See Lesson 4.3.

Environment Type

The site's kind, from WP_ENVIRONMENT_TYPE: local, development, staging or production (the default), read with wp_get_environment_type(). The course site is local; core sends pings only from production and allows application passwords over HTTP only on local. See Lesson 1.2 and Lesson 8.4.

Escaping

Making a value safe for the place it is printed, as late as possible: esc_html() for text, esc_attr() for attributes, esc_url() for links, wp_kses_post() for HTML with safe tags. The defense against XSS (cross-site scripting: a script smuggled into the page through data printed unescaped). See Lesson 1.3 and Lesson 5.3.

F

Feature Class (Pages & Co.)

The course plugin's structure: each feature is one class in src/ that implements PagesCo\Books\Feature and adds its hooks in register(); Plugin::feature_classes() lists them, and the filter pagesco_books_features lets others change the list. See Lesson 5.1.

Filter

A hook that passes a value through callbacks: apply_filters( 'the_title', $title ) gives the value to each callback added with add_filter(), and each one must return it, changed or not. Compare action. See Lesson 2.3.

fontFace

The theme.json key that bundles web fonts with a theme ("src": [ "file:./assets/fonts/…woff2" ]); WordPress prints the @font-face rules itself. Appearance > Fonts manages fonts as well. See Lesson 3.3.

Front Page and Home

In the template hierarchy, front-page is the site's front page whatever it shows, while home is the list of latest posts (the blog index), wherever that lives. With a static front page, home is not used for /. See Lesson 3.1.

functions.php

A theme's PHP file that runs on every request while the theme is active (after plugins, before init): theme supports, enqueued assets, menu locations, widget areas, pattern categories. Site features belong in a plugin instead. See Lesson 4.3.

G

Globals

Variables core shares across files, such as $wpdb (the database), $post (the current post in the Loop), $wp_query (the main query) and $wp_version. Read them with global $wpdb;, prefer functions when there are some, and never overwrite them. See Lesson 1.3.

H

Headless WordPress

Using WordPress only as the content back end while a separate front end (another site, an app) fetches the content through the REST API. It costs previews, plugins' front-end features and SEO work; it pays when several front ends share the content. See Lesson 9.2.

Hook

A named place where WordPress lets your code run (an action) or change a value (a filter). Hooks are how plugins and themes change WordPress without editing it. See Lesson 2.3.

I

i18n and l10n

Internationalization (i18n) makes code translatable: strings wrapped in __(), esc_html__(), _n(), _x() with a literal text domain. Localization (l10n) is the translation itself, in PO, MO, .l10n.php and JSON files. See Lesson 1.3 and Lesson 8.3.

Interactivity API

WordPress's standard for front-end behavior in blocks: HTML rendered on the server carries directives, and a small store in a script module (store() from @wordpress/interactivity) reacts to clicks. The course's Book Filter uses it. See Lesson 6.4.

L

Loop (The Loop)

The classic pattern that walks through a query's posts: while ( have_posts() ) { the_post(); … }. the_post() sets the global $post, so template tags inside the Loop refer to the current post. See Lesson 4.1.

M

Mailpit

The course's mail catcher: a fake SMTP server with a web inbox at http://localhost:8025. The must-use plugin mailpit-smtp.php sends all of WordPress's email there and fixes the sender address. See Lesson 1.2.

Main Query

The query WordPress runs for the URL before choosing a template (stored in $wp_query): the posts the page is "about". Change it with pre_get_posts; extra lists on a page are secondary queries. See Lesson 4.2.

Meta Box

A panel on a post's edit screen, added with add_meta_box() on add_meta_boxes_{post_type} and saved on save_post_{post_type}. The Book details box saves the book meta, with a nonce and a capability check. See Lesson 5.2 and Lesson 5.3.

Meta (Metadata)

Extra key-value data attached to a post, user, term or comment, in the wp_postmeta-style tables: get_post_meta( $id, $key, true ). Every value is stored as a string; register_post_meta() declares a key's type, and show_in_rest exposes it. See Lesson 2.2 and Lesson 5.2.

Must-Use Plugin

A PHP file in wp-content/mu-plugins/ that WordPress always loads, before normal plugins, and that cannot be deactivated in the admin. The course keeps mailpit-smtp.php and pagesco-site.php there. See Lesson 2.3 and Lesson 1.2.

N

N+1 Queries

One query for a list, then one more for each item: for example a loop calling get_post_meta() on posts fetched with 'fields' => 'ids'. Fix it by priming the cache once, with update_postmeta_cache( $ids ). See Lesson 8.2.

Namespace (REST)

The first part of a REST route, vendor plus version: core's wp/v2, the course's pagesco/v1. See Lesson 7.1 and Lesson 7.2.

Nonce

A token, tied to a user, an action and a time window, that proves a request came from your own form or link (wp_nonce_field(), wp_nonce_url(), checked with check_admin_referer() or wp_verify_nonce()). It is WordPress's defense against CSRF (a forged request from another site), not a permission check: pair it with current_user_can(). See Lesson 5.3.

O

Object Cache

WordPress's in-memory store for data it has already loaded (wp_cache_get(), wp_cache_set(), grouped by key). By default it lasts one request; an object-cache.php drop-in backed by Redis, Memcached or SQLite makes it persistent. See Lesson 8.2.

Options API

Site-wide settings stored as rows of wp_options: get_option(), update_option(), add_option(), delete_option(). Every screen under Settings is options. The course plugin keeps its settings in one array option, pagesco_books_settings. See Lesson 2.1 and Lesson 5.4.

P

Pattern

A ready-made group of blocks people can insert. A theme registers its patterns from PHP files in patterns/ whose header gives at least Title and Slug; templates insert one with <!-- wp:pattern {"slug":"pagesco/hero"} /-->. See Lesson 3.3.

Pattern Cache

WordPress caches the list of a theme's pattern files in a site transient for 30 minutes, valid for one theme Version. WP_DEVELOPMENT_MODE 'theme' switches it off on the course site; on a live site, raise the theme's Version with each release. See Lesson 3.3 and Lesson 8.4.

Permalinks

The URL structure of posts and pages. The course uses "pretty" permalinks, /%postname%/, set with wp rewrite structure; a WP-CLI install leaves the plain /?p=1 style. See Lesson 1.2.

permission_callback

The required argument of register_rest_route() that decides who may call an endpoint: return true, false or a WP_Error with a status. Use '__return_true' only for deliberately public reads. See Lesson 7.2.

PHPUnit and WP_UnitTestCase

Automated tests for the plugin: classes that extend WP_UnitTestCase run inside a real WordPress whose database changes are rolled back after each test. The course runs them in a wp-env test site with vendor/bin/phpunit. See Lesson 8.1.

Playground

WordPress running in WebAssembly, in a browser tab (playground.wordpress.net) or from the command line with npx @wp-playground/cli@latest server; good for quick tries, with SQLite and /wordpress/ paths. See Lesson 1.1 and Lesson 1.2.

Pluggable Function

A function core or a parent theme defines only if it does not exist yet (if ( ! function_exists( … ) )), so a plugin or child theme that loads first can replace it. See Lesson 2.2 and Lesson 3.4.

Plugin

A folder in wp-content/plugins/ with a main PHP file whose header starts with Plugin Name:, adding features to a site through hooks. Features belong in plugins; presentation in themes. See Lesson 5.1.

Plugin Check

The official plugin that runs the WordPress.org directory's checks (security, headers, readme, files that should not ship) on a plugin: wp plugin check pagesco-books. See Lesson 8.3.

Plugin Header

The comment at the top of a plugin's main file: Plugin Name (required), Description, Version, Requires at least, Requires PHP, License, Text Domain, Domain Path, Update URI. WordPress refuses activation when the requirements are not met. See Lesson 5.1.

POT, PO and MO Files

Translation files: wp i18n make-pot extracts a plugin's strings into a POT template; a translator writes a PO file per language; make-mo, make-php and make-json compile it for PHP and JavaScript. See Lesson 8.3.

Prefix

A project-specific start for every global name (functions, classes, constants, hooks, options, handles): pagesco_, pagesco_books_. Without one, two plugins with the same function name take a site down. See Lesson 1.3.

pre_get_posts

The action that receives every WP_Query before it runs, so you can change the main query in place ($query->set( 'posts_per_page', 3 )). Guard it with is_admin(), $query->is_main_query() and the kind of page. See Lesson 4.2.

prepare() ($wpdb)

$wpdb->prepare() builds SQL with placeholders that it quotes and escapes: %s string, %d integer, %f float, %i identifier (table or column name, WordPress 6.2+). Every query with a variable in it goes through it. See Lesson 5.3 and Lesson 5.5.

Priority

The number that orders callbacks on the same hook: lower runs first, the default is 10, and ties run in the order they were added. add_filter( 'pagesco_store_notice', 'pagesco_notice_late_opening', 20 ) runs after the defaults. See Lesson 2.3.

Q

Query Loop Block

The block (core/query with core/post-template inside) that lists posts in a block template. With "inherit": true it shows the main query. See Lesson 3.2.

Query Monitor

A developer plugin that shows, for each page, its database queries, hooks, HTTP requests, PHP errors and the template used. Install it while debugging and remove it afterwards. See Lesson 8.1.

R

readme.txt

The plugin directory's description file: a header (Requires at least, Tested up to, Requires PHP, Stable tag, License) and sections such as Description, FAQ, Changelog and Upgrade Notice. See Lesson 8.3.

render.php

The PHP file that produces a dynamic block's HTML, named in block.json with "render": "file:./render.php". WordPress gives it $attributes, $content and $block; the wrapper gets get_block_wrapper_attributes(). See Lesson 6.3.

REST API

WordPress's JSON interface under /wp-json/: routes such as /wp/v2/books answer HTTP methods with JSON, status codes and headers (X-WP-Total). The block editor itself works through it. See Lesson 7.1.

Revision

A saved copy of a post's earlier content, stored as a post of type revision with the original as parent; every update creates one. An autosave is a special revision. See Lesson 2.1.

Role

A named set of capabilities assigned to users: Administrator, Editor, Author, Contributor, Subscriber (plus Super Admin on multisite), and custom roles such as the course's pagesco_bookseller added with add_role(). Code checks capabilities, not roles. See Lesson 2.1 and Lesson 5.1.

Route and Endpoint

A REST route is a URL pattern such as /pagesco/v1/books/(?P<id>\d+); an endpoint is one HTTP method on it with its callback, arguments and permission check. register_rest_route() on rest_api_init adds them. See Lesson 7.1 and Lesson 7.2.

S

Sanitizing and Validating

Sanitizing cleans input into the shape you store (sanitize_text_field(), absint(), sanitize_key()), as early as possible and after wp_unslash(); validating decides whether to accept it at all (a real date, a known genre). See Lesson 1.3 and Lesson 5.3.

Schema (REST Arguments)

The JSON-schema keywords on a REST argument (type, default, minimum, maximum, enum, required, maxLength) that WordPress checks and applies before your callback runs, and that OPTIONS requests describe. See Lesson 7.2.

search-replace

wp search-replace OLD NEW: changes a URL (or any text) everywhere in the database, unserializing and reserializing values so their recorded lengths stay right. The course's launch command adds --all-tables-with-prefix --skip-columns=guid and --dry-run or --export. See Lesson 8.4.

Section Style

A block style variation defined in a theme's styles/ folder with blockTypes, such as the course's sage and ink bands; it appears as a style choice on those blocks and renders as an is-style-… class. See Lesson 3.3.

Serialized Data

PHP's text form of an array or object (a:2:{s:4:"city";…}), which WordPress uses for array options and meta. It records the length of every string, so a plain SQL REPLACE() to a longer value breaks it. See Lesson 2.2 and Lesson 8.4.

Settings API

Core's system for admin settings forms: register_setting() (group, option, type, sanitize_callback, default), add_settings_section(), add_settings_field(), and in the form settings_fields() and do_settings_sections(), which options.php saves with its own nonce check. See Lesson 5.4.

Shortcode

A bracketed tag in content, such as [pagesco_events] or [pagesco_book id="30"], replaced by the output of a callback registered with add_shortcode(). The callback returns its HTML; it never echoes. See Lesson 5.5.

Site Editor

Appearance > Editor in a block theme: owners edit templates, parts, patterns, navigation and styles visually. What they save becomes database posts (wp_template, wp_template_part, wp_global_styles) that win over the theme's files. See Lesson 3.2 and Lesson 3.3.

Slug

The URL-friendly name of a post or term (post_name, such as staff-picks); also the folder name that identifies a theme or plugin, and the name of a pattern or template. See Lesson 2.1.

Static Block

A block whose HTML is produced by its JavaScript save() and stored in the post; the front end needs no PHP or JavaScript for it. Changing save() later needs a deprecation. Compare dynamic block. See Lesson 6.2 and Lesson 6.3.

Store (Interactivity API)

The object a block registers with store( 'pagesco/book-filter', { state, actions } ) in its view script module; directives name it with data-wp-interactive. Getters in the store compute derived state (with PHP closures in wp_interactivity_state() for the first render). The namespace must match exactly. See Lesson 6.4.

Style Variation

An alternative theme.json in a theme's styles/ folder (such as "Evening") that owners can switch to under Styles; its values are merged over the theme's own. See Lesson 3.3.

Synced Pattern

A pattern stored in the database as a wp_block post (formerly "reusable block") and inserted by reference, <!-- wp:block {"ref":20} /-->: edit it once, it changes everywhere. Deleting it empties every page that uses it. See Lesson 3.3.

T

Taxonomy and Term

A taxonomy is a way of grouping content (core's categories and tags, the course's genre, registered with register_taxonomy()); its terms are the groups (Fiction, Fantasy), stored in wp_terms and linked through wp_term_relationships. See Lesson 2.1 and Lesson 5.2.

Template

The layout WordPress uses for a kind of page. In a block theme, an HTML file of block markup in templates/ (single.html, archive.html); in a classic theme, a PHP file (singular.php). See Lesson 3.2 and Lesson 4.1.

Template Hierarchy

The ordered list of template names WordPress tries for a request, most specific first, ending at index: for /category/news/, category-news, category-2, category, archive, index. See Lesson 3.1.

Template Part

A reusable piece of a block template, such as parts/header.html, inserted with <!-- wp:template-part {"slug":"header","tagName":"header"} /-->. In classic themes, get_template_part( 'template-parts/content' ) includes a PHP part (without .php). See Lesson 3.2 and Lesson 4.1.

Template Tag

A function used in classic templates to print or return data about the current post: the_title() / get_the_title(), the_permalink(), the_content(), the_excerpt(). The the_ versions print; the get_ versions return. See Lesson 4.1.

Text Domain

The identifier that ties a theme's or plugin's strings to its translations, written as a literal string in every call: __( 'Book details', 'pagesco-books' ). It matches the folder name and the Text Domain header. See Lesson 1.3 and Lesson 8.3.

theme.json

A block theme's design system in one file: settings (the palette, fonts, sizes, spacing and layout widths people may use) and styles (how the site, elements and blocks look), plus templateParts and customTemplates. WordPress turns presets into CSS custom properties such as --wp--preset--color--oxblood. See Lesson 3.2.

Transient

A cached value with an expiry time: set_transient( $key, $value, 12 * HOUR_IN_SECONDS ), get_transient() (false when missing or expired), delete_transient(). Stored in wp_options, or in the object cache when it is persistent; it may disappear early, so always be ready to rebuild it. See Lesson 7.3.

W

Widget Area

A place in a classic theme where owners put widgets (blocks since 5.8), registered with register_sidebar() on widgets_init with a fixed id and printed with dynamic_sidebar(). See Lesson 4.3.

@wordpress/scripts (wp-scripts)

The official build toolkit for blocks (webpack, Babel, Sass, dependency extraction): wp-scripts build, wp-scripts start and wp-scripts plugin-zip, run through the plugin's package.json scripts. See Lesson 6.1 and Lesson 8.3.

wp_body_open, wp_head and wp_footer

The three actions every page must fire: wp_head inside <head> (styles, scripts, meta tags), wp_body_open right after <body>, and wp_footer before </body>. Block themes get them from core's template canvas; classic themes call them in their templates. See Lesson 3.1 and Lesson 2.3.

WP-CLI

The command-line interface for WordPress. In this course wp is a shortcut for docker compose --progress quiet run --rm wpcli wp, and every command runs in the WordPress root of the course container. WP-CLI runs as no user unless you pass --user. See Lesson 1.2.

wp-config.php

The site's configuration file one level above wp-content/: database credentials, keys and salts, $table_prefix and constants such as WP_DEBUG, WP_ENVIRONMENT_TYPE, DISALLOW_FILE_EDIT and DISABLE_WP_CRON. Never in Git; written per environment. See Lesson 2.2 and Lesson 8.4.

wp-content

The folder for everything that is not core: themes/, plugins/, mu-plugins/, uploads/, languages/, drop-ins and debug.log. Your code lives here, and in Lesson 8.4 it becomes the Git repository. See Lesson 1.1 and Lesson 8.4.

WP-Cron

WordPress's scheduler for recurring and one-time events (wp_schedule_event(), wp_next_scheduled(), wp_clear_scheduled_hook()). It runs due events when a page view triggers wp-cron.php; live sites set DISABLE_WP_CRON and let a real cron job run wp cron event run --due-now. See Lesson 7.3 and Lesson 8.4.

$wpdb

The global database object: $wpdb->get_results(), get_row(), get_var(), insert(), update(), delete(), prepare(), and the table names $wpdb->posts, $wpdb->prefix. Never type wp_ in PHP. See Lesson 2.2 and Lesson 5.5.

wp-env

The WordPress project's Docker-based tool for plugin and block development, npx @wordpress/env start with a .wp-env.json file (MariaDB, port 8888 by default). The course uses it for the test site in Lesson 8.1. Always type the scoped name: the package wp-env is something else. See Lesson 1.2 and Lesson 8.1.

WP_Error

WordPress's error object, returned instead of a value: is_wp_error( $result ), $error->get_error_code(), get_error_message(). The REST API turns one into an HTTP error using its status data. See Lesson 1.3 and Lesson 7.2.

WP_Query

The class that queries posts from an array of arguments (post_type, posts_per_page, tax_query, meta_query, orderby…) and runs secondary Loops: $q->have_posts(), $q->the_post(), then wp_reset_postdata(). See Lesson 4.2.

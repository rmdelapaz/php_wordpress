🔎 Reading a WordPress Error

A PHP message has a level (Fatal error, Warning, Notice, Deprecated), the message, a file and a line; uncaught exceptions add a stack trace, newest call first. WordPress adds its own "called incorrectly" and "deprecated" notices, which always name wp-includes/functions.php on line 6260 (the function that prints them): the useful part is the function name and the sentence. Where a message turns up tells you a lot:

You see itBecause
above <!DOCTYPE html>a block theme renders the whole template (blocks, filters, shortcodes) before it prints the <head> (Lesson 2.3)
inside the contentit came from a dynamic block's render.php (Lesson 6.3)
only in an X-WP-DoingItWrong headerit happened during a REST request (Lesson 7.2)
only in wp-content/debug.loga background request (the editor, WP-Cron, REST), or display is off; tail -f wordpress/wp-content/debug.log (Lesson 1.2)
as "There has been a critical error on this website."a fatal error with display off: the log has the details (Lesson 8.1)
as {closure}() without a filePHP 8.3 or older; 8.4+ prints {closure:/path/file.php:LINE}() (Lesson 2.3)
as EvalFile_Command.php(85) : eval()'d codethe code ran through wp eval-file, not from your file's own name

Every message below was printed on the course site (WordPress 7.1.3, PHP 8.5) and appears in the lesson linked under it; long stack traces are cut after the first lines. Your paths are the same (/var/www/html/… is your wordpress/ folder); IDs, timestamps and addresses may differ. Search this page with Ctrl+F for a few words of your message. Setup problems without a message are on the Troubleshooting page; terms are explained in the Glossary.

🐳 Docker and Setup

All from Lesson 1.2, where the environment is built. Most are environment problems rather than code: the Troubleshooting page has the longer checklists.

mkdir: cannot create directory ... Permission denied

Error

mkdir: cannot create directory ‘wordpress/wp-content/mu-plugins’: Permission denied

What it means: Linux or WSL: the containers ran as user 33 (www-data), so the files in wordpress/ belong to it and your user can read but not write them.

Fix: The Linux setup of Lesson 1.2 (.env with your user and group numbers plus compose.override.yaml), or its repair box if you already started without it. Not sudo in front of your editor, not chmod -R 777. (Lesson 1.2)

required variable PAGESCO_UID is missing a value

Error

Error while interpolating services.wordpress.user: required variable PAGESCO_UID is missing a value: run the Linux setup from Lesson 1.2 first

What it means: compose.override.yaml is there but the .env file with your user and group numbers is not, so Compose refuses to start.

Fix: In the project folder: printf 'PAGESCO_UID=%s\nPAGESCO_GID=%s\n' "$(id -u)" "$(id -g)" > .env, then docker compose up -d. (Lesson 1.2)

Bind for 0.0.0.0:8080 failed: port is already allocated

Error

Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint pagesco-wordpress-1 (f3189481e620...): Bind for 0.0.0.0:8080 failed: port is already allocated

What it means: Something else already listens on port 8080 (or 8025 for Mailpit): another Compose project, an old container, a local Apache, another course's server.

Fix: Find it in the PORTS column of docker ps and stop it. Changing the course port means changing "8080:8080", the Listen line in config/apache-8080.conf and the site URL: freeing the port is easier. (Lesson 1.2)

Error establishing a database connection (Access denied for user 'wordpress')

Error

Warning: mysqli_real_connect(): (HY000/1045): Access denied for user 'wordpress'@'172.19.0.4' (using password: YES) in /var/www/html/wp-includes/class-wpdb.php on line 1990
Error: `Access denied for user 'wordpress'@'172.19.0.4' (using password: YES)`
Error establishing a database connection

What it means: The database password in compose.yaml was changed after the first start. The MySQL image reads MYSQL_PASSWORD only when it creates the database in an empty volume, so WordPress now sends a password MySQL never heard of.

Fix: Put the old password back and run docker compose up -d; or change it inside MySQL first; or start over with docker compose down -v. The address in the message changes from computer to computer. (Lesson 1.2)

no configuration file provided: not found

Error

no configuration file provided: not found

What it means: The wp shortcut (or any docker compose command) ran outside the project folder: Compose found no compose.yaml in the folder or above it. In a new terminal without the alias you get wp: command not found instead.

Fix: cd ~/pagesco-dev (or any folder inside it), and put the alias in ~/.bashrc or ~/.zshrc. (Lesson 1.2)

Invalid address: (From): wordpress@localhost

Output (with a wp_mail_failed listener)

Invalid address:  (From): wordpress@localhost
bool(false)

What it means: mailpit-smtp.php is missing from mu-plugins/ (for example after a reset). WordPress builds the sender from the site's domain, localhost, and the mail library rejects it; wp_mail() returns false and only the wp_mail_failed action says why. wp-env sites have the same problem.

Fix: Copy config/mailpit-smtp.php back into wordpress/wp-content/mu-plugins/. (Lesson 1.2)

Deprecated: Using null as an array offset ... Colors.php

Message (shortened in the lesson)

Deprecated: Using null as an array offset is deprecated ... php-cli-tools/lib/cli/Colors.php on line 95

What it means: WP-CLI 2.12's own code on PHP 8.5, printed after its Success and Error lines when WP_DEBUG is on. It is not your code. The course's WP-CLI image hides it; a natively installed WP-CLI or another PHP 8.5 image shows it.

Fix: Ignore it, or use the course container. It does not appear on PHP 8.4. (Lesson 1.2)

Failed to get current SQL modes ... TLS/SSL error: self-signed certificate

Error

Error: Failed to get current SQL modes. Reason: ERROR 2026 (HY000): TLS/SSL error: self-signed certificate in certificate chain

What it means: You ran wp db query (or export, check) with the official wordpress:cli image against MySQL 9.7, whose development certificate that image's client refuses. Reproduced for this page with wordpress:cli-php8.5; the same command in the course's pagesco-wpcli image works.

Fix: Use the course's wpcli service (the wp shortcut): its image adds the fixes in config/wpcli.Dockerfile and config/mariadb-local.sh. Against MariaDB (wp-env) the official image works. (Lesson 1.2)

💥 Fatal Errors

A fatal error stops the request. With WP_DEBUG_DISPLAY on you see the message in the page; visitors of a live site see "There has been a critical error on this website." and the details go to the log. A fatal error in a must-use plugin, or at load time in any plugin, takes the admin and WP-CLI down too.

Cannot redeclare function get_the_title()

Error

Fatal error: Cannot redeclare function get_the_title() (previously declared in /var/www/html/wp-includes/post-template.php:118) in /var/www/html/wp-content/mu-plugins/mistake-redeclare.php on line 2

What it means: Two functions with the same name: core declared it first. The same happens when two plugins forget a prefix.

Fix: Prefix every function (pagesco_get_title()); to change what a core function returns, use its filter. PHP 8.5 adds a stack trace under this message; 8.4 and older print the single line. (Lesson 1.3)

TypeError: str_repeat(): Argument #2 ($times) must be of type int, string given

Error

Fatal error: Uncaught TypeError: str_repeat(): Argument #2 ($times) must be of type int, string given in /var/www/html/wp-content/mu-plugins/mistake-strict.php:4

What it means: declare(strict_types=1) met a WordPress value: options come out of the database as strings (get_option( 'posts_per_page' ) is "10").

Fix: Leave strict types out of code that talks to WordPress, or cast where the value enters: (int) get_option( 'posts_per_page' ). (Lesson 1.3)

ArgumentCountError: Too few arguments to function {closure:...}(), 1 passed ... exactly 2 expected

Error

Fatal error: Uncaught ArgumentCountError: Too few arguments to function {closure:/var/www/html/wp-content/mu-plugins/mistake-args.php:2}(), 1 passed in /var/www/html/wp-includes/class-wp-hook.php on line 355 and exactly 2 expected in /var/www/html/wp-content/mu-plugins/mistake-args.php:2

What it means: A callback asks for two arguments, but add_filter() was given the default of one.

Fix: Pass the number of arguments: add_filter( 'the_title', $callback, 10, 2 );. PHP 8.3 and older name the closure just {closure}(); the thrown in line then points to your file. (Lesson 2.3)

call_user_func_array(): Argument #1 ($callback) must be a valid callback

Error

Fatal error: Uncaught TypeError: call_user_func_array(): Argument #1 ($callback) must be a valid callback, function "pagesco_register_thing" not found or invalid function name in /var/www/html/wp-includes/class-wp-hook.php:353

What it means: A typo in a callback name: add_action() stores the string without checking, and the error happens when the hook fires (here init, so on every request, admin and WP-CLI included). Editors do not catch it: to them it is a string.

Fix: Copy the name from the function definition. When a hook seems to do nothing, ask has_action(). (Lesson 2.3)

What it means: The plugin was copied or checked out without running Composer, so vendor/ is missing. On activation WordPress includes the file in a sandbox first and refuses ("Plugin could not be activated because it triggered a fatal error.").

Class "PagesCo\Books\StoreNotice" not found

Error

Fatal error: Uncaught Error: Class "PagesCo\Books\StoreNotice" not found in /var/www/html/wp-content/plugins/pagesco-books/src/Plugin.php:54

What it means: The autoloader looked for src/StoreNotice.php and the file is named differently (src/Storenotice.php): PSR-4 file names must match the class name exactly, capitalization included. It runs on plugins_loaded, so the whole site is down.

Fix: Rename the file to the class name. In a release (Lesson 9.1), the same message for PagesCo\Books\Holds\HoldsTable meant the ZIP was missing a new folder of src/: add it to the "files" list in package.json. (Lesson 5.1, Lesson 9.1)

Call to undefined function plugin_dir_path() (a plugin file requested directly)

Server log

PHP Fatal error:  Uncaught Error: Call to undefined function plugin_dir_path() in /var/www/html/wp-content/plugins/pagesco-books/pagesco-books.php:22

What it means: Someone requested the plugin's PHP file by URL; without WordPress loaded it dies on the first WordPress function (HTTP 500, this line in docker compose logs wordpress). A file with top-level actions would perform them for anyone.

Fix: defined( 'ABSPATH' ) || exit; at the top of every PHP file that can run on its own. (Lesson 5.1)

What it means: A fatal error after WordPress started (here in an init callback). Visitors see only the last sentence; the details are in debug.log or the server log. 🔔 Notices, Warnings and "Called Incorrectly"

These do not stop the page. In a block theme a notice from a template or filter prints above <!DOCTYPE html>, because the whole template is rendered before the <head>; notices from a dynamic block's render.php print inside the content. All of them also go to debug.log.

Deprecated: str_replace(): Passing null to parameter #3 ($subject) ... formatting.php on line 5777

Output (top of the page)

Deprecated: str_replace(): Passing null to parameter #3 ($subject) of type array|string is deprecated in /var/www/html/wp-includes/formatting.php on line 5777

What it means: A filter callback forgot to return, so the value became null; the next callback on the_title, core's capital_P_dangit(), passed it on. The notice blames core, the title is gone everywhere, and on a live site nothing is printed at all.

Fix: Every filter callback ends with return $value;, also when it changes nothing. When a notice points into core, look at what your code handed to it. (Lesson 2.3)

Function get_currentuserinfo is deprecated since version 4.5.0!

Output

Deprecated: Function get_currentuserinfo is <strong>deprecated</strong> since version 4.5.0! Use wp_get_current_user() instead. in /var/www/html/wp-includes/functions.php on line 6260

What it means: Code copied from an old tutorial. The message names the version that deprecated the function and its replacement (the <strong> tags are there because it is formatted for a web page).

Fix: Use the replacement. The same pattern appears in Lesson 8.2: removing the emoji scripts with only two of the three remove_action() lines logs "Function print_emoji_styles is deprecated since version 6.4.0!" on every page. (Lesson 1.1, Lesson 8.2)

Function is_home was called incorrectly. Conditional query tags do not work before the query is run.

Output

Notice: Function is_home was called <strong>incorrectly</strong>. Conditional query tags do not work before the query is run. Before then, they always return false. Please see <a href="https://developer.wordpress.org/advanced-administration/debug/debug-wordpress/">Debugging in WordPress</a> for more information. (This message was added in version 3.1.0.) in /var/www/html/wp-includes/functions.php on line 6260

What it means: A conditional tag at the top level of a plugin file runs while plugins load, long before the main query. It returns false.

Fix: Ask inside a callback on a hook that runs after the query: template_redirect, wp, or the hook that prints your output. (Lesson 4.1)

Function wp_enqueue_style was called incorrectly. Scripts and styles should not be registered or enqueued until ...

Output (shortened)

Notice: Function wp_enqueue_style was called <strong>incorrectly</strong>. Scripts and styles should not be registered or enqueued until the <code>wp_enqueue_scripts</code>, <code>admin_enqueue_scripts</code>, or <code>login_enqueue_scripts</code> hooks. This notice was triggered by the <code>pagesco-hours</code> handle. ...
Notice: Function wp_is_block_theme was called <strong>incorrectly</strong>. This function should not be called before the theme directory is registered. ...
Notice: Function is_feed was called <strong>incorrectly</strong>. Conditional query tags do not work before the query is run. ...

What it means: An enqueue call at the top level of a file instead of in a callback. One misplaced line, three notices: read the first one. The style still loads, on every screen, the admin and login page included.

Fix: Wrap it in a function hooked to wp_enqueue_scripts (or admin_enqueue_scripts, login_enqueue_scripts). (Lesson 4.3)

register_sidebar ... No id was set ... Defaulting to "sidebar-1"

Output (shortened)

Notice: Function register_sidebar was called <strong>incorrectly</strong>. No <code>id</code> was set in the arguments array for the "Shop sidebar" sidebar. Defaulting to "sidebar-1". Manually set the <code>id</code> to "sidebar-1" to silence this notice and keep existing sidebar content. ...

What it means: A widget area registered without an id. The generated number shifts when areas are added or removed, and the owner's widgets move or vanish into Inactive Widgets.

Fix: Always pass a fixed id (footer) and never change it on a live site. (Lesson 4.3)

get_block_patterns was called incorrectly ... ("Slug" field missing)

Output (visible text of the page)

Notice: Function get_block_patterns was called incorrectly. Could not register file "/var/www/html/wp-content/themes/pagesco/patterns/visit-us.php" as a block pattern ("Slug" field missing) Please see Debugging in WordPress for more information. (This message was added in version 6.0.0.) in /var/www/html/wp-includes/functions.php on line 6260

What it means: A pattern file without a Slug: header line is skipped. Without development mode the file list is cached, so the notice may appear only once and the pattern is simply missing afterwards.

Fix: Add Slug: pagesco/visit-us (letters, digits, /, _ and - only). (Lesson 3.3)

wp_json_file_decode(): Error when decoding a JSON file at path .../theme.json: Syntax error

Output (top of every page)

Notice: wp_json_file_decode(): Error when decoding a JSON file at path /var/www/html/wp-content/themes/pagesco/theme.json: Syntax error in /var/www/html/wp-includes/functions.php on line 6260

What it means: Invalid JSON in theme.json (here a trailing comma). WordPress then uses no theme.json at all: palette, fonts and colors fall back to core's defaults. On a live site there is no message, only a suddenly plain design.

Fix: Fix the syntax: no comma after the last item, double quotes only, no comments. With the $schema line, VS Code underlines the error. (Lesson 3.2)

register_collection was called incorrectly. The specified manifest file does not exist.

Error

Notice: Function WP_Block_Metadata_Registry::register_collection was called <strong>incorrectly</strong>. The specified manifest file does not exist. Please see <a href="https://developer.wordpress.org/advanced-administration/debug/debug-wordpress/">Debugging in WordPress</a> for more information. (This message was added in version 6.7.0.) in /var/www/html/wp-includes/functions.php on line 6260

What it means: The plugin's build/ folder is missing (a fresh checkout, a forgotten build), so the block registration finds no manifest; a second notice follows. With display on, the notices print above every admin screen and break the block editor.

register_rest_route was called incorrectly ... missing the required permission_callback argument

Error (shortened)

Notice: Function register_rest_route was called <strong>incorrectly</strong>. The REST API route definition for <code>pagesco/v1/hours</code> is missing the required <code>permission_callback</code> argument. For REST API routes that are intended to be public, use <code>__return_true</code> as the permission callback. ... (This message was added in version 5.5.0.) in /var/www/html/wp-includes/functions.php on line 6260

What it means: A route without permission_callback. It still answers, as if public. During REST requests the notice is not printed (it would break the JSON) but sent as an X-WP-DoingItWrong response header; WP-CLI (wp eval 'rest_get_server();') prints it.

Fix: Always write the key; '__return_true' for deliberately public reads, a capability check for everything else. (Lesson 7.2)

Warning: Undefined array key "..."

Error (three lessons)

Warning: Undefined array key "show_events_link" in /var/www/html/wp-content/mu-plugins/mistake-checkbox.php on line 15
Warning: Undefined array key "title" in /var/www/html/wp-content/mu-plugins/mistake-card-title.php on line 9
Warning: Undefined array key &#8220;count&#8221; in /var/www/html/wp-content/plugins/pagesco-books/build/blocks/book-list/render.php on line 19

What it means: Three course situations: an unticked checkbox is not sent at all (Lesson 5.4); a block attribute with a source lives in the HTML, not in $block['attrs'] (Lesson 6.2); a block attribute without a default is missing from $attributes (Lesson 6.3, where wptexturize even curled the quotes, because render.php output is content).

Note the path in the third message: build/, the copy WordPress runs; edit the one in src/. (Lesson 5.4, Lesson 6.2, Lesson 6.3)

Warning: Trying to access array offset on null / foreach() argument must be of type array|object, null given

Error

Warning: Trying to access array offset on null in /var/www/html/wp-content/mu-plugins/mistake-supplier.php on line 14

Warning: foreach() argument must be of type array|object, null given in /var/www/html/wp-content/mu-plugins/mistake-supplier.php on line 14
Copies at the supplier: 0

What it means: Code checked is_wp_error() and trusted the rest: the supplier answered 503 with an HTML page, json_decode() returned null. Worse than the warnings is the confident, wrong "0".

Using the synchronous event.preventDefault() function in a store action without wrapping it in withSyncEvent() is deprecated

Browser console (recorded)

Console: [warning] Using the synchronous event.preventDefault() function in a store action without wrapping it in withSyncEvent() is deprecated and will stop working in WordPress 7.0. Please wrap the store action in withSyncEvent().

What it means: An Interactivity API action uses the event (preventDefault(), stopPropagation(), currentTarget) without withSyncEvent(). It still works in 7.1, with this warning in the browser console.

Fix: Wrap the action: selectGenre: withSyncEvent( ( event ) => { … } ). (Lesson 6.4)

🖥️ WP-CLI and Admin Messages

Error: Template is missing. Standalone themes need to have a templates/index.html or index.php template file.

Error

Error: Template is missing. Standalone themes need to have a <code>templates/index.html</code> or <code>index.php</code> template file. <a href="https://developer.wordpress.org/themes/advanced-topics/child-themes/">Child themes</a> need to have a <code>Template</code> header in the <code>style.css</code> stylesheet.

What it means: A theme folder with only a style.css. Appearance > Themes lists it under Broken Themes.

Fix: Add templates/index.html (block theme) or index.php (classic theme); a child theme needs a Template: header instead. (Lesson 3.1)

Error: The parent theme is missing. Please install the "..." parent theme.

Error

Error: The parent theme is missing. Please install the "twenty-twenty-five" parent theme.

What it means: A child theme's Template: header names something that is not a theme folder (the parent's display name, a typo), or the parent is not installed. wp theme list does not show the broken child at all.

Fix: Use the parent's folder name (twentytwentyfive) and install the parent first. (Lesson 3.4)

Error: No plugins activated.

What it means: The theme's or plugin's Requires at least / Requires PHP header asks for more than the site has. WordPress checks them on activation and refuses. (The doubled "Error:" and the escaped &amp; are WP-CLI's.)

Error

What it means: Three different causes in the course: the option really does not exist (an activation hook that never ran, Lesson 5.1; a cron callback that never ran, Lesson 7.3); or it exists but its serialized value is broken, so unserialize() fails (an SQL REPLACE() changed a string's length, Lesson 2.2).

The link you followed has expired.

Output

<div class="wp-die-message">The link you followed has expired.</div>

What it means: The admin page was registered with a capability the user lacks (the shop's settings need manage_options; Maria is an editor).

What it means: A template part block with a slug that matches no part (here a typo for header). Visitors simply see no header; only logged-in users get this hint, and nothing is logged.

Browser console (recorded)

Fix: Add the old version to the block's deprecated array (with migrate() if attributes changed); keep save() deterministic, with literal text. After every change to save(): insert, save, reload. (Lesson 6.2, Lesson 6.2)

🌐 REST API Errors

REST errors arrive as JSON with a code, a message and data.status. Overview in Lesson 7.1.

rest_not_logged_in: You are not currently logged in.

Output

{"code":"rest_not_logged_in","message":"You are not currently logged in.","data":{"status":401}}

What it means: The request ran as nobody. Causes in the course: fetch() from wp-admin without the X-WP-Nonce header (the cookie alone does not count), Basic authentication with the account password instead of an application password, or a mistyped or revoked application password (the API deliberately does not say which).

Fix: Use wp.apiFetch (it adds the nonce) or send X-WP-Nonce; for scripts, an application password (Users > Profile shows when it was last used). (Lesson 7.1)

rest_cookie_invalid_nonce: Cookie check failed

Output

{"code":"rest_cookie_invalid_nonce","message":"Cookie check failed","data":{"status":403}}

What it means: A nonce was sent, but it is not valid for this user's session (expired, from another login, or made by another tool).

Fix: Get a fresh nonce from the page (apiFetch does) or from admin-ajax.php?action=rest-nonce with the same cookies. (Lesson 7.1)

rest_cannot_edit / rest_forbidden: Sorry, you are not allowed to ...

Output

{"code":"rest_cannot_edit","message":"Sorry, you are not allowed to edit this post.","data":{"status":401}}
{"code":"rest_cannot_edit","message":"Sorry, you are not allowed to edit this post.","data":{"status":403}}
{"code":"rest_forbidden","message":"Sorry, you are not allowed to manage events.","data":{"status":403}}

What it means: The permission check said no. 401 means nobody is logged in (fix the authentication); 403 means the user is known but may not do this (Devon, an author, editing Maria's Dune). Your own routes return the same through rest_authorization_required_code().

Fix: Authenticate (401) or use an account with the capability (403). Never "fix" it by loosening permission_callback to __return_true for a write. (Lesson 7.1, Lesson 7.2)

rest_invalid_param: Invalid parameter(s) ...

Output

{"code":"rest_invalid_param","message":"Invalid parameter(s): per_page","data":{"status":400,"params":{"per_page":"per_page must be between 1 (inclusive) and 100 (inclusive)"},"details":{"per_page":{"code":"rest_out_of_bounds","message":"per_page must be between 1 (inclusive) and 100 (inclusive)","data":null}}}}

What it means: An argument failed its schema: out of range (rest_out_of_bounds), not in the list (rest_not_in_enum: "orderby is not one of title, newest, and price."), the wrong type (rest_invalid_type, also for registered meta), or your own validate_callback (pagesco_unknown_genre). data.params names each one.

Fix: Send a valid value. When writing routes: one failing validate_callback hides the other arguments' errors, so fix them one round at a time. (Lesson 7.1, Lesson 7.2, Lesson 5.2)

rest_no_route: No route was found matching the URL and request method.

Output

{"code":"rest_no_route","message":"No route was found matching the URL and request method.","data":{"status":404}}
{"code":"rest_post_invalid_id","message":"Invalid post ID.","data":{"status":404}}

What it means: A typo in the route (/bookz), the wrong HTTP method for it, or a route registered on the wrong hook; the second message is a real route with an ID that does not exist.

Fix: Compare with the index (/wp-json/ or /wp-json/pagesco/v1); register routes on rest_api_init. (Lesson 7.1)

HTTP/1.1 500 Internal Server Error with "data":null

Output

HTTP/1.1 500 Internal Server Error
{"code":"pagesco_book_not_found","message":"No book was found with that ID.","data":null}

What it means: A REST callback returned a WP_Error without a status, which is sent as 500: clients believe the server broke and may retry.

Fix: Give every error its status: new WP_Error( 'pagesco_book_not_found', $message, array( 'status' => 404 ) ). (Lesson 7.2)

📞 HTTP, Cron and Database Server Errors

http_request_failed: cURL error 28 (timeout) / cURL error 6 (could not resolve host)

Output

http_request_failed: cURL error 28: Operation timed out after 2056 milliseconds with 0 bytes received
No host:    WP_Error http_request_failed: cURL error 6: Could not resolve host: supplier.invalid (Domain name not found)

What it means: The request got no answer at all: too slow for the timeout, or a host name that does not exist. These are WP_Errors; a 401 or 503 is an answer, an array.

Fix: Treat it as "the supplier is not reachable": cache the failure briefly (the course caches it for 5 minutes) and show a clear message. Keep timeouts short on page views. (Lesson 7.3)

A valid URL was not provided.

Output

http://192.168.1.10/                                      A valid URL was not provided.
http://127.0.0.1:8080/                                    A valid URL was not provided.

What it means: wp_safe_remote_get() refused an address on a private network: the protection against SSRF for URLs that come from users.

Fix: Correct for user-supplied URLs. For your own configured service use wp_remote_get(). (Lesson 7.3)

invalid_schedule: Event schedule does not exist.

Output

invalid_schedule: Event schedule does not exist.

What it means: wp_schedule_event() got a recurrence name WordPress does not know (with $wp_error set to true; otherwise it just returns false).

Fix: Use hourly, twicedaily, daily, weekly, or add your own on the cron_schedules filter (wp cron schedule list shows them). (Lesson 7.3)

Error: The DISABLE_WP_CRON constant is set to true. WP-Cron spawning is disabled.

Error

Error: The DISABLE_WP_CRON constant is set to true. WP-Cron spawning is disabled.

What it means: wp cron test on a production-configured site, where page views no longer trigger WP-Cron. Expected, as long as a real cron job runs wp cron event run --due-now.

Fix: Check the scheduler instead (the rehearsal site: docker compose logs cron). (Lesson 8.4)

mariadb-dump: Got error: 1044 ... when using LOCK TABLES

Error

mariadb-dump: Got error: 1044: "Access denied for user 'pagesco_app'@'%' to database 'pagesco'" when using LOCK TABLES

What it means: wp db export with a least-privilege database account that may not lock tables. It also leaves a header-only file with the backup's name (831 bytes). The related ERROR 1044 (42000) ... to database 'test' after CREATE DATABASE is the same restriction, working as intended.

Fix: Grant exactly that right, as root: GRANT LOCK TABLES ON pagesco.* TO 'pagesco_app'@'%';. Judge a backup by its size and a restore test, not by its file name; read the whole output of wp db import, which can print errors and still end with "Success". (Lesson 8.4)

🧪 Build, Lint and Test Messages

make-pot: contains placeholders but has no "translators:" comment / Multiple placeholders should be ordered.

Output

Warning: The string "Showing %s of %s books" contains placeholders but has no "translators:" comment to clarify their meaning. (strings.php:11)
Warning: Multiple placeholders should be ordered. (strings.php:11)

What it means: wp i18n make-pot found strings a translator cannot handle well. It still writes the file and exits successfully, and it says nothing about fragments ('Books in ') or __( $variable ), which produces no entry at all.

Fix: A /* translators: */ comment, numbered placeholders (%1$s), whole sentences, _n() for numbers. (Lesson 8.3)

Overriding WordPress globals is prohibited. Found assignment to $title

Output

 10 | ERROR | Overriding WordPress globals is prohibited. Found assignment to
    |       | $title (WordPress.WP.GlobalVariablesOverride.Prohibited)

What it means: PHPCS (WPCS) sees a top-level variable named like a WordPress global. In a block's render.php it happens to be local, but the sniff cannot know that.

Fix: A specific name ($book_title) costs nothing. Fix cheap findings; document real exceptions with // phpcs:ignore Rule -- reason. (Lesson 9.1, Lesson 8.1)

An error occurred inside PHPUnit: Call to undefined method TestSuite::empty()

Error

An error occurred inside PHPUnit.

Message:  Call to undefined method PHPUnit\Framework\TestSuite::empty()

What it means: Bare phpunit in the wp-env container starts the global PHPUnit 10.5, which meets the plugin's PHPUnit 9 classes and the WordPress test library written for 9.

Fix: Run the project's copy: npx @wordpress/env run cli --env-cwd=wp-content/plugins/pagesco-books vendor/bin/phpunit. (Lesson 8.1)

prompt_invalid_argument: No models found that support text_generation for this prompt.

Output

prompt_invalid_argument: No models found that support text_generation for this prompt.

What it means: The AI client has no provider: none ships with core. With WP_AI_SUPPORT false the answer is prompt_prevented (503) "AI features are not supported in this environment." instead.

Fix: Install a provider plugin and add its key under Settings > Connectors; in code, always handle the WP_Error. (Lesson 9.2)

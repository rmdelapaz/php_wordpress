3.3

Patterns, Style Variations & the Site Editor

Sections you design once.

3.3 · Mental model

A rubber stamp and a hanging sign

  • Theme pattern: a stamp. The print is a copy; editing the stamp changes no print
  • Synced pattern: one sign in many rooms (wp_block, by ID)
  • Template part: the signs fixed to the building (parts/, by slug)
  • Ask: must every copy change when the original changes?
3.3 · Why PHP?

A pattern file is a header plus blocks

  • Title: and Slug: pagesco/hero are required
  • Translatable: esc_html_e( ..., 'pagesco' )
  • Portable: get_theme_file_uri(), home_url()
  • Post Types: wp_template: offered in templates only
WHY The Site Editor will take all three away from you at the end of the demo.

3.3 · The loop

From the Site Editor back to code

  1. List the copies: wp post list of wp_template, wp_template_part, wp_global_styles
  2. Find the change (wp post get, or Export the theme)
  3. Put it in the right file: often a pattern
  4. Delete the copy: wp post delete ID --force or Reset
RULE Never paste the copy over your file.

3.4

Child Themes & Customizing Existing Themes

Change someone else's theme without touching it.

3.4 · Mental model

Tracing paper over a floor plan

  • The parent is the printed plan; the child the tracing paper
  • Draw only what you want different
  • A new plan from the architect? Slide the paper onto it
  • A child theme is still a theme: features go in plugins
3.4 · Inheritance

Looks in the child first

  • style.css: the child's header; its CSS only if enqueued
  • theme.json: merged, but preset lists replaced
  • templates, parts, styles/: same file name replaces
  • patterns: same slug wins
  • functions.php: both run, the child's first

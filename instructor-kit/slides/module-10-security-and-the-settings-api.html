5.3

Security in WordPress

Four habits, everywhere data crosses a boundary.

5.3 · Mental model

The shop's back door

  • Nonce: the token you handed the courier this morning
  • Capability: the person signing for it works here
  • Sanitize: unwrap and inspect before it goes on the shelf
  • Escape: a customer's name in the window, as text
FLOW request → genuine? → allowed? → sanitize → store → escape → page

5.3 · Escape late

The destination decides

  • Text: esc_html()
  • An attribute value: esc_attr()
  • An href or src: esc_url()
  • HTML that may keep safe tags: wp_kses_post()
  • At the point of output, even for data you sanitized
5.3 · Sanitize

Clean what you store

wp eval 'echo max( 0, (float) "-5.50" ), " | ", absint( "412 pages" ),
    " | ", sanitize_text_field( "O\x27Brien <b>Press</b>" ), "\n";'
0 | 412 | O'Brien Press
WHY Validate what must have a shape: a date, an allowed value.
5.3 · Live demo

The nonce round trip

wp eval 'wp_set_current_user( 2 );
$t = wp_create_nonce( "pagesco_books_save_details" );
echo "good: ", var_export( (bool) wp_verify_nonce( $t,
    "pagesco_books_save_details" ), true ), ", bad: ", var_export( (bool)
    wp_verify_nonce( "deadbeef", "pagesco_books_save_details" ), true ), "\n";'
good: true, bad: false
WHY In a form: wp_nonce_field() prints it, check_admin_referer() checks it.
5.3 · Two questions

Genuine is not allowed

  • A nonce proves the request came from your page, for this user
  • Any logged-in user who can open the form gets a valid one
  • So every state change also asks current_user_can( "edit_post", $id )
  • wp_insert_post() and friends check nothing: they trust you
WATCH A nonce without a capability lets any user act.
5.3 · SQL by hand

Every value through a placeholder

  • %s string · %d integer · %f float · %i identifier
  • $wpdb->prepare( $sql, $a, $b ) quotes and escapes each value
  • Never concatenate a variable into a query string
  • Prefer core APIs: WP_Query and get_post_meta() prepare for you
5.3 · Mistake

The wrong context

wp eval '$url = home_url( "/books/?genre=sci-fi&sort=price" );
echo esc_url( $url ), "\n", esc_html( $url ), "\n";'
http://localhost:8080/books/?genre=sci-fi&#038;sort=price
http://localhost:8080/books/?genre=sci-fi&amp;sort=price
WATCH esc_url() keeps a usable link; esc_html() makes display text.

5.4

Admin Pages, Settings API & Options

Settings the shop changes itself, safely.

5.4 · Mental model

One labeled box on the shared shelf

  • wp_options is the shelf every plugin shares
  • One box: pagesco_books_settings, an array of four values
  • One row, one autoloaded read, one delete on uninstall
  • One class knows the name, the defaults and the cleaning: Settings
5.4 · Live demo

Defaults without a row

wp db query "SELECT COUNT(*) FROM wp_options
    WHERE option_name = 'pagesco_books_settings'"

  'notice_extra' => 'Open until 9 p.m. on Thursdays.',

WHY register_setting()'s default is handed out while the row is missing.
5.4 · Menus

A page, and who may open it

  • add_options_page() on admin_menu: an item under Settings
  • Capability manage_options: guards the menu item AND the URL
  • Maria (editor): 403, before your callback runs
  • render() checks again: defense in depth
5.4 · The Settings API

The form as data

  • register_setting( group, option, args ) on init
  • add_settings_section(), add_settings_field() on admin_init
  • settings_fields( group ) · do_settings_sections( page ) · submit_button()
  • Group pagesco_books ≠ page slug pagesco-books
WATCH settings_fields() takes the GROUP. The slug gives "not in the allowed options list".
5.4 · Save Changes

What options.php does

  1. The nonce of the group (pagesco_books-options)
  2. current_user_can( "manage_options" )
  3. Is the option on the allowed options list?
  4. update_option() runs your sanitize callback
  5. Redirect back with settings-updated=true: saved, or your errors

5.4 · A sanitize callback

Return the complete value

  • Treat the input as hostile: it may not even be an array
  • Clean each key: sanitize_text_field(), absint()
  • A missing checkbox means off: ! empty( $input[...] )
  • Refuse with add_settings_error() and keep the saved value
WATCH update_option() with half the array empties the other half.

3.1

Theme Anatomy & the Template Hierarchy

How WordPress chooses the file that draws a page.

3.1 · Mental model

The shop fit-out

  • Books (content) and the till (plugins) move across unchanged
  • Shelving, signs and paint are the theme
  • A good fit-out can be replaced next year
  • Keep it after a redesign? Then it is a plugin
3.1 · Three kinds

Block, classic, hybrid

  • Block: templates/*.html + theme.json · true, true
  • Classic: PHP templates · false, false
  • Hybrid: classic + theme.json · false, true
  • Ask: wp_is_block_theme(), wp_theme_has_theme_json()
WHY New default themes are block themes; most client sites are classic or hybrid.

3.1 · The hierarchy

Chains you will use

  • Page /about/: page-about · page-12 · page · singular · index
  • Category /category/news/: category-news · category-2 · category · archive
  • Author /author/maria/: author-maria · author-2 · author · archive
  • Search: search · index  ·  Not found: 404 · index
  • Front page: front-page · home · index
WATCH Slugs, never titles. Posts include their type: single-post-hello-world.

3.2 · theme.json

Two halves

  • settings = what is available: palette, fonts, sizes, spacing, widths
  • styles = what is applied: the page, elements, block types
  • var:preset|color|paper points at a preset
  • defaultPalette: false: editors see the shop's five colors
WHY $schema makes VS Code check the file as you type.

WHY tagName made the header and main; WordPress added the layout classes.
3.2 · Static and dynamic

Two kinds of block in a template

  • Static: Group, Heading, Paragraph · exact HTML between the comments
  • Dynamic: Site Title, Query Loop, Post Title · self-closing /-->
  • "inherit":true: the Query Loop shows what the main query found
  • tagName: header, main, footer landmarks
TIP Build static sections in the Site Editor, copy from the Code editor, never Save.

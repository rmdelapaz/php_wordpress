1.3

PHP the WordPress Way

Still PHP, with house rules.

1.3 · Mental model

Moving into a shared house

  • Label your food: a prefix on every global name
  • Use the shared kitchen tools: core's functions, not your helpers
  • Leave notes others can read: coding standards, DocBlocks
  • Do not rearrange the living room: read globals, never assign
WHY Every rule exists because of the other people in the process.
1.3 · The bridge

From PHP Foundations to WordPress

  • htmlspecialchars() → esc_html(), esc_attr(), esc_url()
  • filter_input() → wp_unslash() + sanitize_*()
  • exceptions → WP_Error and is_wp_error()
  • typed parameters → one array of arguments, wp_parse_args()
  • PDO → $wpdb (Lessons 2.2, 5.5)
NOTE Core runs on PHP 7.4. Your plugin declares its own minimum.

1.3 · Sanitize early

WordPress adds slashes

<p class="pagesco-q">raw: O\&#039;Reilly &lt;b&gt;books&lt;/b&gt; | clean: O&#039;Reilly books</p>
  • The URL sent O'Reilly <b>books</b>
  • Raw: a backslash from wp_magic_quotes()
  • Clean: sanitize_text_field( wp_unslash( ... ) )
RULE Unslash, then sanitize. Every time.

2.1

The Content Model

What WordPress stores, and how it fits together.

2.1 · Mental model

One filing cabinet, many labels

  • Every folder has the same fields: title, content, author, date, status
  • The label is post_type: post, page, attachment, revision, menu
  • Tabs on the folders: terms · who may open them: capabilities
  • The settings on the wall: options · on the paper: block markup
WHY Code that works on one folder works on every label at once.
2.1 · Everything is a post

16 post types, one table

  • Content: post, page, attachment
  • History: revision
  • Block themes: wp_template, wp_template_part, wp_global_styles, wp_navigation
  • Patterns: wp_block · fonts: wp_font_family, wp_font_face
  • Classic themes: nav_menu_item, custom_css
TRY wp post-type list on your own site. Lesson 5.2 adds book.

Two tools, two defaults

WHY WP-CLI lists every status; get_posts() only published, like the front end.
2.1 · Revisions

Every update is a revision

  • Create, then update twice: two revisions
  • The newest revision equals the current post
  • Trash is a status (30 days); --force deletes for good
  • WP_POST_REVISIONS true: keep them all (-1)
RULE Creating is not updating: the first version has no revision.
2.1 · Capabilities

Roles bundle capabilities

wp eval 'var_dump( current_user_can( "edit_posts" ) );'
wp eval 'var_dump( current_user_can( "edit_posts" ) );' --user=admin
bool(false)
bool(true)
WHY WP-CLI runs as nobody without --user. Code checks capabilities, never roles.
2.1 · Options

Every Settings field is an option

wp eval 'var_dump( get_option( "posts_per_page" ) );'

WATCH A string. Options are text in the database: cast them.

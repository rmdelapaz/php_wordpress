5.1

Your First Plugin

Everything the shop does, in a structure that grows.

5.1 · Mental model

The shop's departments

  • pagesco-books is the back office; each feature is a department
  • The main file is the front door: lights on, a list to the manager
  • The manager, Plugin, opens every department on plugins_loaded
  • A new department = a new room + one line on the list
WHY Never knock through the walls of an existing feature.
5.1 · Three relatives

Which PHP runs when?

  • must-use plugin: always, no switch (Lesson 2.3)
  • functions.php: only while that theme is active (Lesson 4.3)
  • plugin: the owner switches it on and off; it can clean up
  • What the shop DOES belongs in a plugin

5.1 · Namespaces and Composer

Class name in, file name out

  • PagesCo\Books\Plugin → src/Plugin.php
  • PagesCo\Books\Admin\SettingsPage → src/Admin/SettingsPage.php
  • composer dump-autoload writes vendor/autoload.php once
  • New classes are found without running Composer again
  • The file name is the class name, letter for letter
CASE macOS and Windows forgive a wrong case. Linux servers do not.

5.1 · Life cycle

Three moments, three jobs

  • Activation: set up once (roles, defaults, tables, rules)
  • Deactivation: a pause; undo what is temporary, keep data
  • Uninstall (uninstall.php): remove the plugin's own data
  • Register both hooks at the TOP LEVEL, with __FILE__

5.1 · Mistake

An activation hook registered too late

5.2

Custom Post Types, Taxonomies & Meta

Teach WordPress about books.

5.2 · Mental model

A new drawer in the same cabinet

  • Post type: a new drawer in wp_posts (book)
  • Taxonomy: colored tabs that group the files (genre)
  • Meta: the index card in each file (price, author)
  • The Loop, WP_Query, REST and the editor work for free
WHY All three register on init, each as a feature class.
5.2 · Live demo

Rules, and a flush

wp rewrite flush
wp rewrite list --match=/books/ --fields=match,query,source
Success: Rewrite rules flushed.
+--------------------------+-------------------------------------------------+--------+
| match                    | query                                           | source |
+--------------------------+-------------------------------------------------+--------+
| books/?$                 | index.php?post_type=book                        | other  |
| (.?.+?)(?:/([0-9]+))?/?$ | index.php?pagename=$matches[1]&page=$matches[2] | page   |
| ([^/]+)(?:/([0-9]+))?/?$ | index.php?name=$matches[1]&page=$matches[2]     | post   |
+--------------------------+-------------------------------------------------+--------+
WHY Until a flush, /books/ is a 404: the rules live in the database.
5.2 · The activator

Registering is not enough on activation

  • On the activation request, the plugin's own init has NOT run
  • So activate() registers the type and taxonomy, THEN flushes
  • deactivate() unregisters both and flushes again
  • Never flush on init: it rewrites the rules on every page load
RULE A deactivated plugin leaves no broken links, and keeps the books.
5.2 · Live demo

The cycle

wp plugin activate pagesco-books

5.2 · Mistake

Stale rules

wp eval 'unregister_post_type( "book" ); flush_rewrite_rules();'
curl -s -o /dev/null -w 'before flush: %{http_code}\n' http://localhost:8080/books/
wp rewrite flush
curl -s -o /dev/null -w 'after flush:  %{http_code}\n' http://localhost:8080/books/
before flush: 404
Success: Rewrite rules flushed.
after flush:  200
WATCH An empty rules option rebuilds itself. Stale rules do not.

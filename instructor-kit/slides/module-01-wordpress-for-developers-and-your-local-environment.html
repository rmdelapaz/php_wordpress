1.1 · One request

Load, then query, then template

  1. index.php → wp-blog-header.php → wp-load.php → wp-config.php
  2. wp-settings.php: core, mu-plugins, plugins, theme, init
  3. wp(): the address becomes the main query
  4. template-loader.php: the theme's template draws the HTML
RULE Core runs the program and calls you: inversion of control.

1.2

Your Local Development Environment

The same site on every laptop.

1.2 · Mental model

A food truck, not a restaurant

  • Docker brings the whole kitchen: Apache, PHP, MySQL
  • docker compose down drives it away; your work stays
  • wordpress/ on your disk is /var/www/html inside
  • Everyone runs the same images: outputs match the lessons
1.2 · Four services

One compose.yaml

  • wordpress: Apache and PHP 8.5, the site on localhost:8080
  • db: MySQL 9.7, data in the volume db_data
  • wpcli: WP-CLI on demand, the wp shortcut
  • mailpit: catches every email, localhost:8025
LINUX Linux and WSL: run it as you (.env + compose.override.yaml) before the first start.
1.2 · Install clinic · 25 minutes

Fix by platform

  • Windows: WSL integration on, the project inside WSL
  • macOS: Docker Desktop started, the right chip
  • Linux: the docker group, a new login
  • Linux and WSL: the file-owner fix, or the repair box
  • Done = check_environment.sh says READY

1.2 · Everyday commands

Start, stop, reset

  • docker compose up -d · ps · stop: everything kept
  • docker compose down: containers gone, files and database kept
  • docker compose down -v: the database is deleted
  • wp-env: npx @wordpress/env, never npx wp-env
CAREFUL -v means the volumes. Only when you really want a blank site.

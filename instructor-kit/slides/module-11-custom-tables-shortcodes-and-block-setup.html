5.5 · Storage

When a custom table is right

  • Content people write: a post type (+ meta)
  • A shared label: a taxonomy
  • A few site-wide values: an option
  • Many uniform rows, queried by their fields: a custom table
PRICE You give up REST, admin screens, revisions and export for free.
5.5 · dbDelta()

One statement for install and upgrade

  • One column or index per line
  • PRIMARY KEY (id), KEY starts_at (starts_at)
  • $wpdb->get_charset_collate() at the end
  • The name from $wpdb->prefix, never wp_
  • It only ADDS: no renames, no drops

5.5 · $wpdb

A row's whole life

wp eval 'use PagesCo\Books\EventsTable; global $wpdb;
$id = EventsTable::add( "Test event", "2027-10-31 12:00:00",
    "Back office", 0 );
echo $wpdb->get_var( $wpdb->prepare( "SELECT title FROM %i WHERE id = %d",
    EventsTable::name(), $id ) ), "\n";
echo $wpdb->delete( EventsTable::name(), array( "id" => $id ),
    array( "%d" ) ), " row deleted\n";'
Test event
1 row deleted
WHY Values passed separately from the SQL, every time.
5.5 · Mistake

A schema change without a version

  • A host column added to schema(), the page reloaded
  • pagesco_books_db_version is still 1, so maybe_upgrade() did nothing
  • information_schema: 0 host columns; the first query that reads host fails
  • Every schema change comes with a higher DB_VERSION
WATCH dbDelta() only runs when asked, and only adds.

6.1

Block Development Setup

Node, a build, and the first block in pagesco-books.

6.1 · Mental model

A kit, a workshop and a shelf

  • Kit: src/blocks/book-card (JSX, SCSS)
  • Workshop: npm run build (@wordpress/scripts)
  • Shelf: build/blocks + blocks-manifest.php
  • WordPress only looks at the shelf
WHY Change the kit and nothing happens until the workshop runs.
6.1 · A block type

Four parts

  • block.json: name, title, icon, supports, files
  • edit: the editing view, a React component
  • save: the HTML stored in post_content
  • styles; later a PHP render (Lesson 6.3)
WHY A static block's front end needs no JavaScript.

6.1 · create-block

Into the plugin we have

  • npx @wordpress/create-block@latest book-card
  • --no-plugin --target-dir=src/blocks/book-card
  • --namespace=pagesco --textdomain=pagesco-books
  • Without --no-plugin: a second plugin
WATCH The name pagesco/book-card is stored in every post: never rename it.
6.1 · package.json

One build script, three flags

  • --webpack-src-dir=src/blocks: away from the PHP classes
  • --output-path=build/blocks: one folder per block
  • --blocks-manifest: blocks-manifest.php
  • npm install once; npm run build / npm start

6.1 · Mistake

A missing build

  • A fresh checkout: build/ is not in Git, nobody ran npm
  • "The specified manifest file does not exist." above every page
  • With display on, the editor breaks too; with it off, the block just vanishes from the inserter
  • Fix: npm install && npm run build wherever the plugin comes from source
WATCH Posts keep showing their saved HTML: it is in the post.
6.1 · Mistake

src changed, build did not

  • The icon changed to book in src/blocks/book-card/block.json
  • WordPress still says smiley: it reads the manifest in build/
  • npm run build, ask again: book
  • While you work: npm start rebuilds on every save
WATCH The kit changed; the shelf did not.

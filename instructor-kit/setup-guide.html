PHP and WordPress Development · Before You Begin

Set Up Your Local WordPress for the Course

About 45 minutes to do before the first session, most of it downloading: install Docker, unpack the course's Compose project pagesco-dev, start it, install WordPress 7.1 on PHP 8.5 with two commands, and run a short check that tells you (and your instructor) whether your laptop is ready. These are the same steps as Lesson 1.2 on the course site (rays-php-wordpress.netlify.app, lesson "Your Local Development Environment"), which shows every step with its real output. Session 1 then spends its time on WordPress instead of progress bars. A second, shorter setup (Node 24, Composer and, if you join for Part 2, a ready-made starting site) comes before Part 2: see Part 2 Setup near the end.

⏱ 30–60 min, mostly downloading About 3 GB of images Windows (WSL 2) · Mac · Linux Free software
Please do this at home, not in class

The Session 1 images come to about 3 GB on disk. Twenty laptops pulling them at once over venue Wi-Fi takes most of a session. If a step fails, keep going with the others and bring the exact error message (a screenshot is fine) to Session 1: its first half hour includes the environment check, and Lesson 1.2's time in the room is an install clinic.

What You Need

  • A laptop and its charger: Windows 10/11 (64-bit) with WSL 2, a recent macOS (Apple silicon or Intel), or a 64-bit Linux. 8 GB of memory or more is comfortable (the course site itself runs in 2 to 3 GB) and about 10 GB of free disk space for Docker, the images and the project. You need permission to install software (Docker needs administrator rights once). Chromebooks, tablets and locked work laptops cannot run the course comfortably: talk to your instructor first.
  • Docker: Docker Desktop on Windows and macOS, Docker Engine with the Compose plugin on Linux (Step 1). Docker Desktop is free for personal use, education and small businesses; larger companies need a paid subscription, so check before you install it on a work computer.
  • A terminal: the Ubuntu app on Windows (WSL 2), Terminal on macOS, your usual terminal on Linux. Every course command runs there.
  • A code editor: VS Code (free) works well, with a PHP extension such as PHP Intelephense; on Windows also the WSL extension.
  • A web browser with developer tools (any current Chrome, Edge, Firefox or Safari).
  • The course's labs/ folder, which your instructor sends with this guide. Its file labs/module-01/l1_0-orientation/check_environment.sh is the environment check in Step 5.
  • A learning journal: a plain text file or a paper notebook. Every lesson ends with a journal prompt.

Am I Ready for This Course?

PHP and WordPress Development builds on PHP Foundations and MySQL Foundations (or the same material learned elsewhere): it does not re-teach PHP. Lesson 1.3 is a short refresher on how WordPress uses it. You are ready if you can:

  • ☐ Write a PHP function with typed parameters, loop over an associative array and explain what htmlspecialchars() protects against
  • ☐ Read a small PHP class with a namespace, and say what Composer's vendor/autoload.php does
  • ☐ Write a SELECT with a JOIN and a WHERE, and say why prepared statements matter
  • ☐ Write a small HTML page with a stylesheet, and read basic JavaScript (Module 6 builds blocks with it)
  • ☐ Move between folders in a terminal with cd, list files with ls and run a command someone gives you

Two or more unchecked? Come anyway and tell your instructor. Session 1 includes a short, ungraded diagnostic on these same skills, so your instructor knows where to help.

Set Up in 5 Steps

1

Install Docker

~15 min

Skip this step if docker compose version already prints a version 2 or newer (the Docker lessons of PHP Foundations or MySQL Foundations may have set you up).

  • Windows 10 and 11: WSL 2 plus Docker Desktop. Open PowerShell as administrator and run wsl --install; restart when asked and create a Linux user name and password when Ubuntu starts for the first time. Install Docker Desktop for Windows with the WSL 2 backend (the installer's default), start it, open Settings > Resources > WSL integration and switch on your Ubuntu distribution. From now on, open the Ubuntu app for every command, and keep the project in the Linux file system (your Linux home folder, ~), not under /mnt/c/: there every page load crosses from Linux to Windows and WordPress becomes many times slower. Inside Ubuntu you are on Linux: do the Linux part of Step 2 too.
  • macOS. Install Docker Desktop for Mac (Apple silicon or Intel, to match your Mac), start it once from Applications and wait until it says it is running. All the course images run natively on both kinds of Mac.
  • Linux. Install Docker Engine and the Compose plugin from Docker's own package repository (docs.docker.com/engine/install; your distribution's packages are often too old). Then let your user run Docker without sudo, and log out and back in: 
    sudo usermod -aG docker "$USER"

Check (your version numbers will differ):

docker --version
docker compose version
docker run --rm hello-world

Write docker compose with a space. The old separate program docker-compose, with a hyphen, is retired.

2

Get the course project (and, on Linux or WSL, run WordPress as you)

~5 min

The course ships a ready-made Compose project, pagesco-dev: WordPress 7.1 on PHP 8.5 with Apache, MySQL 9.7, WP-CLI and Mailpit, the same images the lessons were tested on. Download and unpack it in your home folder (on Ubuntu and WSL, sudo apt install unzip first if unzip is missing):

cd ~
curl -LO https://rays-php-wordpress.netlify.app/downloads/pagesco-dev.zip
unzip pagesco-dev.zip
cd pagesco-dev

From here on, your project folder means pagesco-dev, and every docker compose command runs inside it.

Linux and Windows (WSL 2) only: before the first start

Without this, the WordPress image creates every file as its web server user (uid 33) and your editor gets "Permission denied" in wordpress/wp-content/. From the project folder, once:

printf 'PAGESCO_UID=%s\nPAGESCO_GID=%s\n' "$(id -u)" "$(id -g)" > .env
cp config/compose.linux.yaml compose.override.yaml
mkdir wordpress
cat .env

cat .env prints your two numbers (often PAGESCO_UID=1000 and PAGESCO_GID=1000). Already started without it? The repair, from the project folder:

docker compose run --rm --user root wpcli chown -R "$(id -u):$(id -g)" /var/www/html
printf 'PAGESCO_UID=%s\nPAGESCO_GID=%s\n' "$(id -u)" "$(id -g)" > .env
cp config/compose.linux.yaml compose.override.yaml
docker compose up -d

macOS (and Docker Desktop without WSL) needs nothing here.

3

Start the site and install WordPress

~5 min (the first start downloads the images)
docker compose up -d
docker compose ps

ps lists pagesco-db-1 (healthy), pagesco-mailpit-1 and pagesco-wordpress-1. Then install WordPress and turn on pretty permalinks (two long lines; copy them whole):

docker compose run --rm wpcli wp core install --url=http://localhost:8080 --title="Pages & Co." --admin_user=admin --admin_password=password --admin_email=wordpress@example.com --skip-email
docker compose run --rm wpcli wp rewrite structure '/%postname%/'

Expected: Success: WordPress installed successfully., Success: Rewrite structure set. and Success: Rewrite rules flushed. (The first run wpcli builds the course's WP-CLI image, about a minute.) Open http://localhost:8080: the Pages & Co. site in Twenty Twenty-Five. Log in at http://localhost:8080/wp-admin/ as admin / password (a development password for a site that exists on your computer alone).

Make the course's wp shortcut and add the same line to ~/.bashrc (macOS: ~/.zshrc) so a new terminal has it too:

alias wp='docker compose --progress quiet run --rm wpcli wp'

Check: wp core version --extra starts with WordPress version: 7.1.3, and wp eval 'echo "PHP ", PHP_VERSION, "\n";' prints PHP 8.5.12.

4

Turn on email (Mailpit) and put labs/ in place

~3 min

Mailpit catches every email the site sends (nothing is delivered) and shows it at http://localhost:8025. WordPress needs one small must-use plugin to reach it; without it wp_mail() returns false (Invalid address: (From): wordpress@localhost). From the project folder:

mkdir -p wordpress/wp-content/mu-plugins
cp config/mailpit-smtp.php wordpress/wp-content/mu-plugins/
wp plugin list --status=must-use

The list shows mailpit-smtp as must-use. Now copy the labs/ folder from your instructor into the project folder, next to compose.yaml (not inside wordpress/, which is the web root):

pagesco-dev/
  compose.yaml   config/   wordpress/   labs/     <- here
5

Run the environment check

~2 min

On your computer (not in a container), from the project folder, with the site started:

cd ~/pagesco-dev
bash labs/module-01/l1_0-orientation/check_environment.sh

It checks Docker and Compose, the project folder, the running services, who owns wordpress/, WP-CLI, WordPress 7.1, PHP 8.5 on the web server and in WP-CLI, the site address, permalinks, the home page, wp cron test, the debug settings, a test email through Mailpit and the host ports. It changes nothing on your site. Each line says OK, CHECK (works, read the note), INFO or FIX (what to do next); the last line is the verdict.

✅ Done when the last line says READY for PHP and WordPress Development

Send that line to your instructor. READY WITH NOTES is fine: read the CHECK lines (for example PHP 8.4 instead of 8.5, or a project folder on the Windows drive). NOT READY? Fix the FIX lines from the top (each names the next step; the table below has more), run the check again, then send the whole output.

PHP 8.4 and other ways to run WordPress

The course is built and checked on WordPress 7.1.3 and PHP 8.5; keep the image names in compose.yaml as they are. A site on PHP 8.4 runs the course: the lessons note where its output differs (a few cards of Lessons 1.2 and 1.3 show PHP 8.5-only output, such as the longer fatal-error format), and the check says READY WITH NOTES. Local, XAMPP, MAMP, Laravel Herd, wp-env and WordPress Playground all run WordPress, and Lesson 1.2 shows wp-env and Playground; but the course's outputs, paths (/var/www/html/...), port, mail catcher and WP-CLI fixes are tested on the Docker project. If you are new to all of them, use the course project.

Common Install Problems

You see…Try this
Bind for 0.0.0.0:8080 failed: port is already allocated (or 8025)Something else listens on that port: another Compose project, an old container, a local Apache, another course's server. Find it with docker ps (the PORTS column) and stop it. Changing the course port means changing the site URL too, and the lessons' URLs no longer match: freeing the port is easier.
Linux/WSL: mkdir: cannot create directory ‘wordpress/wp-content/mu-plugins’: Permission deniedThe site started without the Linux setup: the repair box in Step 2.
required variable PAGESCO_UID is missing a valuecompose.override.yaml is there but .env is not: the printf line of Step 2.
WSL: everything works but pages take seconds; the check says CHECK the project is on the Windows driveThe project is under /mnt/c/. Move it to your Linux home folder (~/pagesco-dev) and open it with code . from Ubuntu.
no configuration file provided: not foundThe terminal is not in the project folder: cd ~/pagesco-dev.
wp_mail() returns bool(false); the check says FIX wordpress/wp-content/mu-plugins/mailpit-smtp.php is missingStep 4's cp. WordPress's default From address wordpress@localhost is rejected; the mu-plugin sends through Mailpit with a valid address.
Access denied for user 'wordpress' after editing compose.yamlDatabase passwords are set on the very first start only. Put the old value back, or start over with docker compose down -v (this deletes the database) and Step 3 again.
Deprecated: Using null as an array offset … php-cli-tools/lib/cli/Colors.php after every WP-CLI lineYou ran a WP-CLI installed on your computer with PHP 8.5: that notice is WP-CLI's own code, not yours. Use the course's wp shortcut (the container's WP-CLI hides it).
npx wp-env prints something odd ("Security PoC")That is a different npm package. The WordPress tool is always npx @wordpress/env … (Lesson 1.2 and Lesson 8.1).
Docker is installed but docker ps failsStart Docker Desktop. On Linux: sudo usermod -aG docker "$USER", then log out and in.

More cases, each with the exact error text: Lesson 1.2's Common Mistakes section, and the course's Troubleshooting page (rays-php-wordpress.netlify.app/troubleshooting.html) and Common Errors page (rays-php-wordpress.netlify.app/common-errors.html).

B

The Part 2 starting site (only if your site has not finished Lesson 4.3)

~1 min

Part 2 starts from the site exactly as Lesson 4.3 leaves it: the pagesco block theme active, pagesco-classic and pagesco-tt5-child installed, the store notice mu-plugins/pagesco-site.php, the users maria (editor) and devon (author), the pages About Us, Contact and Events, and the News posts. Learners who did Part 1 already have it. Anyone new, or with a broken Part 1 site, installs the course download pagesco-part2-start.zip:

    curl -LO https://rays-php-wordpress.netlify.app/downloads/pagesco-part2-start.zip
unzip pagesco-part2-start.zip
  2. Copy the pagesco-part2-start folder into your project's wordpress/ folder: 
    cp -R pagesco-part2-start ~/pagesco-dev/wordpress/
  3. From the project folder, run the installer in the WP-CLI container: 
    cd ~/pagesco-dev
docker compose run --rm wpcli sh pagesco-part2-start/install.sh

The import replaces your posts, pages, users and settings. Undo: docker compose run --rm wpcli wp db import pagesco-part2-start/backup-before-part2.sql. Frequently Asked

Docker Desktop uses a lot of memory. Can I limit it?

Yes. On Windows, WSL 2 takes what it needs up to a limit you set in a .wslconfig file in your Windows user folder (memory=4GB under [wsl2]); on macOS, Docker Desktop's Settings > Resources has a memory slider. Run docker compose stop when you are not working.

Does stopping the site lose my work?

No. docker compose stop and docker compose down keep your files (in wordpress/) and your database (in a Docker volume); docker compose up -d brings it all back. Only docker compose down -v deletes the database.

Where is phpMyAdmin?

Not included: wp db query and wp db cli cover what the lessons need, with the SQL you know from MySQL Foundations.

Is the course data real?

No. Pages & Co., its staff, events and customers, the Part 1 project and assessment clients and the final project's shop are invented for the course (the books are real classics). The passwords are development passwords for a site on your own computer: never use them anywhere else.

What if a step fails and I cannot fix it?

Come anyway, with the output of the environment check. Session 1 opens with the check and has an install clinic, and you can pair with a neighbor until your machine is ready.

Session 2: PHP the WordPress Way and the Content Model

How to teach the session where learners start writing WordPress code and stock the site with content: the house rules of WordPress PHP (coding standards checked by PHPCS, prefixes, sanitize early and escape late, translatable strings, callbacks, arrays of arguments, WP_Error), then the content model seen from WP-CLI and PHP, ending with the Pages & Co. staff, pages and News posts that every later lesson starts from.

The #1 risk of Session 2: the IDs drift

Lesson 2.1's project prints IDs 12 to 17 because every earlier block of the lesson used one up: attachment 5, the revision demo's post 6 and its revisions 7 and 8, the Gift Cards draft 9, the duplicate Sample Page 10 and its trash revision 11. So: in the 2.1 demo everybody types along, and before the project every machine runs the next-ID check below. It must print 12. Retrieval questions and answers
  1. Which folder of the WordPress root is yours, and why is nothing else? Answer: wp-content/ (themes, plugins, mu-plugins, uploads), plus your settings in wp-config.php. Everything else is core and every update replaces it.
  2. Put them in order: the main query, init, the template. Answer: init (the end of loading: core, mu-plugins, plugins, the theme), then wp() runs the main query, then the template loader draws the page: load, query, template.
  3. docker compose down and docker compose down -v: what survives each? Answer: down keeps the files and the database (the volume); -v deletes the database volume too.
  4. A page says "There has been a critical error on this website." Where do you look first? Answer: The end of wordpress/wp-content/debug.log (tail -n 20 wordpress/wp-content/debug.log, or tail -f while reloading).
  5. What does wp option get blogname print on the course site, and why? Answer: Pages &amp; Co.: WordPress stored the title HTML-escaped when it was saved. Today's first lesson explains when to escape yourself.

PHP the WordPress Way

70 min
Objectives (from the lesson page)
  • Write PHP that follows the WordPress coding standards, and check it with PHPCS and the WordPress ruleset
  • Choose the right escaping function for each output context (esc_html, esc_attr, esc_url, wp_kses_post) and the right sanitizing function for each input
  • Make strings translatable with __(), esc_html__(), _n() and sprintf(), with a text domain and translator comments
  • Pass callbacks in every form WordPress accepts, and write functions that take an array of arguments merged with wp_parse_args()
  • Handle WP_Error results, and use core's globals ($wpdb, $post, $wp_query) and classes without fighting them

Mental model to say

"In PHP Foundations your code was the whole application. In WordPress it is a guest. Moving from your own apartment into a shared house: you label your food (prefixes), you use the shared kitchen tools the way everyone does (core's functions instead of your own helpers), you leave notes others can read (coding standards and DocBlocks), and you do not rearrange the living room (globals). None of the rules is hard. Ignoring them is what causes the fights."

Then the lesson's bridge table, four rows on the board: htmlspecialchars() → esc_html() and friends · filter_input() → wp_unslash() + sanitize_*() · exceptions → WP_Error · PDO → $wpdb. And one sentence on versions: "WordPress 7.1 still runs on PHP 7.4, so core looks old-fashioned. Your plugin declares its own minimum (Lesson 5.1) and may use modern PHP above it. You are learning conventions, not going back in time."

Three mistakes to expect, and how to coach each
  • The wrong escaper, or one for everything. esc_html() around an href, or esc_attr() everywhere. Coach with the board's table and one question: "Where does this value land: between tags, in an attribute, in a URL?" (Self-check Q1, lesson quiz Q1, the guided lab's TODOs 6 and 7.)
  • Sanitizing on output, escaping on input. $nick = esc_html( $_POST['nickname'] ). Coach: "Sanitize is for the way in, escape for the way out; the database should hold the clean value, not HTML entities." (Lesson quiz Q5.)
  • Forgetting wp_unslash(). The apostrophe in O'Neil grows a backslash. Coach: "WordPress added it on the way in; take it off before you clean." (The slashes demo, the guided lab's TODO 1.)

Checks for understanding

Ask these out loud during the demo and the lab (cold-call gently, or think-pair-share):

  • Which escaper for a link's href, for its title attribute, and for its text? Answer: esc_url(), esc_attr(), esc_html().
  • Why does every function in the course theme start with pagesco_? Answer: one global namespace per request, shared by core and every plugin; two functions with one name are a fatal error.
  • What do __() and _e() do differently? Answer: __() returns the translation, _e() echoes it (and returns null).
  • A WordPress function failed. Exception, false, or something else? Answer: usually a WP_Error (check with is_wp_error()); some return 0 or false unless you ask for the error: read the Return line.

Mental model to say

Draw a filing cabinet with one drawer labeled wp_posts: "Every document goes into the same kind of folder with the same fields: title, content, author, date, status. A colored label says what it is: blog post, page, image, old version, template, menu. Code that works on 'a folder' (saving, revisions, permissions, the REST API) works on every label at once. That is why a custom post type, Lesson 5.2's book, gets all of it for free."

Then the rest of the picture around the cabinet: terms (colored tabs: categories, tags, later genre), users (who may open which drawer: roles are bundles of capabilities, and code checks the capability), options (the settings on the wall: every Settings field is one), and block markup (what is written on the paper: HTML wrapped in comments). "Every feature you meet later, in core or in a plugin, is one of these in disguise."

Three mistakes to expect, and how to coach each
  • "My page is not there." A draft (the default of wp post create and wp_insert_post()) or a PHP list that only shows published content. Coach: "Which status? Which default does this tool have?" (Mistake 1, self-check Q8.)
  • Checking a role. in_array( 'editor', $user->roles ) for "may edit others' posts" locks out the administrator. Coach: "Which capability does the feature need?" (Lesson Mistake 3, self-check Q9, the debug handout.)
  • Copying block markup by hand and changing it. A missing wp-block-heading class: fine on the front end, "invalid block" in the editor. Coach: "Copy it from the Code editor or the lesson, never retype the HTML." (The lesson's warning box; in the project, learners copy the files from the page.)

Checks for understanding

Closing

Exit ticket (3 questions, no notes, 4 minutes)

Put the three questions on the slide. Learners answer in the workbook's Exit Ticket box or on a sticky note and leave it on the way out. Sort the notes before Session 3: question 1's pile tells you how much of Session 3's warm-up goes back to escaping.

  1. Which escaping function for text between tags, for an attribute value, and for an href? Answer: esc_html(), esc_attr(), esc_url() (and wp_kses_post() for HTML a post may contain).
  2. Why does every global name in your theme and plugin start with pagesco_? Answer: WordPress, the theme and every plugin share one PHP process (and one options table): two functions with the same name are a fatal error, and you cannot know which plugins the client installs next year.
  3. Posts, pages, uploaded images, revisions and block-theme menus: where are they stored, and what tells them apart? Answer: all are rows of wp_posts; the post_type column (post, page, attachment, revision, wp_navigation).

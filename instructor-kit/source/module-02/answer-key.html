Warm-up · Session 1 Revisited

  1. W1 Which folder of the WordPress root is yours, and why is nothing else? Answer: wp-content/ (themes, plugins, mu-plugins, uploads), plus your settings in wp-config.php. Everything else is core and every update replaces it.
  2. W2 Put them in order: the main query, init, the template. Answer: init (the end of loading: core, mu-plugins, plugins, the theme), then wp() runs the main query, then the template loader draws the page: load, query, template.
  3. W3 docker compose down and docker compose down -v: what survives each? Answer: down keeps the files and the database (the volume); -v deletes the database volume too.
  4. W4 A page says "There has been a critical error on this website." Where do you look first? Answer: The end of wordpress/wp-content/debug.log (tail -n 20 wordpress/wp-content/debug.log, or tail -f while reloading).
  5. W5 What does wp option get blogname print on the course site, and why? Answer: Pages &amp; Co.: WordPress stored the title HTML-escaped when it was saved. Today's first lesson explains when to escape yourself.

1.3 · PHP the WordPress Way: self-check

Q1
A template prints a book cover: <img src="..." alt="...">. The alt text is the book's title as staff typed it. Which function goes around the title?
A) esc_html()
B) esc_attr()
C) esc_url()
D) wp_kses_post()
Why: The value goes inside an attribute, so esc_attr() (and the attribute is quoted). Lesson 1.3's rule: escape late, for the exact place the value is printed into.
A is wrong: esc_html() is for text between tags. Here it would happen to encode the same characters, but a reviewer or PHPCS reads the context from the function: use the one that names it.
C is wrong: esc_url() is for the src and every href: it checks the protocol, which an alt text does not have.
D is wrong: wp_kses_post() keeps HTML tags a post may contain; tags inside an attribute value break the page.
Q2
From the project folder, on the course site: what does this print?
wp eval 'echo esc_html( esc_html( "Tom & Jerry" ) ), "\n";'
Tom &amp; Jerry
Why: The first esc_html() turns the ampersand into &amp;, and the second leaves an entity that is already there alone: WordPress's escapers do not double-encode (Lesson 1.3, the escape.php demo), so escaping at output is safe even when something upstream already escaped.
Q3
What reaches the page from $h = '<h2>' . _e( 'Staff picks', 'pagesco' ) . '</h2>'; echo $h;?
A) <h2>Staff picks</h2>
B) Nothing: PHP stops with a fatal error
C) "Staff picks" first, then an empty <h2></h2>
D) <h2>_e(Staff picks)</h2>
Why: _e() ECHOES the translation at once and returns null, so the text is printed while the string is still being built, and the heading ends up empty. Inside an expression you want __(), or better esc_html__() (Lesson 1.3, Common Mistakes 3). No message warns you.
A is wrong: That is what __() would give.
B is wrong: Concatenating null is allowed; nothing complains.
D is wrong: _e is a function call, not text.
Q4
Which of these needs NO pagesco_ prefix?
A) A class inside the namespace PagesCo\Books, such as PagesCo\Books\Plugin
B) A global function that formats prices
C) A variable defined at the top level of a plugin file
D) An option your plugin saves in wp_options
Why: The namespace is the prefix (Module 5's plugin uses one). Everything global shares one PHP process with core and every plugin, and a database table with them: functions, global variables, constants, hook names, options and meta keys all get the prefix.
B is wrong: Two plugins with format_price() stop the site with a fatal error.
C is wrong: A plugin file runs in the global scope, so its variables are globals.
D is wrong: Options share wp_options with core and every plugin: pagesco_books_settings, not settings.
Q5
What does this print?
wp eval 'var_dump( absint( "-7 copies" ), sanitize_key( "Staff Picks!" ) );'
int(7)
string(10) "staffpicks"
Why: absint() makes a non-negative integer: the text is cut at the first non-digit and the minus sign is dropped (validate when a negative must be REJECTED). sanitize_key() keeps lowercase letters, digits, dashes and underscores: option names and array keys.
Q6
$id = wp_insert_post( array( 'post_title' => '' ) ); What is $id, and how do you learn why it failed?
A) A WP_Error: call $id->get_error_message()
B) false: read debug.log
C) An exception: wrap the call in try/catch
D) 0: pass true as the second argument to get a WP_Error with the message
Why: By default wp_insert_post() returns 0 on failure; with true as its last argument it returns the WP_Error ("Content, title, and excerpt are empty."). Read the Return line in the Code Reference before you rely on a result (Lesson 1.3, errors.php).
A is wrong: Only when asked for with true; wp_insert_user() always returns one.
B is wrong: Nothing is logged: the failure is silent.
C is wrong: Core returns errors as values; it does not throw.

1.3 · PHP the WordPress Way: predict, then run

P1
Predict the output, then run it.
wp eval 'echo esc_url( "example.com/books?a=1&b=2" ), "\n";'
http://example.com/books?a=1&#038;b=2
Why: esc_url() adds http:// to an address without a protocol (it looks like a domain) and encodes the ampersand for HTML as &#038;. In an href the browser turns it back into &. A URL you store or redirect to uses esc_url_raw(), which leaves the & alone.
P2
Predict the output, then run it.
wp eval 'echo _n( "%s book", "%s books", 0 ), "\n";'
%s books
Why: English uses the plural for zero, so _n() picks the second string. It does NOT fill in the number: _n() only chooses the string, and sprintf() puts the count into %s (Lesson 1.3's book card does both: sprintf( _n( ... ), number_format_i18n( $n ) )).

2.1 · The Content Model: self-check

Q7
Twenty Twenty-Five's header menu lists the site's pages. Which post type stores that menu?
A) nav_menu_item
B) page
C) wp_template_part
D) wp_navigation
Why: Block themes keep their menus as wp_navigation posts (post 4 on the course site, holding a Page List block). Everything is a post with a type: one filing cabinet, many labels (Lesson 2.1).
A is wrong: nav_menu_item rows are the menus of classic themes (Module 4).
B is wrong: The pages are what the menu LISTS, not the menu.
C is wrong: The header template part contains the Navigation block; the menu itself is a separate post.
Q8
On a fresh course site (before the lesson project): what does this print, and why are the two numbers counting different things?
wp eval 'echo count( get_posts( array( "post_type" => "page" ) ) ), " ", wp_count_posts( "page" )->draft, "\n";'
1 1: one published page for get_posts() (it defaults to publish), and one draft page counted by wp_count_posts() (the Privacy Policy)
Why: get_posts() and WP_Query default to 'post_status' => 'publish', so PHP sees only the Sample Page; wp_count_posts() counts every status, and the draft Privacy Policy is one of them. WP-CLI's wp post list also lists every status unless you pass --post_status.
Q9
Devon (Author) opens Maria's published post "Book club: Dune" (ID 17). What does user_can( $devon, 'edit_post', 17 ) answer?
A) false: edit_post is a meta capability that maps to edit_others_posts here, which authors lack
B) true: authors have edit_posts
C) true: the post is published
D) An error: edit_post needs a role, not a user
Why: WordPress maps the meta capability edit_post to real capabilities from the post's author and status: someone else's published post needs edit_others_posts (and edit_published_posts). Lesson 2.1's Exercise 1 prints exactly this "no".
B is wrong: edit_posts covers his own posts only.
C is wrong: Published makes it harder, not easier: edit_published_posts joins the list.
D is wrong: user_can() takes a user (or ID); roles are never checked directly.
Q10
What does this print?
wp eval 'echo parse_blocks( "<!-- wp:separator /-->" )[0]["blockName"], "\n";'
core/separator
Why: Block markup drops the core/ namespace of core blocks (wp:separator), and parse_blocks() puts it back. A self-closing comment is a block with no saved HTML; dynamic blocks such as Latest Posts look the same and are rendered by PHP on every view.
Q11
A script creates a post with WP-CLI and then updates it twice. How many revisions does the post have, and what is in the newest one?
A) Three: the newest holds the version before the last update
B) Two: the newest is identical to the current post
C) One: WordPress keeps only the latest
D) None: only the block editor makes revisions
Why: "Every update is a revision, and the most recent revision always matches the current post" (core's own comment, shown in Lesson 2.1). Creating a post is not an update, so the first version has no revision.
A is wrong: That is the intuitive model, and it is wrong in both the count and the content.
C is wrong: WP_POST_REVISIONS is true on the course site: every revision is kept (-1).
D is wrong: WP-CLI and the editor both call wp_insert_post() / wp_update_post(); the revision comes from core.
Q12
A deployment script must set the "Site Address (URL)" field of Settings > General. Which option is that?
A) siteurl
B) blogname
C) home
D) permalink_structure
Why: Site Address is home (where visitors find the site); WordPress Address is siteurl (where WordPress's files live). They are usually equal, which is why they are easy to swap. Every Settings field is a row in wp_options (Lesson 2.1's table).
A is wrong: siteurl is the WordPress Address field.
B is wrong: blogname is the Site Title.
D is wrong: permalink_structure is Settings > Permalinks.

2.1 · The Content Model: predict, then run

P3
Predict the output, then run it.
wp post list --post_type=attachment --format=count
0
Why: Zero. Twenty Twenty-Five's pictures are files in its theme folder, not uploads: only what goes through the Media Library (or wp media import) becomes an attachment post. The lesson's demo imports one of those theme files and deletes it again.
P4
Predict the output, then run it.
wp eval 'var_dump( get_option( "page_on_front" ), get_option( "pagesco_no_such_option" ) );'
string(1) "0"
bool(false)
Why: page_on_front exists and is the STRING "0" (no static front page; options are strings). An option that does not exist returns false, which is how get_option() tells you it is missing (pass a second argument for another default).

The Lesson Pages' Own Quick Quizzes

Lesson 1.3 · PHP the WordPress Way
  1. C echo '<a href="' . esc_url( $url ) . '">Website</a>';: href and src take esc_url, which encodes the URL for HTML and drops dangerous protocols such as javascript:.
  2. A small red: wp_parse_args keeps the default size, uses the passed color, and simply carries the misspelled colour key along without using it.
  3. B if ( 0 === $count ) { pagesco_reset_count(); }: Spaces inside the parentheses, a Yoda condition with ===, and a prefixed snake_case function name.
  4. A if ( is_wp_error( $id ) ) { /* show $id->get_error_message() */ }: wp_insert_user returns the new user ID or a WP_Error object; is_wp_error tells the two apart, and the error object has the code and message.
  5. C $nick = sanitize_text_field( wp_unslash( $_POST['nickname'] ) );: Unslash first (WordPress adds slashes to request data), then sanitize on input. Escape later, when you print it.
Lesson 2.1 · The Content Model
  1. B A page: Timeless content that is linked from a menu rather than listed by date is what pages are for.
  2. C core/heading 4: Core blocks are core/name in PHP even though the comment omits the namespace, and attributes come from the JSON in the opening comment.
  3. A current_user_can( 'edit_others_posts' ): Check the capability the feature needs. Administrators, editors and any custom role that has it pass; nobody else does.
  4. B At least three; the newest is identical to the current page: Every update stores a revision of the new version, so the most recent revision always matches the current page.
  5. C In the posts_per_page option: wp option update posts_per_page 12: Every Settings field is an option; this one is posts_per_page, so wp option update posts_per_page 12 sets it.

Exit Ticket

  1. Escapers: esc_html() for text between tags, esc_attr() for an attribute value (quoted), esc_url() for every href and src; wp_kses_post() when the value is HTML a post may contain.
  2. Prefixes: core, the theme and every active plugin run in ONE PHP process with one global namespace (and share one options table): a second function with the same name is a fatal error that takes the site down, and you cannot know which plugins a client installs later. A namespace counts as a prefix for classes.
  3. The content model: all are rows of wp_posts; the post_type column tells them apart (post, page, attachment, revision, wp_navigation). That is why they share revisions, permissions and the REST API.

Common Wrong Answers and What They Reveal

  • Q1 A (esc_html()). Thinks of escaping as one operation. It works here by accident; ask where an href goes, then show the javascript: link from Mistake 1.
  • Q2 Tom &amp;amp; Jerry. Expects double encoding. Run it: WordPress's escapers leave existing entities alone.
  • Q3 A. Has not met "_e echoes". Have them run the demo's mistake-e.php and read the third line of its output.
  • Q4 C. Thinks a variable in a plugin file is private. Plugin files run in the global scope; show $GLOBALS holding it.
  • Q6 A. Generalizes from wp_insert_user(). Read the Return line of wp_insert_post() in the Code Reference together.
  • Q7 A. Classic-theme knowledge. Run wp post get 4 --field=post_type and --field=post_content.
  • Q8 2 1 or 1 0. Expects one default for all tools. WP-CLI vs get_posts() is the lesson's statuses section.
  • Q11 A. The intuitive model of revisions. Run the lesson's revision demo again and compare the newest revision with the post.
  • Q12 A. Swaps the two addresses. WordPress Address = siteurl (files), Site Address = home (visitors).

Lesson

9.1

Final Project: Launch the Pages & Co. Website

By the end of the project you can
  • Turn a client's brief into data, rules, routes, blocks and screens, and decide where each rule is enforced
  • Build a feature through every layer of the course: a custom table, settings, a service class with a custom hook, REST routes with real permission callbacks, form handlers, a staff screen, a dynamic and an interactive block, and a theme pattern with live data
  • Make it secure and private by default: nonces and capabilities on every change, ownership in every query, escaping, and personal data kept no longer than needed
  • Prove the feature with coding standards, PHPUnit tests, a smoke test from outside, accessibility checks and a performance measurement
  • Release it from a tagged commit and deploy it as code only, then present your work against a rubric
Key ideas
  • A feature is a stack of layers: the data (HoldsTable only stores), the rules (Holds only decides), the doors (form handlers, REST routes, blocks only check who is asking). A rule changes in one place.
  • A custom table for holds: typed columns, indexes for "this customer's holds" and "what is waiting", a clean delete. maybe_upgrade() on init creates it on an update, where activation never runs.
  • "Expired" is computed, never stored: waiting and pickup_by before today.
  • Ownership goes into the query (WHERE id = %d AND user_id = %d, the user from the login); another customer's hold is "not found", so its existence is never confirmed.
  • Errors carry their HTTP status: 401 not logged in, 404 no such thing (or not yours), 409 the shop's state says no. Every door passes it on.
  • Your own action (pagesco_books_hold_placed) is the extension point: the email listens to it; the rules know nothing about email.
  • Measure first (the query report), prove last (lint, tests, a smoke test, the numbers again).
Worked example: what a release ZIP would contain

Lesson 9.1's Common Mistake 1, met before it happens. In the plugin's folder, with Node as in Lesson 6.1, a stand-in file in the folder Milestone 2 creates, then npm's own list of what a package would hold:

mkdir -p src/Holds
printf '<?php\n' > src/Holds/HoldsTable.php
npm pack --dry-run 2>&1 | grep -c ' src/'
npm pack --dry-run 2>&1 | grep -c ' src/Holds/'
rm -r src/Holds
24
0

24 PHP files from src/, none from src/Holds/: package.json's "files" list names the folders that existed in Lesson 8.3. Nothing warns you; the live site would answer "There has been a critical error". The rule: a new top-level folder in src/ goes into "files" in the same commit, and Milestone 8 counts the new folder's files in the ZIP before upload.

Why does the reference solution keep holds in a custom table rather than a post type?

B) A hold is one customer, one book, a status and a date: typed columns with indexes answer "this customer's holds" and "what is waiting" directly, and old rows can be deleted cleanly

Glossary

TermMeaning
holdOne customer, one book, a status (waiting, collected, cancelled) and a last day of pickup; a row in wp_pagesco_holds
pickup_byThe last day of pickup, a date in the site's time zone: today + hold_days when placed
expiredA waiting hold whose pickup_by is before today: computed by Holds::status(), never stored
maybe_upgrade()Runs on init; installs the table when the version option is older than the code (the update path)
doorAnything that receives a request: a form handler, a REST route, a block; it checks who is asking and passes the question to the rules
IDORInsecure direct object reference: acting on someone else's record by sending its ID; stopped by ownership in the query
409 ConflictThe request is fine, the current state says no (limit, duplicate, sold out)
pagesco_books_hold_placedThe plugin's own action after a hold is saved; HoldMail listens to it
baselineThe numbers before a change (Milestone 1's query counts), compared after (Milestone 7)

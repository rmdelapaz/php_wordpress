Session 8: Part 1 Project and Assessment

Answers and reasoning for Session 8: the warm-up, the Part 1 self-check, the predict items, the review lab and handout, and the project's and the assessment's self-check outputs (rubrics and scoring in final-assessment.html).

Session 8 12 self-check items Confidential

Warm-up

  1. W1 Hooks (Lesson 2.3), themes (Modules 3 and 4), plugins (Module 5), blocks (Module 6), APIs (Module 7). Part 1 covered the first two.
  2. W2 Block: templates/*.html and parts/*.html, block markup. Classic: *.php in the theme root (index.php, singular.php...), PHP with template tags.
  3. W3 Not is_admin(); $query->is_main_query(); $query->is_home() (the query's method, not the global function).
  4. W4 esc_html() text, esc_attr() attributes, esc_url() href/src, wp_kses_post() HTML with safe tags (and the _e / __ variants for translated text).
  5. W5 Each learner's own number: the status round (see the studio triage).

Self-check: Part 1

Q1
The site shows the latest posts on its front page. The active block theme has templates/front-page.html, templates/home.html and templates/index.html. Which template draws /?
A) home.html, because the front page lists posts
B) index.html, the fallback for everything
C) front-page.html
D) page.html, because the front page is a page
Why: front-page is checked first for the front page, whatever it shows (Lesson 3.1's hierarchy). home draws the posts list only when it is NOT the front page. That is why Fernhill's news list lives in front-page.html.
A is wrong: home.html would win only if front-page.html were missing (or the posts list were on another page).
B is wrong: index.html is the last resort, used when nothing more specific exists.
D is wrong: With show_on_front set to posts there is no front PAGE at all.
Q2
What does this print?
wp eval 'add_filter( "the_title", function ( $t ) { return "A" . $t; }, 20 );
add_filter( "the_title", function ( $t ) { return "B" . $t; } );
echo apply_filters( "the_title", "x" ), "\n";'
ABx
Why: Callbacks run by priority, lowest first: the default 10 ("B") before 20 ("A"). Each filter receives the value the previous one returned, so A wraps the result of B (Lesson 2.3).
Q3
Which file must a block theme have, besides style.css, for WordPress to accept it?
A) functions.php
B) templates/index.html
C) theme.json
D) index.php
Why: A block theme needs style.css (its name) and templates/index.html (the last resort of the hierarchy); without the template WordPress reports "Template is missing" (Lesson 3.1, Mistake 1). theme.json is strongly recommended, functions.php optional.
A is wrong: Optional: many block themes have none.
C is wrong: Without theme.json the theme works on core's defaults.
D is wrong: That is the CLASSIC theme's required template.
Q4
pagesco-tt5-child is a child theme of Twenty Twenty-Five. What does the middle command print?
wp theme activate pagesco-tt5-child
wp eval 'echo get_template(), " ", get_stylesheet(), "\n";'
wp theme activate pagesco
twentytwentyfive pagesco-tt5-child
Why: get_template() is the PARENT's folder (the Template header), get_stylesheet() the active theme's own folder: the child (Lesson 3.4). Without a child theme both print the same name.
Q5
A learner changed Fernhill's footer in the Site Editor yesterday. Today every edit to parts/footer.html is ignored. Why, and what fixes it?
A) The database copy of the part (a wp_template_part post) wins over the file: copy what you want into the file, then reset or delete the copy
B) OPcache: restart the containers
C) The footer area in theme.json is wrong: change it to "footer-1"
D) Template parts are cached for 30 minutes: wait
Why: A Site Editor save creates a database copy (source custom) that WordPress prefers to the theme's file. Export or copy the markup into the file, then Reset in the Site Editor or delete the post (Lesson 3.2, Mistake 3; the project's rule R8).
B is wrong: OPcache caches PHP, and the course setup revalidates on every request; .html parts are not PHP.
C is wrong: The area only says where the part belongs in the editor; it does not decide which copy wins.
D is wrong: The 30-minute cache is for PATTERN files, and WP_DEVELOPMENT_MODE theme switches it off on the course site.
Q6
This callback forgets the main-query guard. What does the last line print on the course site (four published posts)?
wp eval 'add_action( "pre_get_posts", function ( $q ) {
	if ( is_admin() ) { return; }
	if ( $q->is_home() ) { $q->set( "posts_per_page", 3 ); }
} );
$q = new WP_Query( array( "posts_per_page" => 5 ) );
echo $q->post_count, "\n";'
A) 4
B) 5
C) 0
D) 3
Why: A WP_Query without query variables counts as the blog home (is_home() is true), so the unguarded callback changes YOUR query too: 3 posts instead of the four you asked for. $query->is_main_query() is the guard (Lesson 4.2, Mistake 3; the project's R6).
A is wrong: That is what the query returns WITH the guard (all four posts, fewer than five).
B is wrong: There are only four published posts.
C is wrong: Nothing is excluded; the query only gets a smaller page size.
Q7
What does this print? (Three posts are in News.)
wp eval '$q = new WP_Query( array( "category_name" => "news", "posts_per_page" => 2 ) );
echo $q->post_count, " ", $q->found_posts, "\n";'
A) 2 2
B) 2 3
C) 3 3
D) 3 2
Why: post_count is how many posts this page of results holds (posts_per_page 2), found_posts how many match in all (3). max_num_pages would be 2: that is what pagination needs (Lesson 4.2).
A is wrong: found_posts ignores the page size.
C is wrong: post_count respects the page size.
D is wrong: The two are swapped.
Q8
A pattern prints a link to an address that comes from home_url(). Which function goes around it inside href="..."?
A) esc_html()
B) esc_attr()
C) esc_url()
D) wp_kses_post()
Why: esc_url() checks the protocol and encodes the characters a URL may not carry; it is the escaping for href and src, even for an address WordPress built (Lessons 1.3 and 3.3). Escape late, at the echo.
A is wrong: For text between tags, not for URLs.
B is wrong: For other attribute values; it does not check the protocol (javascript: would pass).
D is wrong: For HTML that may keep safe tags, such as post content.
Q9
What does this print? (Post 17 is "Book club: Dune".)
wp eval 'global $post; $post = get_post( 17 ); setup_postdata( $post );
echo "<h2>" . the_title() . "</h2>\n";'
Book club: Dune<h2></h2>
Why: the_title() ECHOES and returns nothing, so the title is printed while PHP builds the string, before the concatenated <h2></h2>. Use the_title( "<h2>", "</h2>" ) or get_the_title() with esc_html() (Lesson 4.1, Mistake 1).
Q10
Fernhill must load assets/css/fernhill.css on the front end. On which hook does wp_enqueue_style() belong?
A) init
B) after_setup_theme
C) wp_head
D) wp_enqueue_scripts
Why: wp_enqueue_scripts is the hook for front-end styles and scripts (admin_enqueue_scripts and login_enqueue_scripts for those screens). Called anywhere earlier, WordPress says the function was called incorrectly; wp_head is too late for the queue to be printed in order (Lesson 4.3, Mistake 1).
A is wrong: Too early: "wp_enqueue_style was called incorrectly".
B is wrong: For theme supports and menus, not assets.
C is wrong: wp_head is where the queue is PRINTED (at priority 8); enqueueing on it is too late or out of order.
Q11
A theme has styles/autumn.json with a title and a palette, and no blockTypes. What is it?
A) A style variation the site owner can switch on for the whole site
B) A section style for Group blocks
C) A child theme of the theme
D) A pattern
Why: A JSON file in styles/ without blockTypes is a style variation: it overlays the theme's theme.json for the whole site when chosen in Styles (it saves as user global styles). With blockTypes it is a section (block style) variation (Lesson 3.3).
B is wrong: Section styles name the block types they apply to.
C is wrong: A child theme is its own folder with Template: in style.css (Lesson 3.4).
D is wrong: Patterns are PHP (or HTML) files in patterns/ with a Slug header.
Q12
pagesco's theme.json has the palette color oxblood, #7a2e2e. What does this print?
wp eval 'echo wp_get_global_stylesheet( array( "variables" ) ), "\n";' \
	| grep -o -- '--wp--preset--color--oxblood: [^;]*'
--wp--preset--color--oxblood: #7a2e2e
Why: Every preset becomes a CSS custom property, --wp--preset--color--<slug>; var:preset|color|oxblood in theme.json and the has-oxblood-* classes point at it (Lesson 3.2). That is why slugs name ROLES: a variation changes the value, never the name.

Predict, Then Run

P1
Predict the output, then run it.
wp eval 'echo wp_get_theme( "pagesco-tt5-child" )->get( "Template" ), "\n";'
twentytwentyfive
Why: The child's style.css names its parent FOLDER in the Template header (Lesson 3.4); WP_Theme reads it as Template.
P2
Predict the output, then run it.
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/page/2/
404
Why: pagesco shows ten posts per page (the Reading setting) and the site has four posts, so there is no page 2: WordPress answers 404. On Fernhill (three per page) or Brightwater (two) it exists.
P3
Predict the output, then run it.
wp eval '$q = new WP_Query( array( "post_type" => "page", "orderby" => "title", "order" => "ASC" ) );
echo implode( ", ", wp_list_pluck( $q->posts, "post_title" ) ), "\n";'
About Us, Contact, Events, Sample Page
Why: A WP_Query of pages with no post_status finds only published pages: the Privacy Policy is a draft. orderby title sorts alphabetically; posts_per_page defaults to the Reading setting (ten).
P4
Predict the output, then run it.
wp eval 'echo esc_html( "<b>Fernhill</b> & friends" ), "\n";'
&lt;b&gt;Fernhill&lt;/b&gt; &amp; friends
Why: esc_html() turns <, > and & into entities. The browser shows the text exactly as written; that is the point, even for your own strings (a translation might contain anything).

Exit Ticket

  1. pre_get_posts: a callback in functions.php, guarded (not admin, $query->is_main_query(), $query->is_home()), sets posts_per_page to 3. The Query Loop inherits the main query, so pagination and /page/2/ work; a second query in the template would not page, and the main query would still run.
  2. esc_html_e(): it makes the string translatable with the theme's text domain and escapes it as it prints; a translation is data the theme did not write. It is also the habit that keeps a later dynamic value safe.
  3. Own answer: use the "review" answers to choose Session 9's Part 1 refresher topics.

Common Wrong Answers and What They Reveal

  • Q1 A (home.html). Mixes up "shows posts" with "is the posts page". front-page wins for the front page whatever it shows.
  • Q2 BAx. Assumes the order of add_filter() calls is the order of running; priority decides, then the order of adding.
  • Q5 B or D. Blames caching. Ask: where does the Site Editor save? (The database: Lesson 3.2.)
  • Q6 A. Trusts the code to do what it says. The guard is the whole point; that is also why the self-check cannot catch the missing guard and the rubric reads the code.
  • Q9 <h2>Book club: Dune</h2>. the_ functions echo; the get_ functions return (Lesson 4.1).
  • Q10 C (wp_head). Remembers that styles print in the head. Enqueue on wp_enqueue_scripts; WordPress prints the queue in wp_head.

The per-URL check (Lesson 3.2), for Fernhill

From the project folder, in the WP-CLI container shell (docker compose run --rm wpcli sh), with fernhill active. Every line should show one header, one main and one footer; /no-such-path/ answers 404.

for url in / /page/2/ /hello-world/ /about/ /category/news/ "/?s=garden" /no-such-path/; do
	page=$(curl -s -w '\n%{http_code}' "http://localhost:8080$url")
	echo "$url  $(echo "$page" | tail -n 1)  header:$(echo "$page" | grep -c '<header class="wp-block-template-part"')  main:$(echo "$page" | grep -c '<main ')  footer:$(echo "$page" | grep -c '<footer class="wp-block-template-part"')  h1: $(echo "$page" | grep -o '<h1[^>]*>.*</h1>' | head -n 1 | sed 's/<[^>]*>//g')"
done

Part 1 Assessment: How It Runs

  • 60 minutes, alone, open book (lesson pages, notes, this workbook, your own course code). No other people, no AI assistants, no code from the web.
  • A new client's classic theme to finish: five tasks, three of them from the client's bug reports. Your instructor hands out the files at 1:25; the BRIEF lists the tasks and the rubric.
  • A self-check like the project's: run it as often as you like. It is a help, not your score.
  • Hand-in at 2:35: a zip of the theme folder with the self-check's output in it. Unfinished? One honest line at the top of functions.php.

Q5
A learner changed Fernhill's footer in the Site Editor yesterday. Today every edit to parts/footer.html is ignored. Why, and what fixes it?

D) Template parts are cached for 30 minutes: wait
Q6

	if ( $q->is_home() ) { $q->set( "posts_per_page", 3 ); }
} );
$q = new WP_Query( array( "posts_per_page" => 5 ) );
echo $q->post_count, "\n";'

B) 5
C) 0
D) 3

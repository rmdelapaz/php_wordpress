Start Here · Diagnostic

Not graded. Each reason also says where the skill comes back in this course. PHP's own answers to D1, D2 and D6 are in the diagnostic lab's output below.

D1
What does this PHP print?
$books = ['Dune' => 14.99, '1984' => 9.99, 'Emma' => 7.99];
echo count($books), ' ', array_key_first($books);
A) 3 Dune
B) 3 Emma
C) 2 Dune
D) 3 14.99
Why: count() counts the three entries; array_key_first() returns the first KEY, 'Dune'. WordPress passes arrays of arguments almost everywhere (Lesson 1.3). Skill: PHP arrays. Where it comes back: PHP Foundations Module 3; every WordPress function that takes an array of arguments (Lesson 1.3).
D2
A visitor typed <b>Maya</b> into a form. What reaches the browser from this line?
echo 'Hello, ', htmlspecialchars('<b>Maya</b>');
A) Hello, Maya (in bold)
B) Hello, &lt;b&gt;Maya&lt;/b&gt;
C) Hello, <b>Maya</b>
D) Hello, (the tags are removed)
Why: htmlspecialchars() turns < and > into entities, so the browser shows the tags as text instead of running them. WordPress's esc_html() does the same job. Skill: escaping output. Where it comes back: PHP Foundations Lesson 4.2; esc_html() and friends in Lessons 1.3 and 5.3.
D3
Which query lists the titles of the books under $10, cheapest first?
A) SELECT title FROM books ORDER BY price < 10;
B) SELECT title WHERE price < 10 FROM books;
C) SELECT title FROM books WHERE price < 10 ORDER BY price;
D) SELECT * FROM books HAVING price < 10 DESC;
Why: FROM names the table, WHERE keeps the rows that match, ORDER BY sorts (ascending unless you say DESC). Lesson 2.2 runs queries like this on WordPress's own tables. Skill: SQL. Where it comes back: MySQL Foundations; WordPress's tables in Lesson 2.2 and $wpdb in Lesson 5.5.
D4
Your terminal is in your home folder; the course project is ~/pagesco-dev. Which starts the site?
A) docker compose up -d
B) docker compose up -d pagesco-dev
C) sudo docker compose up -d
D) cd pagesco-dev, then docker compose up -d
Why: Docker Compose reads the compose.yaml of the folder you are in (or a folder above it). From your home folder there is none, so every course command starts with being in the project folder. Skill: folders and the terminal. Where it comes back: Lesson 1.2 (every docker compose command) and every lab.
D5
A browser asks a server for a page that does not exist. Which status code should come back?
A) 404 Not Found
B) 200 OK
C) 301 Moved Permanently
D) 500 Internal Server Error
Why: 404 means "no such page". 200 is success, 301 a redirect, 500 a crash on the server. WordPress answers 404 when the main query finds nothing, and picks the theme's 404 template. Skill: HTTP status codes. Where it comes back: PHP Foundations Lesson 1.1; rewrite rules and 404 templates in Lessons 2.2 and 3.1.
D6
What does this PHP print?
function shout($t) { return strtoupper($t) . '!'; }
echo implode(' ', array_map('shout', ['Dune', 'Emma']));
A) Dune! Emma!
B) DUNE! EMMA!
C) shout shout
D) An error: a function name cannot be a string
Why: array_map() calls the function whose NAME you pass, once per item. That is a callback. In WordPress you hand function names to add_action() and add_filter(), and core calls them at the right moment (Lesson 2.3). Skill: callbacks. Where it comes back: PHP Foundations functions; hooks in Lesson 2.3 work exactly like this.

1.1 · WordPress for Developers: self-check

Q1
Pages & Co. updates WordPress from 7.1.3 to 7.1.4. Which of these folders does the update REPLACE?
A) wp-content/plugins/pagesco-books/
B) wp-content/themes/pagesco/
C) wp-includes/
D) wp-content/uploads/
Why: wp-includes/, wp-admin/ and the wp-*.php files in the root are core: every update overwrites them, which is why a change there disappears (Lesson 1.1, "Never edit core files"). wp-content/ belongs to the site.
A is wrong: Your own plugin is never touched by a core update.
B is wrong: Your own theme is never touched by a core update (a directory theme such as Twenty Twenty-Five is replaced by its own updates).
D is wrong: Uploads are the site's media; no update touches them.
Q2
From the WP-CLI container, on a fresh course site: what does this print?
curl -s http://localhost:8080/ | grep -o '<title>.*</title>'
<title>Pages &amp; Co.</title>
Why: The home page shows the latest posts, so WordPress titles it with the site title alone; a single post adds its own title and the separator (Hello world! &#8211; Pages &amp; Co.). The title comes from the database, stored escaped: &amp; is the ampersand.
Q3
A front-end request travels through core. Which of these happens FIRST?
A) template-loader.php picks a template from the theme
B) wp() parses the URL and runs the main query
C) the init action fires, after plugins and the theme are loaded
D) the theme's template prints the HTML
Why: wp-settings.php loads core, must-use plugins, plugins and the theme and fires init; only then does wp() work out the request and run the main query, and template-loader.php draws the page. Load, then query, then template.
A is wrong: Choosing a template needs the main query's result, so it comes last but one.
B is wrong: wp() runs after wp-settings.php has finished, init included.
D is wrong: That is the very end of the trip.
Q4
wp core verify-checksums prints Warning: File doesn't verify against checksum: wp-includes/functions.php. What happened, and what do you do?
A) The download was damaged: reinstall WordPress from scratch
B) WordPress 7.1 changed functions.php: nothing to do
C) A plugin is outdated: update all plugins
D) Someone edited a core file: restore it and put the change in a plugin or theme, on a hook
Why: WordPress knows what every core file must contain. A file that fails the check was changed after installation, here by a "quick fix". The next update would silently undo it; security scanners flag it as a possible hack.
A is wrong: A reinstall would also wipe the evidence of what was changed; restore the one file.
B is wrong: Core files match their checksums in every release; a mismatch is never normal.
C is wrong: Plugins live in wp-content/ and are not part of the core checksums.
Q5
With pretty permalinks, which file does the web server hand /books/dune/, /about/ and almost every other front-end URL?
A) wp-config.php
B) index.php in the WordPress root
C) wp-settings.php
D) A file named after the URL, such as books/dune.php
Why: Any request that does not match a real file goes to index.php; from there WordPress loads itself, matches the URL against its rewrite rules and runs the main query. That replaces the one-file-per-page router of PHP Foundations.
A is wrong: wp-config.php only holds settings; it is loaded on the way, by wp-load.php.
C is wrong: wp-settings.php is loaded later in the chain, never requested directly.
D is wrong: No such files exist: the address is matched to content in the database.
Q6
In PHP Foundations you printed a visitor's input with htmlspecialchars(). Which WordPress function do you use instead when printing text into HTML?
esc_html()
Why: It is Lesson 1.1's bridge table: esc_html() for text, esc_attr() inside attributes, esc_url() for links, wp_kses_post() for HTML that may keep safe tags. Lesson 1.3 practices the family; the fixed debug demo of Lesson 1.2 already used it.

1.1 · WordPress for Developers: predict, then run

P1
Predict the output, then run it.
curl -s http://localhost:8080/sample-page/ | grep -o '<title>.*</title>'
<title>Sample Page &#8211; Pages &amp; Co.</title>
Why: A single page is titled with its own title, the separator (an en dash written as &#8211;) and the site title, which is stored escaped (&amp;). Compare self-check Q2: the home page has the site title alone.
P2
Predict the output, then run it.
wp eval 'echo did_action( "init" ), " ", did_action( "template_redirect" ), "\n";'
1 0
Why: WP-CLI loads all of WordPress, so init has fired once (did_action() counts). But no front-end request was made: wp() and the template loader never ran, so template_redirect fired 0 times. That is the line between loading and drawing a page (Lesson 1.1).

1.2 · Your Local Development Environment: self-check

Q7
You want to throw your site away and start over with a blank WordPress. Which command deletes the database?
A) docker compose stop
B) docker compose down
C) docker compose down -v
D) docker compose restart
Why: The database lives in the db_data volume, and only -v ("and the volumes") deletes it. Afterwards delete wordpress/ too and run the install steps again (Lesson 1.2, Everyday Commands).
A is wrong: stop pauses the containers; everything stays.
B is wrong: down removes the containers but keeps the volume: Exercise 1 proves the tagline survives it.
D is wrong: restart stops and starts the same containers.
Q8
What does this print on the course site, exactly?
wp option get blogname
Pages &amp; Co.
Why: WordPress stores the site title HTML-escaped (--title="Pages & Co." is saved with &amp;). Browsers show a plain &, but code that reads the option gets the escaped form: it matters when you compare strings or put the title in an email.
Q9
wp-content/debug.log says PHP Warning: Undefined variable $pagesco_name in /var/www/html/wp-content/mu-plugins/pagesco-debug-demo.php on line 8. Where is that file on YOUR computer?
A) /var/www/html/wp-content/... on your computer's disk
B) wordpress/wp-content/mu-plugins/pagesco-debug-demo.php in your project folder
C) Inside the db container
D) Nowhere: it only exists while the container runs
Why: ./wordpress:/var/www/html in compose.yaml is a bind mount: your wordpress/ folder IS the WordPress root inside the containers. Every path in an error message translates by swapping /var/www/html for your wordpress folder.
A is wrong: /var/www/html exists only inside the containers.
C is wrong: The database container holds the database, not WordPress's files.
D is wrong: A bind-mounted folder is an ordinary folder on your disk; it outlives every container.
Q10
In a new terminal you type wp core version and get no configuration file provided: not found. What is wrong?
A) You are not in the project folder: Docker Compose found no compose.yaml here or above
B) WordPress is not installed yet
C) Docker is not running
D) The wp shortcut is missing
Why: Docker Compose looks for compose.yaml in the current folder and every folder above it. cd ~/pagesco-dev (or any folder inside it) and try again (Lesson 1.2, Common Mistakes 5).
B is wrong: An uninstalled site gives a WP-CLI error about the database tables, not this.
C is wrong: With Docker stopped the message is about the Docker daemon.
D is wrong: Without the shortcut the shell says wp: command not found.
Q11
Most Docker tutorials map 8080:80. Why does the course project use 8080:8080 (Apache listens on 8080 inside the container too)?
A) Port 80 is reserved for MySQL
B) Docker Desktop cannot publish port 80
C) It makes the site faster
D) WordPress calls its own address, http://localhost:8080, from inside the container (WP-Cron, Site Health), and that must reach Apache
Why: With 8080:80 the site works in your browser, but WordPress's requests to itself at http://localhost:8080 reach nothing inside the container, and wp cron test fails. config/apache-8080.conf adds the second port.
A is wrong: MySQL uses 3306, and only on the private network.
B is wrong: It can; the choice is about WordPress's own requests.
C is wrong: Speed is the same; correctness is the point.
Q12
What does this print on the course site? Name one thing that value changes.
wp eval 'echo wp_get_environment_type(), "\n";'
local: for example, Mailpit's mu-plugin only reroutes email when the environment is local; application passwords work over plain HTTP; WordPress 7.1 turns pings off
Why: WP_ENVIRONMENT_TYPE comes from WORDPRESS_CONFIG_EXTRA in compose.yaml. Code (yours included) can behave differently on local, staging and production; Lesson 8.4 sets production.

1.2 · Your Local Development Environment: predict, then run

P3
Predict the output, then run it.
wp db query "SELECT option_value FROM wp_options WHERE option_name = 'blogname'"
option_value
Pages &amp; Co.
Why: wp db query prints the column name and then the value, tab-separated, without a table (in a terminal or not). The value is the escaped title as it sits in the database: the escaping happened when the option was SAVED.
P4
Predict the output, then run it.
wp eval 'var_dump( wp_mail( "", "No address", "Hello" ) );'
bool(false)
Why: No message at all: wp_mail() returns false and WordPress keeps the reason for the wp_mail_failed action (Lesson 1.2, Common Mistakes 3 shows how to listen to it). A silent false is the hardest kind of bug: check return values.

The Lesson Pages' Own Quick Quizzes

Lesson 1.1 · WordPress for Developers
  1. B In the pagesco-books plugin in wp-content/plugins/: It is a feature of the store's data, so it belongs in the store's own plugin, in wp-content/plugins/, where it survives core updates and theme changes.
  2. C Ask which plan they are on, because only some plans allow your own plugins: Whether you can install your own plugins on WordPress.com depends on the plan. Find out first; the answer may be an upgrade or a move to another host.
  3. A index.php, wp-blog-header.php, wp-config.php, wp-settings.php, template-loader.php: index.php hands over to wp-blog-header.php, whose wp-load.php finds wp-config.php, which ends by loading wp-settings.php; only then do wp() and the template loader run.
  4. C Replace the call with wp_get_current_user() and check how old the tutorial is: The message names the replacement. Switch to wp_get_current_user(), and treat the tutorial with care: it was written for a much older WordPress.
  5. B WordPress core runs the main program and calls your code through hooks: Core runs the program and calls your functions at the moments you registered them for with hooks. This inversion of control is what Lesson 2.3 builds on.
Lesson 1.2 · Your Local Development Environment
  1. C In a new wpcli container that is removed when the command ends: The alias runs docker compose run --rm wpcli wp: a one-off wpcli container that shares the WordPress files and the network, runs the command in /var/www/html and is removed afterwards.
  2. A Run the containers as your user (.env plus compose.override.yaml) after giving the existing files to your user: Running the wordpress and wpcli containers as your own user means you, Apache and WP-CLI all create files as the same user. Repair the existing files with a root chown in a container first.
  3. B Both are still there: the database is in a volume and the files are in wordpress/: The posts are in the db_data volume and the theme files in the wordpress folder on your disk; down only removes containers. Only down -v deletes the volume.
  4. B mailpit-smtp.php is not in wp-content/mu-plugins/, so the sender wordpress@localhost is rejected: Without mailpit-smtp.php in mu-plugins, WordPress sends from wordpress@localhost, PHPMailer rejects that address, and wp_mail returns false. Copy the plugin back.
  5. C npx @wordpress/env start, with phpVersion 8.5 in .wp-env.json: The official package is @wordpress/env, run with npx and a .wp-env.json that sets phpVersion 8.5. The unscoped wp-env package is someone else's code.

Opening: Reading the Room

There is no retrieval warm-up in Session 1. The opening's two checks have their answers above: the environment check output (what READY looks like) and the diagnostic D1 to D6. Learners who end the clinic still NOT READY leave with a numbered plan in their workbook's Start Here box.

Exit Ticket

  1. Your code: in wp-content/: your own theme, your own plugin, or a must-use plugin. Core (wp-admin/, wp-includes/, the root wp-*.php) is replaced by every update, so a change there disappears, and wp core verify-checksums (and every security scanner) reports it.
  2. Four services: wordpress (Apache and PHP 8.5 with WordPress, the site on port 8080), db (MySQL 9.7, the data in the db_data volume), wpcli (WP-CLI, started for each command and removed), mailpit (catches every email, inbox on 8025).
  3. A critical error: the end of wordpress/wp-content/debug.log: tail -n 20 wordpress/wp-content/debug.log from the project folder (or tail -f while reloading the page; Lesson 1.2's Exercise 3 makes it wplog).

Common Wrong Answers and What They Reveal

  • Q1 B ("the theme folder"). Mixes up WordPress updates and theme updates. Fine to discuss: Twenty Twenty-Five IS replaced, by its own updates; pagesco is not, by anything.
  • Q2 with an en dash. Expects every title to have the separator. The home page lists posts and is titled with the site name alone; ask them to curl /hello-world/ and compare.
  • Q3 B ("wp() first"). Thinks WordPress works out the request before loading plugins. Redraw the boxes: the plugins must be loaded first, or nobody could register a post type before the query runs.
  • Q5 D ("a file per URL"). The PHP Foundations model. Show ls of the root again: there is no about.php.
  • Q9 A ("/var/www/html on my disk"). Has not connected the bind mount to the folder they edit. Open wordpress/ in VS Code next to an error message.
  • Q11 B or C. Guessing. Run wp cron test and explain what it requested.
  • Q12 with development. Remembers the four environment types but not this site's. The value comes from compose.yaml: open it.

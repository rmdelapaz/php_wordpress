Warm-up · Session 2 Revisited

  1. W1 Which escaping function goes around a URL in an href attribute? Answer: esc_url() (text between tags: esc_html(), other attribute values: esc_attr()).
  2. W2 Name the four shapes a WordPress callback can take. Which one is hard for anyone else to unhook? Answer: A function name, a closure, array( $object, 'method' ), a static method ('Class::method' or array( 'Class', 'method' )). The closure: nobody else has a handle on it (Lesson 2.3 comes back to this).
  3. W3 A page and a post: which table holds each, and which column tells them apart? Answer: Both are rows in wp_posts; post_type is page or post (Lesson 2.1's filing cabinet).
  4. W4 Code must decide whether the current user may publish pages. What does it check, and why not the role? Answer: current_user_can( 'publish_pages' ): a capability. Roles are bundles that sites change; capabilities are what WordPress checks.
  5. W5 What does wp_parse_args( $args, $defaults ) return? Answer: One array: the defaults, overridden by whatever the caller passed in $args.

2.2 · Core Architecture & the Database: self-check

Q1
A tutorial says to add define( 'DISALLOW_FILE_EDIT', true ); to wp-config.php. You paste it as the very last line of the file, after require_once ABSPATH . 'wp-settings.php';. What happens?
A) It works: wp-config.php is read on every request, so the position does not matter
B) PHP stops with a parse error
C) It is defined too late: wp-settings.php has already loaded WordPress, so the file editors stay
D) WordPress moves the line above the "stop editing" comment the next time it saves the file
Why: The require_once on line 139 hands over to the loader, and WordPress reads its settings while it loads. Anything after it is defined when the decisions have been made. That is what "That's all, stop editing!" means: custom lines go between the two comments above it.
A is wrong: The position is the whole point: wp-config.php runs top to bottom, and the last line loads WordPress.
B is wrong: It is valid PHP; it simply comes too late.
D is wrong: WordPress never rewrites wp-config.php by itself.
Q2
What does this print on the course site, and what is that value?
wp config get DB_HOST
db: the name of the database service in compose.yaml (on a typical host it is localhost)
Why: wp-config.php reads it with getenv_docker('WORDPRESS_DB_HOST', ...) from the container's environment, which compose.yaml sets. Containers on one Compose network reach each other by service name. wp config get reads wp-config.php for you, so a script never needs the password.
Q3
In which order does wp-settings.php load these on every request?
A) The theme's functions.php, active plugins, must-use plugins, pluggable.php
B) Must-use plugins, active plugins, pluggable.php, the theme's functions.php
C) pluggable.php, must-use plugins, the theme's functions.php, active plugins
D) Active plugins, must-use plugins, the theme's functions.php, pluggable.php
Why: Must-use plugins at line 506, active plugins at 582, pluggable.php at 612, the theme at 741 (WordPress 7.1.3). Pluggable functions come after the plugins so a plugin can replace one by defining it first; that is also why calling one at the top of a plugin file fails.
A is wrong: That is the order backwards: the theme comes last of the four.
C is wrong: pluggable.php waits for the plugins, on purpose.
D is wrong: Must-use plugins always come before normal plugins.
Q4
Devon's first name is stored once in wp_usermeta. What does this print?
wp eval 'var_dump( get_user_meta( 3, "first_name" ) );'
array(1) {
  [0]=>
  string(5) "Devon"
}
Why: Without the third argument (true) the metadata API returns EVERY value of the key, as an array, because a key may be stored several times. With true it returns the single value, the string "Devon". Lesson 2.2, Common Mistakes 4.
Q5
Someone runs UPDATE wp_usermeta SET meta_value = REPLACE(meta_value, 'author', 'editor') on Devon's a:1:{s:6:"author";b:1;}. What happens?
A) The value breaks: unserialize() fails and Devon loses every role
B) It works, but only because both words have 6 characters: the s:6 length still matches. Change roles through WordPress anyway
C) MySQL refuses: the column holds serialized PHP
D) WordPress recomputes the lengths when it reads the value
Why: Serialized values store each string's length. Same length, still valid; "Springfield" to "Portland" was not (Lesson 2.2, Common Mistakes 1). It is still the wrong tool: it skips WordPress's caches and hooks, and the next REPLACE may not be so lucky. wp user set-role devon editor or $user->set_role() is the API.
A is wrong: That happens when the length changes; here it does not.
C is wrong: To MySQL it is just LONGTEXT.
D is wrong: WordPress trusts the stored lengths; a mismatch makes unserialize() fail.
Q6
An option's autoload column says auto-off. What does that mean?
A) The code that saved it passed false
B) It is loaded on every request
C) The option is broken and will be deleted
D) Nobody chose, and WordPress decided not to autoload it, usually because the value is large (over 150,000 bytes)
Why: on/off = the code said true/false; auto = nobody said, WordPress's default (loaded today); auto-on/auto-off = WordPress decided by itself. Lesson 2.2's autoload demo: a 200,000-byte option became auto-off. Rule for your plugins: pass true for small settings you read on every page, false for anything big or rare.
A is wrong: Passing false gives off.
B is wrong: auto-off is NOT in the list wp_autoload_values_to_autoload() returns.
C is wrong: Nothing about it is broken; it is read on demand, with one query.

wp eval 'var_dump( get_option( "pagesco_no_such_option" ), get_option( "pagesco_no_such_option", "none" ) );'
bool(false)
string(4) "none"
Why: An option that does not exist returns false, or the default you pass as the second argument. Both reads cost a query (WordPress cannot know an option is missing without asking; the lesson's options-cost.php measured it).
P2

wp db query "SELECT option_value FROM wp_options WHERE option_name = 'active_plugins'"
option_value
a:0:{}
Why: a:0:{} is a serialized empty array: no active plugins. wp db query prints the column name, then the raw value; get_option( 'active_plugins' ) would return array().

2.3 · The Hooks System: self-check

Q7
What does this print when run with wp eval-file?
<?php
add_filter( 'pagesco_q7', fn( $text ) => $text . 'b', 20 );
add_filter( 'pagesco_q7', fn( $text ) => strtoupper( $text ) );
add_filter( 'pagesco_q7', fn( $text ) => $text . 'a', 5 );

echo apply_filters( 'pagesco_q7', 'x' ), "\n";
XAb
Why: Priority 5 runs first (xa), then the callback at the default 10 (XA), then 20 (XAb). The order in which the lines were written does not matter across priorities; only ties at the same priority keep their added order.
Q8
A members page must send visitors who are not logged in to the login screen. On which action do you call wp_safe_redirect() and exit?
A) plugins_loaded
B) wp_footer
C) template_redirect
D) shutdown
Why: template_redirect fires when WordPress knows which page was asked for (conditional tags work) and before any HTML is printed, so headers can still be sent. Lesson 2.3's table of actions.
A is wrong: Too early: the request has not been parsed, so you cannot know which page it is.
B is wrong: Too late: the page has been printed, headers are gone.
D is wrong: Far too late: the response is finished.
Q9
A theme adds add_action( 'wp_head', 'pagesco_theme_banner' ) inside its after_setup_theme callback. Your plugin calls remove_action( 'wp_head', 'pagesco_theme_banner' ) at the top of its main file, and the banner stays. Why?
A) The plugin ran before the theme added the hook, so there was nothing to remove: remove it on init
B) remove_action() only works on core's hooks
C) The priority is wrong: it must be 1
D) Plugins cannot change what a theme does
Why: Removal rule 2 of Lesson 2.3: remove after it was added. Plugins load at line 582 of wp-settings.php, the theme at 741 and its after_setup_theme callbacks after that; init (line 779) comes later. remove_action() returned false, silently.
B is wrong: It works on any hook, if the hook, callback and priority match and the hook exists already.
C is wrong: The theme added it at the default 10, so 10 (the default) is right.
D is wrong: They can, with hooks; that is the point of them.
Q10
What does this print, and what does the value mean?
wp eval 'var_dump( has_filter( "the_content", "do_blocks" ) );'
int(9): do_blocks is attached to the_content at priority 9, before wpautop at 10
Why: has_filter() with a callback returns its priority, or false when it is not attached. do_blocks turns block markup into HTML before the paragraph filter runs (Lesson 2.1 named it; Exercise 3 of 2.3 lists them all). Test the result with false !== has_filter( ... ): 0 is a valid priority.
Q11
After a new the_title filter, posts have no titles and the only message is Deprecated: str_replace(): Passing null to parameter #3 ... in .../wp-includes/formatting.php on line 5777. What is the likely bug?
A) Your callback does not return the title, so the next callback (core's, at priority 11) received null
B) A bug in WordPress 7.1's formatting.php: update core
C) PHP 8.5 deprecated str_replace()
D) The filter needs 2 accepted arguments
Why: A filter must return the value. Null went down the chain to capital_P_dangit(), which handed it to str_replace(), so the message points into core. When a message blames a core file, look at what YOUR code handed to it (Lesson 2.3, Common Mistakes 1).
B is wrong: Core is fine; it received a null it did not expect.
C is wrong: str_replace() is fine; passing null to it is deprecated.
D is wrong: That mistake is a fatal ArgumentCountError, not a Deprecated notice.
Q12
Your plugin prints a gift-card form. Other developers should be able to print a line of their own just BEFORE the form. What do you add right before you print it?
A) apply_filters( 'pagesco_before_gift_form', '' );
B) add_action( 'pagesco_before_gift_form', 'pagesco_print_form' );
C) do_action( 'before_gift_form' );
D) do_action( 'pagesco_before_gift_form' ); with a DocBlock above it
Why: A moment others may act at is an action; you fire it with do_action(), prefixed and documented like core's (the project's pagesco_before_store_notice). A value others may change would be a filter.
A is wrong: A filter is for a value; nobody is asked to change one here.
B is wrong: add_action() attaches a callback; it does not create the moment.
C is wrong: Unprefixed: another plugin's before_gift_form would collide with it.

2.3 · The Hooks System: predict, then run

P3
Predict the output, then run it.
wp eval 'add_filter( "pagesco_p", "strrev" ); echo apply_filters( "pagesco_p", "Dune" ), " ", apply_filters( "pagesco_other", "Dune" ), "\n";'
enuD Dune
Why: strrev is a callback by name: PHP's own function, which takes one value and returns one, the shape a filter needs. A hook nobody filters returns the value unchanged, which is why calling apply_filters() costs nothing when no plugin uses it.
P4
Predict the output, then run it.
wp eval 'add_action( "pagesco_p", function () { echo "ran "; } ); var_dump( do_action( "pagesco_p" ) );'
ran NULL
Why: The action ran its callback (ran ), and do_action() returns nothing: var_dump() of nothing is NULL. Actions are moments, not values; if you need an answer back, offer a filter.

The Lesson Pages' Own Quick Quizzes

Lesson 2.2 · Core Architecture & the Database
  1. A A row in wp_postmeta with the post's ID, a meta_key and a meta_value: Extra fields of a post are rows in wp_postmeta: post_id, meta_key, meta_value. That is what update_post_meta writes.
  2. B 10, 100, 9: meta_value is LONGTEXT, so the values are compared as text, character by character: 1 sorts before 9. Cast them, or use meta_value_num in WP_Query, for numeric order.
  3. C auto: With no decision from the code and a small value, WordPress stores auto, which is autoloaded today. Large values become auto-off.
  4. B It stays in wp_postmeta as orphaned rows: WordPress tables have no foreign keys, so MySQL neither refuses nor cascades. The meta and term rows stay as orphans; wp_delete_post would have removed them.
  5. C pluggable.php, which defines it, loads only after all plugins: wp_get_current_user lives in pluggable.php, which wp-settings.php loads after all plugins so they can replace its functions. Call it from a hook such as init instead.
Lesson 2.3 · The Hooks System
  1. B add_filter( 'the_title', ... ) with a callback that returns the title and an asterisk: the_title is a filter: WordPress passes the title in and displays whatever your callback returns, so the callback returns the title with an asterisk added.
  2. C CBDA: C has priority 5 and runs first. B and D both have the default 10 and run in the order they were added, then A at 20.
  3. A remove_filter( 'excerpt_length', 'pagesco_excerpt_length', 15 );: Removal needs the same hook, the same callback and the same priority it was added with, here 15.
  4. C ArgumentCountError: Too few arguments to function {closure}(), 1 passed ... and exactly 2 expected: add_filter defaults to one accepted argument, so the closure is called with only the title and PHP throws ArgumentCountError for the missing $id. Registering with 10, 2 fixes it.
  5. A $count = apply_filters( 'pagesco_featured_count', 3 );: A prefixed, documented filter on the value is exactly the extension point: the other developer hooks pagesco_featured_count and returns a different number.

Exit Ticket

  1. Through WordPress: WordPress's tables have no foreign keys, so PHP does what ON DELETE CASCADE would do (wp_delete_post() removes meta, term links, revisions and comments); serialized values carry their lengths, which a text REPLACE breaks; and the API keeps the object cache and every hook in step. A DELETE at the prompt leaves orphans; an UPDATE skips the caches.
  2. Banner and excerpts: a banner at the top of every page is a moment: an action on wp_body_open (the project's store notice). The excerpt length is a value: a filter on excerpt_length whose callback returns a number.
  3. remove_action() false: the priority differs from the one used in add_action(); it ran before the hook was added (a theme's after_setup_theme callback, removed from the top of a plugin file); or the callback is not the same one (a closure, or a method of a different object).

Common Wrong Answers and What They Reveal

  • Q1 A ("position does not matter"). Sees wp-config.php as a list of settings, not a program that ends by loading WordPress. Show line 139 again.
  • Q3 A or D. Remembers that the theme is "the outside" and plugins "the inside" but not the order. Redraw the shop: lights, always-there things, today's departments, window display.
  • Q4 with string(5) "Devon". Expects one value because there is one row. The metadata API always returns a list unless you ask for one value: true.
  • Q5 A. Correct instinct (never edit serialized text), wrong mechanism: count the letters. The answer's second half (use the API anyway) is the part to keep.
  • Q7 with XbA or xaB. Ran the lines in the order written. Ask: "which priority runs first?"
  • Q9 C. Blames the priority, the most common removal bug, but this one is timing. Ask: "when did the theme add it, and when did your line run?"
  • Q11 D. Mixes up the two the_title mistakes: a missing return is a Deprecated notice and an empty title; two arguments asked and one registered is a fatal error.

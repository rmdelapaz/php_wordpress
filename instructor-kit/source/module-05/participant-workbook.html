Lessons

3.3

Patterns, Style Variations & the Site Editor

By the end you can
  • Write PHP pattern files with the right header fields, translatable text and escaped theme URLs, and place them in templates with the Pattern block
  • Explain the difference between theme patterns, synced patterns and template parts, and create a synced pattern that updates every page it is used on
  • Define section styles and a style variation as JSON files in styles/ and read what the Site Editor saves when someone chooses one
  • Bundle a web font with fontFace in theme.json, checking that its license allows redistribution
  • Bring Site Editor changes back into the theme's files with Export and WP-CLI, then reset the database copies
Key ideas
  • Three tools: a theme pattern (a PHP file in patterns/, copied when inserted), a synced pattern (a wp_block post, one original shown everywhere), a template part (parts/, included by slug).
  • A pattern file = a header (Title and Slug required; Categories, Keywords, Description, Post Types, Template Types, Block Types, Inserter) + block markup. PHP makes it translatable (esc_html_e()), portable (get_theme_file_uri(), home_url()) and escaped.
  • The pattern-file list is cached for 30 minutes, keyed on the theme's Version. WP_DEVELOPMENT_MODE = theme switches the theme caches off: local sites only.
  • Templates use patterns by slug: <!-- wp:pattern {"slug":"pagesco/hero"} /-->. front-page.html is above home and index for the front page.
  • Synced patterns are content, referenced by ID (<!-- wp:block {"ref":20} /-->): never in theme files.
  • styles/*.json with blockTypes = a section style (is-style-<slug>); without it = a style variation for the whole site. Choosing one in the Site Editor saves user global styles (a wp_global_styles post).
  • fontFace bundles a web font (file:./assets/fonts/...): only fonts whose license allows redistribution (OFL 1.1).
  • The Site Editor expands patterns when it saves. List copies with wp post list --post_type=wp_template,wp_template_part,wp_global_styles, move each change into the right file, delete the copy.
Worked example: where the front page's design lives

At the end of Lesson 3.3 the design of the front page comes from three different places. Ask WordPress about each. First the theme's patterns, with their categories and the post types they are offered in:

wp eval 'foreach ( WP_Block_Patterns_Registry::get_instance()->get_all_registered() as $p ) { if ( str_starts_with( $p["name"], "pagesco/" ) ) { echo $p["name"], " | ", implode( ", ", $p["categories"] ), " | ", implode( ", ", $p["postTypes"] ?? array( "(any)" ) ), "\n"; } }'
pagesco/call-to-action | call-to-action | (any)
pagesco/featured-books | featured | (any)
pagesco/hero | banner, featured | wp_template

Only the hero says wp_template: it is offered only in the Site Editor's templates, because inserted into a page its <h1> would compete with the page title. Then the synced pattern, which is not in the theme at all:

wp post list --post_type=wp_block --fields=ID,post_title,post_name
+----+---------------+---------------+
| ID | post_title    | post_name     |
+----+---------------+---------------+
| 20 | Opening hours | opening-hours |
+----+---------------+---------------+

A post of type wp_block, in the database. Is it synced? An unsynced user pattern carries the meta key wp_pattern_sync_status; count its meta:

wp post meta list 20 --format=count
0

No meta, so synced: every page that references it by ID shows the one original. Files for the theme's design, posts for the owner's content.

3.4

Child Themes & Customizing Existing Themes

By the end you can
  • Create and activate a child theme with the Template header, and explain the template and stylesheet options it sets
  • Predict how a child's theme.json, templates, template parts, patterns and style variations combine with the parent's
  • Use a child functions.php to enqueue the child's stylesheet, replace a pluggable parent function and remove a parent hook at the right time
  • Build a classic child theme and explain how get_stylesheet_directory(), get_template_directory() and locate_template() choose files
  • Choose between the Site Editor, a child theme, your own theme and a plugin for a requested change
Key ideas
  • A child theme is a theme folder whose style.css says Template: <parent folder>. WordPress looks in the child first and falls back to the parent; the parent stays untouched and can be updated.
  • Two options: template = the parent, stylesheet = the child. get_template_directory() vs get_stylesheet_directory(); get_theme_file_path() / _uri() = the child's copy if it exists, else the parent's.
  • theme.json is merged (core, parent, child, user), single values key by key, but preset lists are replaced whole: repeat every slug, change only values.
  • Same name replaces: templates, parts, classic PHP templates, styles/ files (by file name only); same slug replaces patterns.
  • functions.php: both run, the child's FIRST. A block child's style.css loads only when enqueued (depend on the parent's real handle). Pluggable parent functions (function_exists()) can be replaced; parent hooks are removed on after_setup_theme.
  • Classic child themes work the same with PHP templates (locate_template(), get_header()); never @import the parent's CSS. One level only: no grandchildren.
  • Which tool? Site Editor (owner, database) · child theme (lasting design changes to someone else's theme) · your own theme · a plugin (features that must survive a theme switch).
Worked example: what a child theme overrides, and what it inherits

The child theme of Lesson 3.4 has five files. Everything else comes from the parent:

find wp-content/themes/pagesco-tt5-child -type f | sort
wp-content/themes/pagesco-tt5-child/functions.php
wp-content/themes/pagesco-tt5-child/patterns/footer.php
wp-content/themes/pagesco-tt5-child/style.css
wp-content/themes/pagesco-tt5-child/templates/single.html
wp-content/themes/pagesco-tt5-child/theme.json

Which theme serves each template? get_block_templates() names them all after the active theme, so ask core's internal _get_block_template_file() (fine for checking, not for theme code), with the child switched on for a moment:

wp theme activate pagesco-tt5-child
wp eval 'foreach ( array( "single", "page", "404" ) as $slug ) { echo $slug, ": ", _get_block_template_file( "wp_template", $slug )["theme"], "\n"; }'
wp theme activate pagesco
Success: Switched to 'Pages &amp; Co. TT5 Child' theme.
single: pagesco-tt5-child
page: twentytwentyfive
404: twentytwentyfive
Success: Switched to 'Pages &amp; Co.' theme.

single is the child's copy (the one without comments); page and 404 are the parent's, and keep receiving Twenty Twenty-Five's updates. Override as little as you can.

Glossary

TermMeaning
theme patternA PHP file in the theme's patterns/ folder; inserted as a copy of its blocks
synced patternA wp_block post shown wherever <!-- wp:block {"ref":ID} /--> refers to it; one original
Pattern block<!-- wp:pattern {"slug":"..."} /-->: a theme pattern used in a template by slug
WP_DEVELOPMENT_MODEtheme (also core, plugin, all): switches off the caches that get in a developer's way; never on production
section styleA JSON file in styles/ with blockTypes: a named look for one Group or Columns block (is-style-<slug>)
style variationA JSON file in styles/ without blockTypes: an alternative look for the whole site
user global stylesThe wp_global_styles post the Site Editor saves; the top layer over core and theme
fontFaceThe theme.json key that describes bundled font files (file:./assets/fonts/...)
child themeA theme with Template: <parent folder> that holds only changes; the rest comes from the parent
template / stylesheetThe two options that name the parent and the child (the same folder without a child theme)
pluggable functionA parent function wrapped in if ( ! function_exists( ... ) ), which a child may define first
after_setup_themeThe action that fires after both themes' functions.php files have loaded

  1. W1 In theme.json, what is the difference between settings and styles? Answer: settings say what editors may choose (the palette, font sizes, layout widths); styles say what is applied (the page's colors, fonts, element and block styles). Presets in settings become custom properties and classes (Lesson 3.2).
  2. W2 The front page shows the latest posts. In a block theme, which templates does WordPress look for, in order? Answer: front-page, then home, then index (Lesson 3.1). pagesco has only index.html so far; Lesson 3.3 adds front-page.html today.
  3. W3 The manager changed the Single Posts template in the Site Editor. Where is that change, and which version does a visitor see? Answer: In the database, a wp_template post whose source is custom; it wins over templates/single.html until someone resets it (Lesson 3.2, Common Mistakes 3).
  4. W4 A template part is included as {"slug":"heder"}. What do visitors see? And a logged-in administrator? Answer: Visitors: nothing, the header is just missing. Logged in: "Template part has been deleted or is unavailable: heder" (Lesson 3.2).
  5. W5 Run the two commands on the slide. What should a site ready for today print? Answer: bool(true) twice (pagesco is a block theme with a theme.json), then 0: no Site Editor copies. A learner with copies resets them first (wp post delete ID --force), or today's outputs will not match.

3.3 · Patterns, Style Variations & the Site Editor: self-check

Q1
The live site has no WP_DEVELOPMENT_MODE. You deploy pagesco with a new patterns/gift-cards.php, and the inserter does not show it for half an hour. What makes WordPress read the patterns folder again at once, as part of every release?
A) Raise the theme's Version in style.css
B) Call register_block_pattern() for the file in functions.php
C) Run wp cache flush
D) Rename patterns/ and back
Why: The list of pattern files is cached in a transient (wp_theme_files_patterns-…) for 30 minutes, and rebuilt early when the theme's Version changes or the theme is switched (Lesson 3.3). Bumping Version on every deploy is the habit Lesson 8.4 builds in; the transient holds the version it was built for.
B is wrong: Files in patterns/ register themselves; registering the same pattern by hand is a second, different mechanism.
C is wrong: Without a persistent object cache, transients live in the options table, which a cache flush does not touch.
D is wrong: The cache is keyed on the theme, not on the folder's name; renaming does nothing reliable.
Q2
On the site at the end of Lesson 3.3, what does this print, and what are the two numbers?
wp eval 'echo count( WP_Theme_JSON_Resolver::get_style_variations() ), " ", count( WP_Theme_JSON_Resolver::get_style_variations( "block" ) ), "\n";'
1 2: one site variation (Evening) and two section styles (Sage band, Ink band)
Why: The resolver sorts every JSON file under styles/ by one key: a file with blockTypes is a section style (the second call), a file without it a style variation for the whole site (the first). The folder styles/sections/ is only for order.
Q3
Which of these lines should never be written into a template file in a theme?
A) <!-- wp:pattern {"slug":"pagesco/hero"} /-->
B) <!-- wp:template-part {"slug":"footer"} /-->
C) <!-- wp:block {"ref":20} /-->
D) <!-- wp:query {"query":{"inherit":true}} -->
Why: A synced pattern is referenced by its post ID, and IDs differ on every site: on another copy of the site, post 20 is something else or nothing. Themes refer to patterns by slug and to parts by slug; synced patterns are the site owner's content (Lesson 3.3, "Synced patterns are content, not theme").
A is wrong: A theme pattern by slug is exactly how templates use patterns.
B is wrong: Template parts are included by slug from parts/.
D is wrong: The Query Loop that inherits the main query is how lists are drawn in block templates.
Q4
After the shop manager saved the front page in the Site Editor, the wp_template copy contains "patternName":"pagesco/hero" and src="http://localhost:8080/...". What does that tell you?
A) The copy still refers to hero.php, so changes to the file will show up
B) The Site Editor could not read the pattern file and left a placeholder
C) Nothing: patternName is only used for the inserter's preview
D) The pattern was expanded before saving: its PHP already ran, so the URL is hard-coded and the strings are frozen in English
Why: When someone edits a template that uses wp:pattern, the editor replaces each reference with the pattern's blocks and records where they came from in metadata.patternName. Copying that template over the file would lose translation, theme URLs and escaping; move the actual change into the pattern file and reset the copy.
A is wrong: No wp:pattern reference is left in the copy; it is ordinary blocks now.
B is wrong: The content is complete; the metadata is a note, not a placeholder.
C is wrong: It is a record of where the blocks came from; the important part is that the reference is gone.
Q5
You move section-ink.json from styles/sections/ up into styles/. What changes?
A) It becomes a style variation for the whole site
B) Nothing: it is still a section style, because it has blockTypes
C) WordPress ignores it: section styles must be in styles/sections/
D) It replaces evening.json, because both are in styles/ now
Why: WordPress reads every JSON file under styles/, at any depth, and tells the two kinds apart by the blockTypes key alone. The subfolder exists only for people.
A is wrong: A file becomes a site variation only when it has no blockTypes.
C is wrong: There is no required folder name.
D is wrong: Files replace each other by name only in a child theme (Lesson 3.4), and the names differ.
Q6
The page source announces Vollkorn in a @font-face rule, but every browser shows the fallback serif, and debug.log is empty. Where do you look first, and for what?
The browser's developer tools, Network tab filtered by Font: the font request answers 404, so the src path after file:./ (or the folder name) is wrong
Why: WordPress builds the @font-face URL from theme.json without checking that the file exists (Lesson 3.3, Common Mistakes 2). From the WP-CLI container, curl -s -o /dev/null -w '%{http_code}' <the font URL> shows the same 404.

3.4 · Child Themes & Customizing Existing Themes: self-check

Q7
A client uploads only your child theme (pagesco-tt5-child.zip) to a site where Twenty Twenty-Five has been deleted, and clicks Activate. What happens?
A) WordPress uses its default theme as the parent instead
B) It refuses: the parent theme is missing, and the theme is listed under Broken Themes
C) The child activates, unstyled, until the parent is installed
D) WordPress downloads Twenty Twenty-Five automatically
Why: A child is only meaningful on top of its parent. WP-CLI says Error: The parent theme is missing. Please install the "twentytwentyfive" parent theme.; the Themes screen lists the child under Broken Themes (Lesson 3.4, Common Mistakes 1, where a typo in Template: caused the same). Install the parent first.
A is wrong: Template: names one folder; WordPress never guesses another parent.
C is wrong: Without a parent there are no templates to draw a page with; activation is refused.
D is wrong: Nothing is downloaded on activation; wp theme install or the Themes screen does that.
Q8
On the site at the end of Lesson 3.4: what do the two middle commands print?
wp theme activate pagesco-tt5-child
wp option get stylesheet
wp option get template
wp theme activate pagesco
pagesco-tt5-child, then twentytwentyfive
Why: With a child theme active, the stylesheet option holds the child (the theme whose style.css header names the site's theme) and the template option holds the parent (where the templates and code come from). Without a child theme both hold the same folder name. The first and last lines switch the child on and back to pagesco.
Q9
A colleague's child theme.json lists only the two colors they wanted to change, base and contrast. What happens to Twenty Twenty-Five's accent colors?
A) They disappear: the child's palette replaces the parent's whole palette, and styles that use accent variables silently lose their colors
B) They stay: theme.json is merged key by key
C) WordPress prints a notice that the palette is incomplete
D) The child's two colors are added to the end of the parent's list
Why: Single values merge key by key, but preset lists (palette, font sizes, spacing sizes) are replaced as a whole. The home page still uses var(--wp--preset--color--accent-3) and accent-4, now undefined, and CSS ignores an undefined variable without a message (Lesson 3.4, Common Mistakes 2). Repeat every slug, change only values.
B is wrong: That is true for single values, not for preset lists.
C is wrong: There is no message anywhere; that is what makes it dangerous.
D is wrong: Lists are not appended; the child's list is the list.
Q10
Why can a child of Twenty Twenty-Five replace twentytwentyfive_post_format_setup() by defining a function with that name in its own functions.php?
A) Child functions always override parent functions of the same name
B) WordPress renames the parent's function when a child theme is active
C) The parent's function is registered on a hook, and hooks prefer the child
D) The child's functions.php loads first, and the parent defines that function only if ( ! function_exists( ... ) )
Why: Load order (Lesson 3.4: child, then parent) plus a pluggable function. For a parent function WITHOUT the function_exists() wrapper, defining the same name in the child is a fatal Cannot redeclare error; remove or replace its hook instead, on after_setup_theme.
A is wrong: PHP does not allow two functions with one name; only the wrapper makes it possible.
B is wrong: WordPress renames nothing.
C is wrong: Hooks have priorities, not a preference for the child; and the replacement here is a function definition.
Q11
Twenty Twenty-Four enqueues no stylesheet of its own. In a child of it you write wp_enqueue_style( 'my-child-style', get_stylesheet_uri(), $deps, $version ). What should $deps be?
A) array( 'twentytwentyfour-style' )
B) array( 'wp-block-library' )
C) array()
D) get_template_directory_uri() . '/style.css'
Why: There is no parent handle to wait for, so the child depends on nothing (the session's TT4 child lab does exactly this). Read the parent's functions.php before copying a tutorial's handle: on WordPress 7.1 a dependency that is not registered stops the stylesheet from printing at all, with a notice that it was enqueued with dependencies that are not registered (since 6.9.1).
A is wrong: That handle does not exist: WordPress drops the child's stylesheet and notes it in debug.log.
B is wrong: The child's CSS has nothing to do with the block library's; the dependency only delays it for no reason.
D is wrong: That is a URL, not a list of handles, and it points at the parent's style.css header file.
Q12
The shop manager wants to try a darker link color for the holidays and switch it back in January, without calling you. Site Editor, child theme, or plugin? Why?
The Site Editor's Styles: a visual choice the owner wants to change again; it is saved in the database (the user global styles) and needs no developer
Why: The decision table of Lesson 3.4: who should change it later, and must it survive a theme switch? Lasting design work on a theme you did not write goes in a child theme, kept in Git; features go in plugins; owner-changeable looks belong to the Site Editor.

The Lesson Pages' Own Quick Quizzes

Lesson 3.3 · Patterns, Style Variations & the Site Editor
  1. B The cached list of the theme's pattern files is still the old one: WordPress caches the list of pattern files per theme version. Set WP_DEVELOPMENT_MODE to theme on a development site, or raise the theme Version when you deploy.
  2. C A synced pattern: A synced pattern is one wp_block post; every page references it, so editing it once updates all six.
  3. A One with "blockTypes": [ "core/group" ] and a styles section: The blockTypes key is what makes a file in styles/ a block style variation (section style) instead of a style variation for the whole site.
  4. B Find the actual change, put it into the right theme file (often a pattern), then reset the copy: The export has the patterns expanded, with hard-coded URLs and frozen text. Move the actual change into the file it belongs to, usually a pattern, then reset the database copy.
  5. C Check whether its license allows web use and redistribution in a theme: Desktop or print licenses usually forbid web embedding and redistribution. Check the license (or buy a web license); until then use an OFL font or a system stack.
Lesson 3.4 · Child Themes & Customizing Existing Themes
  1. B twentytwentyfive: template holds the parent's folder (twentytwentyfive); stylesheet holds the child's. Without a child theme both are the same.
  2. A It stays: the child's file is merged over the parent's: Single values in theme.json are merged key by key, so everything the child does not set keeps the parent's value. Only preset lists such as the palette are replaced as a whole.
  3. C false, and the parent's stylesheet is still loaded: The child's functions.php runs before the parent's, so the action has not been added yet and there is nothing to remove. Do it from a callback on after_setup_theme.
  4. B A child pattern with the slug twentytwentyfive/footer: The parent's footer part only references the pattern twentytwentyfive/footer, and a child pattern with the same slug wins, so the part itself stays the parent's.
  5. C In a plugin: A form is a feature with data and security needs; it must survive a theme switch, so it belongs in a plugin (Module 5).

Exit Ticket

  1. Opening hours on four pages: a synced pattern, edited once, shown everywhere it is referenced. A hero for new landing pages: a theme pattern, a starting point that is copied and then edited per page.
  2. Site Editor storage: wp_template (and wp_template_part) posts for templates and parts, the wp_global_styles post for styles; wp post list --post_type=wp_template,wp_template_part,wp_global_styles lists them. (Synced patterns are wp_block posts, created on purpose.)
  3. Load order: the child's functions.php first, then the parent's. A parent hook does not exist yet when the child's file runs, so remove it in a callback on after_setup_theme; a pluggable parent function can be replaced by defining it first.

Common Wrong Answers and What They Reveal

  • Q1 B (register_block_pattern). Thinks pattern files need registering. Show the registry before and after development mode: no code, only the cache.
  • Q3 A or B. Thinks every block comment is risky in a template. The question is what the comment refers to: a slug travels, an ID does not.
  • Q4 A. The most important miss of the session: the learner believes the copy still points at hero.php. Rerun the demo's grep on the copy.
  • Q5 A. Believes the folder decides. Point at the resolver's one key: blockTypes.
  • Q9 B. Knows "merged" from the lesson and applies it to lists. Run the partial-palette count.
  • Q10 A. "Child wins" as a general rule. Ask what PHP does with two functions of the same name.
  • Q11 A. Copied the lesson's handle. The TT4 lab is the cure: read the parent's functions.php.

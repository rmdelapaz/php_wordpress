Session 5: Patterns, Style Variations and Child Themes

How to teach the second half of Module 3. Give the Pages & Co. theme ready-made sections: pattern files that stay translatable, a front page built from them, a synced pattern shared by two pages, a section style, and the Site Editor round trip that keeps files and database copies apart. Then customize a theme you did not write: a child of Twenty Twenty-Five, the merge rules of theme.json, a stylesheet that must be enqueued, and functions.php's load order, with a Twenty Twenty-Four child as the lab.

How to Use This Guide

  • Same rhythm for both lessons: frame (one mental model) → live demo (you type, they type along) → guided lab (a kit lab, new practice on the lesson's ideas) → start the lesson's own project. Exercises, the Quick Quiz and the journal are homework.
  • Type, do not paste. Every command below was run to produce the output printed under it, on WordPress 7.1.3 and PHP 8.5: for 3.3 a course site exactly as Lesson 3.2 leaves it (pagesco active, no patterns yet), for 3.4 the site at the end of Lesson 3.3. Ask for a prediction before every run. IDs (the synced pattern's 20, the template copy's 24) can differ on learners' sites; say so when they appear.
  • The lessons are the reference. Keep lesson_09.html and lesson_10.html open for the long file listings (hero.php, the about/contact markup, theme.json): paste-free typing of those is not the goal, reading them is. Labs live in labs/module-05/ (learners keep the folder in their project folder): _starter files and folders are handouts, _solution ones are yours.
  • Session 5 is Module 3's second half: the theme becomes something editors use (patterns, styles) and you learn to customize themes you did not write (child themes). It ends with pagesco active again, as Session 6 expects.
The #1 risk of Session 5: three copies of "the design"

After today the design of Pages & Co. lives in theme files, in synced patterns, in user global styles and in Site Editor template copies. Learners who click around in the Site Editor at home end the week with database copies that make every later output differ, and they do not know it. Before: the warm-up's second command counts the copies; anyone above 0 resets them. In the room: spend the full six minutes on the Site Editor round trip and write the loop on the board. After: "Before the Next Lesson" in 3.3 asks for the list of template, template-part and global-styles posts to be empty; make it the first line of the homework.

Warm-up answers
  1. W1 In theme.json, what is the difference between settings and styles? Answer: settings say what editors may choose (the palette, font sizes, layout widths); styles say what is applied (the page's colors, fonts, element and block styles). Presets in settings become custom properties and classes (Lesson 3.2).
  2. W2 The front page shows the latest posts. In a block theme, which templates does WordPress look for, in order? Answer: front-page, then home, then index (Lesson 3.1). pagesco has only index.html so far; Lesson 3.3 adds front-page.html today.
  3. W3 The manager changed the Single Posts template in the Site Editor. Where is that change, and which version does a visitor see? Answer: In the database, a wp_template post whose source is custom; it wins over templates/single.html until someone resets it (Lesson 3.2, Common Mistakes 3).
  4. W4 A template part is included as {"slug":"heder"}. What do visitors see? And a logged-in administrator? Answer: Visitors: nothing, the header is just missing. Logged in: "Template part has been deleted or is unavailable: heder" (Lesson 3.2).
  5. W5 Run the two commands on the slide. What should a site ready for today print? Answer: bool(true) twice (pagesco is a block theme with a theme.json), then 0: no Site Editor copies. A learner with copies resets them first (wp post delete ID --force), or today's outputs will not match.

Mental model to say

"A theme pattern is a rubber stamp. You press it onto the page and get a perfect print; after that the print is just ink on paper, and changing the stamp does not change prints you already made. A synced pattern is a sign hung in several rooms: there is only one sign, so repainting it changes what every room shows. Template parts are the signs fixed to the building itself, at every entrance."

Then the table on the board, one row at a time, with the question that decides: must every copy change when the original changes? No: a theme pattern (a starting point). Yes, and it is content the owner runs: a synced pattern. Yes, and it is site structure: a template part.

Then the PHP argument in one breath: "Pattern files are PHP so they can be translated, build URLs that work on any site, and escape their output. Keep those three in mind; the Site Editor will take all three away from you at the end of the demo."

Three mistakes to expect, and how to coach each
  • "My pattern doesn't show up." Either the cache (no development mode: is_registered() is false and nothing says why) or a header without Slug: (a notice at the top of every page). Coach: "Ask the registry first, then read the top of the page." (Self-check Q1; the handout debug_pattern_files.sh.)
  • Copying the Site Editor's markup back over the file. It looks like the newest version. Coach: "Where is your wp:pattern line? What happened to esc_html_e()?" (Self-check Q4, the lesson quiz Q4.)
  • A synced pattern's reference in a theme file. <!-- wp:block {"ref":20} /--> in front-page.html "because it worked". Coach: "On the live site, what is post 20?" (Self-check Q3.)

Mental model to say

"Picture the parent theme as an architect's printed floor plan. You lay tracing paper on top and draw only what you want different. Anyone looking at the stack sees the combined plan.

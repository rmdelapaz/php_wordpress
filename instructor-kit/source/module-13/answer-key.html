6.4 · The Interactivity API: self-check

Q1
A visitor opens /find-a-book/?genre=fantasy. Where does the browser's store get state.genre's starting value from?
A) From the address bar, read by view.js
B) From the state JSON that render.php's wp_interactivity_state() put into the page
C) From localStorage
D) From a REST request the store sends on load
Why: render.php validates ?genre= and passes it to wp_interactivity_state(); WordPress prints the plain values as JSON (the script tag with the id wp-script-module-data-@wordpress/interactivity), and the runtime merges it into the store's state before anything runs.
A is wrong: view.js only WRITES the address (history.replaceState()).
C is wrong: Nothing in the block uses browser storage.
D is wrong: The Book Filter makes no requests: all books are in the HTML (Lesson 7.2 designs the REST version).
Q2
Which of these directives does the SERVER not evaluate when it renders the block?
A) data-wp-bind--hidden="!state.isVisible"
B) data-wp-text="state.visibleCount"
C) data-wp-class--is-selected="state.isSelected"
D) data-wp-on--click="actions.selectGenre"
Why: Events only exist in the browser, so data-wp-on (and watch, init, run) are browser-only. bind, class, style, text, context, each and interactive are processed on the server too, which is why the page is correct before any JavaScript runs.
A is wrong: The server writes hidden on the nine non-fantasy books.
B is wrong: The server fills the span with 2.
C is wrong: The server adds class="is-selected" to the Fantasy link.
Q3
On the course site after Lesson 6.4 (three Dystopian books of eleven): what does this print?
curl -s 'http://localhost:8080/find-a-book/?genre=dystopian' | grep -c '<li hidden'
8
Why: All eleven books are in the HTML; the server ran data-wp-bind--hidden for each and wrote hidden on the eight that are not dystopian. curl runs no JavaScript: this is what every visitor gets first.
Q4
Each genre link must know its own slug. Where does that slug belong?
A) In the element's context, wp_interactivity_data_wp_context( array( 'slug' => $slug ) )
B) In the state, as one key per genre
C) In a global JavaScript variable
D) In the link's class name
Why: State is shared by the whole store (one genre is selected for everyone); context is data attached to one element and visible to the directives inside it. getContext() reads it in getters and actions, wp_interactivity_get_context() in the PHP closures.
B is wrong: Works, but every link's directives would need to name their own key: context is what per-element data is for.
C is wrong: The runtime would not track it, so nothing would update.
D is wrong: Classes are for styling; the store cannot read them as data.
Q5
An action calls event.preventDefault() to stop a link. What does WordPress 6.8 and later require for it?
A) Nothing: actions always run synchronously
B) data-wp-on-async--click instead of data-wp-on--click
C) Wrapping the action in withSyncEvent()
D) Returning false from the action
Why: Since 6.8 the runtime may run actions after the browser has handled the event, too late to prevent anything. withSyncEvent() says the action needs the event right away; without it 7.1 still works but logs a deprecation warning (Common Mistake 2).
A is wrong: That was true before 6.8.
B is wrong: on-async is for actions that need NOTHING from the event.
D is wrong: Return values of actions are ignored.
Q6
A visitor's browser blocks the Book Filter's script module, and she clicks Fantasy. What happens, and why?
The link is followed (a page load) and the server renders the filtered page: the links are real ?genre= links and render.php reads the address
Why: Progressive enhancement: the HTML works on its own; JavaScript only makes it faster. It came almost for free because the state starts in PHP and the derived values have PHP closures.

7.1 · Using the REST API: self-check

Q7
Anonymously, GET /wp-json/wp/v2/books/30?context=edit. What comes back?
A) 200 with the raw title and the content as block markup
B) 404 rest_no_route
C) 401 rest_forbidden_context
D) 403 rest_cannot_edit
Why: context=edit returns raw values only to users who could edit the item. Nobody is logged in, so it is "who are you?": 401. Maria with an application password gets the raw fields; Devon, an author, 403.
A is wrong: Only for users who may edit the book.
B is wrong: The route exists; only the context is refused.
D is wrong: 403 means "I know you, and no": the request is anonymous.
Q8
On the course site (six Classic books, genre ID 7): what does this print?
curl -s 'http://localhost:8080/wp-json/wp/v2/books?genres=7&per_page=4&_fields=id' -D - -o /dev/null | grep -i '^X-WP-TotalPages'
X-WP-TotalPages: 2
Why: X-WP-TotalPages is the number of pages at this per_page: six books in pages of four are two pages. The body (sent to /dev/null here) would hold the first four; a client loops up to the header's number.
Q9
A Dashboard page sends Maria's cookie and an X-WP-Nonce header with an old, made-up value. What does the REST API answer?
A) 403 rest_cookie_invalid_nonce: the page must fetch a fresh nonce
B) 200: the cookie is enough
C) 401 rest_not_logged_in, as if no cookie had been sent
D) 500: the nonce check crashed
Why: With no nonce, the cookie is ignored and the request is anonymous. With a WRONG nonce, WordPress refuses outright, so a stale page knows it must refresh (apiFetch does that by itself through the rest-nonce endpoint).
B is wrong: The nonce is what protects the cookie from CSRF.
C is wrong: That is the answer WITHOUT a nonce.
D is wrong: A failed check is a normal error answer.
Q10
/wp/v2/books/30?_embed=wp:term&_fields=id,title answers without any genres. Why?
A) The book has no genres
B) _embed works only for authenticated requests
C) wp:term is not an embeddable relation
D) _fields removed _links, so there was nothing to follow, and _embedded is cut off too
Why: Since 5.4 WordPress embeds only links that survive _fields. Add _links and _embedded to the list: _fields=id,title,_links,_embedded (Common Mistake 1).
A is wrong: Dune is Fiction and Science Fiction.
B is wrong: Public data embeds anonymously.
C is wrong: The genre link says embeddable: true.
Q11
Why can you create application passwords on the course site although it runs on plain http://localhost:8080?
A) Application passwords never need HTTPS
B) WP_ENVIRONMENT_TYPE is local; elsewhere WordPress offers them only on HTTPS
C) Docker encrypts the traffic
D) Because the administrator created them
Why: Basic authentication only encodes the password; on plain HTTP anyone on the way can read it. WordPress therefore offers application passwords on HTTPS sites or where the environment type is local, as compose.yaml sets it (Lesson 1.2).
A is wrong: They do, outside local environments.
C is wrong: The containers talk plain HTTP.
D is wrong: Maria created hers with WP-CLI; the rule is about the connection.
Q12
Name two things wp.apiFetch() adds to a request that a plain fetch() on the Dashboard does not.
The REST nonce (X-WP-Nonce) for the logged-in user, and the API's root URL (also _locale=user, a JSON body and the server's error object on failure)
Why: The page prints apiFetch's setup when a script depends on wp-api-fetch: createRootURLMiddleware, the nonce middleware, the nonce endpoint for refreshing. Without the nonce the request is anonymous (Common Mistake 2).

<?php
/**
 * checkpoint_solution.php: Checkpoint 2 (Modules 5 and 6), the Weekly Picks report: MODEL ANSWER (Session 13)
 * state: after:lesson_21
 * expect: A  Under $10, in stock: Pride and Prejudice ($7.99), Animal Farm ($8.49), Brave New World ($9.49), 1984 ($9.99)
 * expect: B  Café: 2 events · Rooftop: 0 events · Reading corner'; DROP TABLE x; --: 0 events
 * expect: C1 Fantasy, cheapest first: The Hobbit, Lord of the Rings
 * expect: C2 Staff picks post: 1 Book Card, comment attributes {"backgroundColor":"sage"}
 *
 * Instructor copy. The shop wants a weekly report for its newsletter, built from the plugin's data: Parts A to C
 * are the scored code (three functions); Part D (three written answers) is on the workbook's Checkpoint page.
 * The main section at the end is the same in the starter, and the script changes nothing on the site.
 * Run: wp eval-file --use-include checkpoint_solution.php
 */

/**
 * Part A (Lessons 5.2, 5.3): books in stock that cost at most $max, cheapest first, as "Title ($8.49)".
 *
 * @param float $max The highest price.
 * @return string[]
 */
function pagesco_cp_cheap_books( float $max ): array {
	$books = get_posts(
		array(
			'post_type'      => 'book',
			'post_status'    => 'publish',
			'posts_per_page' => -1,
			'meta_key'       => 'pagesco_price',
			'orderby'        => 'meta_value_num',
			'order'          => 'ASC',
			'meta_query'     => array(
				array(
					'key'     => 'pagesco_price',
					'value'   => $max,
					'compare' => '<=',
					'type'    => 'DECIMAL(10,2)',
				),
				array(
					'key'   => 'pagesco_in_stock',
					'value' => '1',
				),
			),
		)
	);

	$lines = array();
	foreach ( $books as $book ) {
		$lines[] = sprintf( '%s ($%s)', $book->post_title, number_format_i18n( (float) get_post_meta( $book->ID, 'pagesco_price', true ), 2 ) );
	}

	return $lines;
}

/**
 * Part B (Lesson 5.5): how many events take place at a location: one prepared COUNT query on the events table.
 *
 * @param string $location The exact location, as typed by anyone.
 */
function pagesco_cp_events_at( string $location ): int {
	global $wpdb;

	return (int) $wpdb->get_var(
		$wpdb->prepare( 'SELECT COUNT(*) FROM %i WHERE location = %s', PagesCo\Books\EventsTable::name(), $location )
	);
}

/**
 * Part C (Lessons 6.2, 6.3): C1 renders a Book List block for a genre, cheapest first, and returns its titles;
 * C2 describes the Book Cards stored in a post.
 *
 * @param string $genre A genre slug.
 * @return string[]
 */
function pagesco_cp_list_titles( string $genre ): array {
	$attributes = array(
		'genre'   => $genre,
		'orderBy' => 'price',
	);
	$html       = do_blocks( '<!-- wp:pagesco/book-list ' . wp_json_encode( $attributes ) . ' /-->' );

	preg_match_all( '#<a href="[^"]*">([^<]*)</a>#', $html, $found );

	return $found[1];
}

/**
 * @param string $slug A post slug.
 * @return array{count: int, attrs: array}
 */
function pagesco_cp_cards_in( string $slug ): array {
	$post  = get_page_by_path( $slug, OBJECT, 'post' );
	$cards = array_values( wp_list_filter( parse_blocks( $post ? $post->post_content : '' ), array( 'blockName' => 'pagesco/book-card' ) ) );

	return array(
		'count' => count( $cards ),
		'attrs' => $cards ? $cards[0]['attrs'] : array(),
	);
}

echo 'A  Under $10, in stock: ', esc_html( implode( ', ', pagesco_cp_cheap_books( 10.0 ) ) ), "\n";

$pagesco_places = array( 'Café', 'Rooftop', "Reading corner'; DROP TABLE x; --" );
echo 'B  ', implode( ' · ', array_map( fn( $place ) => $place . ': ' . pagesco_cp_events_at( $place ) . ' events', $pagesco_places ) ), "\n";

Accept: WP_Query instead of get_posts(); %i or the table name from EventsTable::name() concatenated (it is not user input); any way of reading the titles from C1's HTML that does not query the books again. Do not accept 'type' => 'NUMERIC' for the price: NUMERIC makes MySQL cast to a whole number (CAST('10.49' AS SIGNED) is 10), so with a maximum of 10 Fahrenheit 451 ($10.49) and The Hobbit ($10.99) slip into line A, measured on the course site; that is Partial in row 1. Without any type the comparison is between strings and finds nothing.

Part D: model answers
  1. D1. The review: static, it is content an editor writes and it should stay as written (and survive the plugin). The three cheapest: dynamic, the data (prices, stock, new books) changes elsewhere, so render.php must ask on every view; a static block would go stale like Lesson 3.3's pattern.
  2. D2. A nonce (wp_nonce_field() in the form, check_admin_referer() or wp_verify_nonce() before saving; the Settings API does both). It stops cross-site request forgery: another site making a logged-in administrator's browser submit the form.
  3. D3. The genre choices are real links to ?genre= addresses, and render.php reads and validates ?genre= to set the starting state, with PHP closures for the derived state, so the server renders each filtered page itself (hidden on the other books, aria-current on the link).

The Lesson Pages' Own Quick Quizzes

Lesson 6.4 · The Interactivity API
  1. A It also builds viewScriptModule files as script modules: It adds a module build, so viewScriptModule files such as view.js are built with a view.asset.php of type module; without it they are skipped silently.
  2. C All eleven books, nine of them with the hidden attribute: render.php prints every book, and the server evaluates data-wp-bind--hidden through the isVisible closure, so the nine others arrive with the hidden attribute.
  3. B data-wp-text="state.visibleCount" on the span: data-wp-text sets the element's text content from a value, on the server and in the browser; here the span holds state.visibleCount.
  4. A So the server can evaluate the directives and send correct HTML before any JavaScript runs: The server evaluates directives while rendering; with the closure it can compute isVisible per book, so the HTML is already filtered and nothing changes when the page hydrates.
  5. C The link is followed and the server renders the fantasy books, with a page load: No store is wired to the directives, so the click follows the link and the server renders the filtered page: correct, but a full page load each time, with no message.
Lesson 7.1 · Using the REST API
  1. B GET /wp-json/wp/v2/books?per_page=5&_fields=id,title.rendered: per_page=5 gives five books, newest first by default, and _fields keeps only id and the rendered title.
  2. C 401: the request is treated as anonymous, and the edit is refused: Without an X-WP-Nonce header WordPress ignores the cookie, treats the request as anonymous and refuses the edit with 401. wp.apiFetch adds the nonce.
  3. A With an application password of a user whose role can edit books, over HTTPS: A program gets its own application password, for a user with no more rights than it needs, sent with Basic authentication over HTTPS, and revocable on its own.
  4. C 403: Devon is authenticated, so it is not 401; his role cannot edit another author's book, so the answer is 403 Forbidden.
  5. B 3: Eleven books in pages of four make three pages (4, 4 and 3); the header is the same on every page.

Exit Ticket

  1. State and derived state: the state is the selected genre (with each book's genres); derived are isVisible, isSelected and visibleCount.
  2. 401 means "who are you?" (not authenticated); 403 is "I know you, and no" (authenticated, not allowed).
  3. The partner's script: an application password of a WordPress user whose role can edit books (an editor), sent with Basic authentication over HTTPS; never the account password.

Common Wrong Answers and What They Reveal

  • Q1 A ("from the address bar"). Has not seen the state JSON: show the <script id="wp-script-module-data-..."> from the demo.
  • Q2 B or C. Thinks the server only prints HTML: run the curl for ?genre=fantasy again.
  • Q4 B ("in the state"). Works for small cases; context is per element. Redraw the three columns.
  • Q7 D (403). Confuses 401 and 403: the request has no user at all.
  • Q9 C (401 as anonymous). Remembers the no-nonce case; a WRONG nonce is refused outright.
  • Q10 A or B. Blames the data or the login: it is _fields cutting the links.
  • Q11 A. Missed the HTTPS rule: application passwords are offered only on HTTPS or a local environment.

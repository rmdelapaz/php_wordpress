5.5

Shortcodes, $wpdb & Custom Tables

By the end you can
  • Register shortcodes with add_shortcode() whose callbacks return escaped HTML, with attributes handled by shortcode_atts()
  • Decide when a custom table is the right storage, and when post types, meta, taxonomies or options are
  • Create and upgrade a table with dbDelta() and a schema version stored in an option
  • Read and write rows with $wpdb: insert(), update(), delete(), get_row(), get_var(), get_results(), always through prepare() or format arrays
  • Remove the table and its version option in uninstall.php
Key ideas
  • A shortcode is add_shortcode( $tag, $callback ) on init; the callback RETURNS escaped HTML and never echoes.
  • shortcode_atts( $defaults, $atts, $tag ) fills defaults, drops undeclared attributes (all values are strings) and creates the shortcode_atts_{$tag} filter.
  • A custom table is for many uniform rows queried by their fields; post types, taxonomies and options come with far more for free.
  • dbDelta() creates a table or adds missing columns and indexes from a carefully formatted CREATE TABLE; it never renames or drops.
  • A schema version in an option, compared on every request: raise it with every schema change, because updates do not rerun activation.
  • Every $wpdb value through placeholders (%s, %d, %f, %i) or the format arrays of insert(), update(), delete().

6.1

Block Development Setup

By the end you can
  • Describe a block type as WordPress sees it: block.json metadata, an editor script with edit and save, styles, and (later) PHP rendering
  • Scaffold a block into an existing plugin with npx @wordpress/create-block and --no-plugin, and read every generated file
  • Build blocks with @wordpress/scripts, and say what each file in build/ is for, including index.asset.php and the blocks manifest
  • Register all built blocks from a plugin feature with wp_register_block_types_from_metadata_collection()
  • Recognize the setup mistakes that cost beginners an afternoon: a second plugin by accident, a missing build, and stale build files
Key ideas
  • A block type is block.json metadata plus an editor script with edit (the editing view) and save (the stored HTML), plus styles; a static block's front end needs no JavaScript.
  • npx @wordpress/create-block@latest <slug> --no-plugin --target-dir=src/blocks/<slug> --namespace=pagesco --textdomain=pagesco-books adds a block to the existing plugin.
  • npm run build (@wordpress/scripts) turns src/blocks into build/blocks: compiled scripts and styles, index.asset.php (dependencies + version) and, with --blocks-manifest, blocks-manifest.php.
  • wp_register_block_types_from_metadata_collection( $dir, $manifest ) on init registers every built block and its asset handles: the Blocks feature.
  • WordPress reads only build/: rebuild after every change (or keep npm start running), and build wherever the plugin is installed from source.
Worked example: the shelf, not the kit

After the project: is the build's block.json the same file as the source's?

cd wp-content/plugins/pagesco-books && diff src/blocks/book-card/block.json build/blocks/book-card/block.json > /dev/null && echo same || echo differ
differ

Different: the build rewrites it (formatting, and file: paths relative to build/). And the saved text survives minification word for word:

grep -o '"Book Card: a staff pick is coming soon."' wp-content/plugins/pagesco-books/build/blocks/book-card/index.js
"Book Card: a staff pick is coming soon."

Glossary

TermMeaning
shortcodeA [tag] in content that a callback replaces with HTML on display
custom tableA table of your own, {$wpdb->prefix}pagesco_events, for uniform rows
dbDelta()Creates or extends a table from a CREATE TABLE statement; only adds
schema versionAn option (pagesco_books_db_version) compared with the code's DB_VERSION
block.jsonA block type's metadata: name, title, attributes, supports, files
edit / saveThe editing view (React) / the function that returns the stored HTML
@wordpress/scriptsWordPress's build tool (webpack, Babel, Sass, dependency extraction)
index.asset.phpThe built script's dependency handles and version hash
blocks manifestbuild/blocks/blocks-manifest.php: every block.json as one PHP array

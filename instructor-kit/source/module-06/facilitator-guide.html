Session 6: The Loop and Custom Queries

How to teach Module 4's first two lessons. Build pagesco-classic and show what a classic template really does: walk the posts the main query already found, with template tags printed or returned, parts and conditional tags. Then ask for lists of your own: secondary queries and their three numbers, the reset that keeps template tags honest, pre_get_posts with guards, and pagination that never ends in a 404.

The #1 risk of Session 6: the bugs are quiet

Every mistake in these two lessons produces no message: a title before an empty heading, a template part that is not found, a page-2 link that 404s, navigation computed for the wrong post, a callback that changes every query on the site. Learners who only watch for errors will miss all of them. In the room: for every demo step ask "which query is this, and has it run yet?" and make learners compare what they see with what they expected. After: the self-check and the two debug handouts are built from exactly these quiet bugs.

Warm-up answers
  1. W1 Theme pattern or synced pattern: which one is a post in the database, and why does a theme never ship one? Answer: The synced pattern: a wp_block post referenced by ID, and IDs differ on every site (Lesson 3.3).
  2. W2 Two JSON files in styles/: what makes one a section style and the other a style variation? Answer: The blockTypes key: with it, a section style for the listed blocks; without it, a look for the whole site.
  3. W3 A child theme is active. What do the template and stylesheet options hold? Answer: template = the parent's folder, stylesheet = the child's (Lesson 3.4).
  4. W4 Why did the child's style.css not load until functions.php enqueued it, and why must a parent hook be removed on after_setup_theme? Answer: A block theme's style.css is a header file; CSS loads only when enqueued. The child's functions.php runs first, so the parent's hooks do not exist yet when it runs.

Mental model to say

"A customer hands the bookseller a list of books they ordered. The bookseller does not search the shop again; the list is done. They go down it one line at a time: is there another book on the list? (have_posts()) Take the next one off the pile and put it on the counter (the_post()). Read out its title, author and price (template tags). Start again. If they forget to take the next book off the pile, they read out the same title forever."

Then the request on the board: URL → query vars → the main query → the template → the Loop. "The template never asks which posts. It only walks the list." And the two-halves rule for template tags: the_ prints HTML-ready text, get_ returns a value you escape for its spot.

Three mistakes to expect, and how to coach each
  • Concatenating a tag that prints. Coach: "Does this function print or return? Then what does the string contain?" (Self-check Q3; debug_loop_report.php.)
  • Forgetting the_post(). The page hangs for 30 seconds. Coach: "Who moves the list on?" (Self-check Q6.)
  • Conditional tags too early. In a must-use plugin's top level, or in functions.php outside a callback. Coach: "Has the main query run yet? Which hook comes after it?" (Self-check Q5.)

Custom Queries

80 min
Objectives (from the lesson page)
  • Tell the main query from secondary queries, and pick WP_Query, get_posts() or pre_get_posts for a task
  • Write WP_Query arguments for post types, categories, authors, dates, searches, ordering and limits, and read found_posts and max_num_pages
  • Run a secondary Loop on the same page as the main one and restore the current post with wp_reset_postdata()

Mental model to say

"The main query is the customer's order at the counter: they asked for News, so they get News, and the whole page is organized around it. Secondary queries are the displays next to the counter, staff picks, you might also like; they never change the order. And when you want the order itself to be different, news in bundles of three, you do not grab the receipt after it is printed; you tell the person taking orders before they write it down. That is pre_get_posts."

Then the decision table on the board, with one question per row: does it change the page's own list? pre_get_posts. Is it an extra list with template tags? new WP_Query, then wp_reset_postdata(). Do you only need the data? get_posts(). query_posts() gets a line through it.

$pagesco_query = new WP_Query(

		'category_name'  => 'news',

printf(

Checks for understanding

  • What do post_count, found_posts and max_num_pages mean? Answer: on this page; in total; pages of this size.

Exit ticket (3 questions, no notes, 4 minutes)

Put the three questions on the slide. Question 3's pile tells you whether Session 7's warm-up needs the order-taker picture again.

  1. In one sentence: what does the Loop do, and what does the_post() do inside it? Answer: it walks the posts the main query already found; the_post() moves to the next one and sets the global $post the template tags read.
  2. Name a template tag pair and say when you use each half. Answer: for example the_title() / get_the_title(): the_ prints HTML-ready text; get_ returns a value you escape yourself, for attributes, strings or further processing.

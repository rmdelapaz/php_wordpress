Lessons

4.1

The Loop & Template Tags

By the end you can
  • Explain what the Loop does with the main query, step by step, and write it correctly with have_posts() and the_post()
  • Use template tags and their the_ / get_ pairs, and choose between printing and returning (and escaping) a value
  • Split a classic theme into header.php, footer.php and template parts with get_template_part(), including passing arguments
  • Use conditional tags such as is_home(), is_singular() and is_search(), and say when they work and when they are called too early
  • Build pagesco-classic with index.php, singular.php and 404.php, and turn it into a hybrid theme with theme.json
Key ideas
  • The main query runs before any template and lives in $wp_query; a classic template only walks its result: if ( have_posts() ) { while ( have_posts() ) { the_post(); ... } }, even on single posts.
  • the_post() moves to the next post and sets the global $post every template tag reads; without it the Loop never ends.
  • Template tags come in pairs: the_title() prints HTML-ready text, get_the_title() returns it for you to escape (esc_attr(), esc_url(), esc_html()); the_title_attribute() for attributes. get_the_content() is raw; the_content() renders blocks. the_date() prints once per day.
  • Parts: get_header(), get_footer(), get_template_part( $slug, $name, $args ) through locate_template() (child first); no .php in the slug; false = not found.
  • Conditional tags (is_home(), is_singular( 'post' ), is_page( 'about' ), is_archive(), is_search(), is_404() ...) read the main query: from template_redirect on, never at a plugin's top level.
  • A classic theme with a theme.json is a hybrid: presets and global styles, but no styles.css custom CSS.

4.2

Custom Queries

By the end you can
  • Tell the main query from secondary queries, and pick WP_Query, get_posts() or pre_get_posts for a task
  • Write WP_Query arguments for post types, categories, authors, dates, searches, ordering and limits, and read found_posts and max_num_pages
  • Run a secondary Loop on the same page as the main one and restore the current post with wp_reset_postdata()
  • Change the main query with a pre_get_posts callback guarded by is_main_query() and is_admin()
  • Paginate lists with the_posts_pagination(), and explain why paging a custom query in a template leads to a 404
Key ideas
  • One main query per request; every other list is a secondary query you create: new WP_Query( $args ) runs at once.
  • Loop over your object ($q->have_posts(), $q->the_post()) and finish with wp_reset_postdata(). get_posts() returns an array and needs no reset.
  • post_count (this page), found_posts (total), max_num_pages; no_found_rows skips the count for lists you never paginate.
  • pre_get_posts changes the main query before it runs. Guard it: is_admin(), $query->is_main_query(), the query's own conditionals. It is an action: $query->set().
  • the_posts_pagination() paginates the main query; paging a custom query in a template ends in 404s.
  • Argument pairs (cat / category_name, author / author_name, p / name) fail silently with the wrong kind of value. query_posts() is for old tutorials only.

Glossary

TermMeaning
main queryThe one WP_Query WordPress runs from the URL, in $wp_query; templates and conditional tags work from it
the Loopwhile ( have_posts() ) { the_post(); ... }: walks the main query's posts
template tagA function about the current post: the_ prints, get_ returns
template partA piece of a classic theme loaded with get_template_part(), get_header() or get_footer()
conditional tagA yes/no function about the request (is_home(), is_singular() ...), reliable after the main query
hybrid themeA classic theme with a theme.json
secondary queryA new WP_Query( $args ) your code creates
wp_reset_postdata()Sets the global $post back to the main query's current post
pre_get_postsThe action that lets you change a query before it runs
found_posts / max_num_pagesThe total number of matches / pages of the current size

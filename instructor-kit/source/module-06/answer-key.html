4.1 · The Loop & Template Tags: self-check

Q1
A classic theme has only index.php, singular.php and 404.php. Which file draws /author/maria/?
A) singular.php
B) index.php, with a Loop over Maria's posts
C) author.php, which WordPress generates
D) 404.php, because there is no author template
Why: The hierarchy for an author archive is author-{nicename}, author-{id}, author, archive, then index (Lesson 3.1). With none of the specific files, index.php runs, and its Loop walks whatever the main query found: Maria's two posts. That is why one index.php can draw every list.
A is wrong: singular.php is for one post or page.
C is wrong: WordPress never generates templates.
D is wrong: 404 is only for requests whose main query finds nothing at all.
Q2
On the course site, what does this print, and why?
wp eval 'var_dump( is_home(), get_the_title() );'
bool(false) and string(0) "": WP-CLI loads WordPress but runs no main query, so is_home() has nothing to answer from and there is no current post for get_the_title()
Why: Conditional tags and template tags read the main query and the global $post, which only a front-end request (or wp(), as the session's debug handouts do) fills. In a template both would work.
Q3
Inside the Loop you need the post's title in a link's title attribute and as the link text inside an h2. Which pair is right?
A) title="<?php the_title(); ?>" and echo '<h2>' . the_title() . '</h2>';
B) title="<?php echo get_the_title(); ?>" and the_title( '<h2>', '</h2>' );
C) title="<?php echo esc_html( the_title() ); ?>" and the_title();
D) title="<?php the_title_attribute(); ?>" and the_title( '<h2>', '</h2>' );
Why: the_title() prints text prepared for HTML, not for an attribute; the_title_attribute() (or esc_attr( get_the_title() )) is the attribute version. the_title() with $before and $after wraps itself; concatenating it into a string prints the title first and an empty h2 after it (Lesson 4.1, Common Mistakes 1).
A is wrong: Both halves are wrong: an unescaped attribute, and the concatenation mistake.
B is wrong: The h2 is right; the attribute is not escaped for its context.
C is wrong: the_title() prints and returns nothing, so esc_html() escapes an empty value after the title is already out.
Q4
get_template_part( 'template-parts/content.php' ); prints nothing, and there is no message. Why?
A) It looked for template-parts/content.php.php, found nothing and returned false
B) Template parts only work inside the Loop
C) Template parts must be in the theme's root folder
D) It found the file but needs a third argument with the post
Why: get_template_part() adds .php itself and goes through locate_template() (child first, then parent). A missing file is not an error: the function returns false, a found file null. var_dump() its return value when a part seems to print nothing.
B is wrong: Parts can run anywhere; content.php just uses template tags, which need a current post.
C is wrong: Any path relative to the theme works.
D is wrong: $args is optional (WordPress 5.5+).
Q5
A plugin must do something only on single posts and pages. Which is the EARLIEST of these hooks on which is_singular() gives the right answer?
A) plugins_loaded
B) init
C) template_redirect
D) wp_footer
Why: Conditional tags read the main query, which runs after init (wp() in the request order, Lesson 2.2). template_redirect fires after the query and before the template, which is why the lesson's conditions tool logs there. wp_footer works too, but much later.
A is wrong: Before the query: the tag returns false, with a "called incorrectly" notice.
B is wrong: Still before the query.
D is wrong: It works, but it is not the earliest; by then the page is printed.
Q6
singular.php shows only one page. Why does it still use while ( have_posts() ) { the_post(); ... }?
The main query holds exactly one post, and the_post() is what sets the global $post that every template tag reads (and fires loop_start / loop_end for plugins)
Why: On a single post or page the Loop has one item. Skipping it leaves template tags without a current post, and plugins that hook into the Loop never see it.

4.2 · Custom Queries: self-check

Q7
On the site at the end of Lesson 4.1: what does this print, and why the second number?
wp eval '$q = new WP_Query( array( "post_type" => "page", "posts_per_page" => 2, "no_found_rows" => true ) ); echo $q->post_count, " ", $q->found_posts, "\n";'
2 0: two pages loaded; found_posts is 0 because no_found_rows skips the counting query
Why: no_found_rows is right for a list you will not paginate (Lesson 4.2's query-args demo). Without it found_posts would be the four published pages.
Q8
A pre_get_posts callback reads if ( is_home() ) { $query->set( 'posts_per_page', 3 ); } and nothing else. What goes wrong?
A) Nothing: is_home() makes sure only the blog home changes
B) Every other WP_Query that runs on the blog home (a box, a widget, a block) is also cut to three posts
C) It is a filter, so it must return $query
D) The admin's Posts screen breaks, but the front end is fine
Why: The callback runs for every WP_Query. The global is_home() describes the request, not the query being built, so secondary queries on the blog home pass the test too. Guard with is_admin(), $query->is_main_query() and the query's own $query->is_home() (Lesson 4.2).
A is wrong: It checks the request, not which query is about to run.
C is wrong: pre_get_posts is an action: the object is changed in place.
D is wrong: is_home() is false in the admin, so the admin is not the problem here.
Q9
A query with 'posts_per_page' => 3 matches 7 posts. On page 3, what are post_count, found_posts and max_num_pages?
A) 1, 7, 3
B) 3, 7, 3
C) 1, 3, 7
D) 3, 3, 3
Why: post_count is what this page holds (7 = 3 + 3 + 1), found_posts the total match, max_num_pages ceil(7 / 3). The session's query_shelf lab prints all three for every query.
B is wrong: Page 3 holds only the remainder.
C is wrong: found_posts and max_num_pages are swapped.
D is wrong: found_posts is the total, not the page size.
Q10
In which case does your code need NO wp_reset_postdata()?
A) After a WP_Query Loop at the end of a template part
B) After a secondary Loop inside the main Loop of singular.php
C) After a secondary Loop in front-page.php, before the main Loop
D) After get_posts(), when each WP_Post is passed to the functions you call (get_the_title( $post ))
Why: Only $query->the_post() (and setup_postdata()) replaces the global $post. get_posts() returns an array and leaves the global alone, as long as you pass each post along instead of calling setup_postdata() (Lesson 4.2, "get_posts() needs no reset").
A is wrong: Somebody will add a template tag after your part one day; reset.
B is wrong: That is exactly the broken post navigation of Common Mistakes 2.
C is wrong: The main Loop's first the_post() sets the post again, but tags between the two Loops would talk about the wrong post: reset anyway.
Q11
An old template starts with query_posts( 'cat=2&posts_per_page=5' );. How do you translate it?
A) Keep it, and call wp_reset_query() at the end
B) Replace it with get_posts() and the same string
C) If it changes the page's main list: pre_get_posts on the main query (category_name, posts_per_page); if it adds a list: new WP_Query plus wp_reset_postdata()
D) Move it into functions.php so it runs earlier
Why: query_posts() throws the main query away and runs a second one, so pagination and conditional tags disagree with what is shown; its own documentation says not to use it (Lesson 4.2 FAQ).
A is wrong: The reset only cleans up after the damage.
B is wrong: get_posts() returns data; it does not change what the template's Loop shows.
D is wrong: query_posts() in functions.php runs before the main query exists and breaks more.
Q12
Module 5 brings a Book post type. The shop wants (a) a "three newest books" box under every post and (b) 12 books per page on /books/. Which tool for each?
(a) a secondary WP_Query (or get_posts()) with posts_per_page 3, plus wp_reset_postdata() after a Loop; (b) pre_get_posts on the main query (is_post_type_archive( 'book' ), posts_per_page 12)
Why: Extra lists are secondary queries; the page's own list is the main query, changed before it runs so that pagination and the 404 decision agree (the lesson's decision table and journal prompt).

4.2 · Custom Queries: predict, then run

P3
Predict the output, then run it.
wp eval '$q = new WP_Query( array( "category_name" => "news", "posts_per_page" => 2 ) ); echo $q->post_count, " ", $q->found_posts, " ", $q->max_num_pages, "\n";'
2 3 2
Why: post_count 2 (this page), found_posts 3 (all News posts), max_num_pages 2 (ceil(3 / 2)).
P4
Predict the output, then run it.
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/page/2/
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/category/news/page/2/
200
404
Why: The home page's main query has three per page (pre_get_posts), so its page 2 exists; the News archive still has ten per page and three posts, so its page 2 does not, and WordPress answers 404 before any template runs.

The Lesson Pages' Own Quick Quizzes

Lesson 4.1 · The Loop & Template Tags
  1. C Dune<p></p>: PHP evaluates the expression first: the_title prints Dune and returns null, then echo prints the empty paragraph. Inside a string use get_the_title with esc_html.
  2. A the_title_attribute(), or esc_attr( get_the_title() ): the_title_attribute prints the title escaped for an attribute; esc_attr( get_the_title() ) is the returning equivalent. the_title prepares HTML text, not attribute values.
  3. B index.php: The search chain is search, then index. A search is not an archive, so archive.php is never a candidate and index.php draws it.
  4. C It returns false, and WordPress notices that it was called incorrectly: The main query has not run when must-use plugins load, so conditional tags return false, and with WP_DEBUG on WordPress reports that they were called incorrectly. Ask on template_redirect instead.
  5. A template-parts/content-none.php: The name is joined to the slug with a hyphen: template-parts/content-none.php, looked up in the child theme and then the parent. Only if it is missing does WordPress fall back to template-parts/content.php.
Lesson 4.2 · Custom Queries
  1. A A pre_get_posts callback that sets posts_per_page to 5 when the main query is_category( 'news' ): Changing the main query before it runs keeps the 404 decision, the template, the conditional tags and the_posts_pagination in agreement.
  2. B The title of the last post of the secondary Loop: Each the_post() of the secondary query replaced the global post, so the last post of that Loop is still current until wp_reset_postdata() restores the main query's post.
  3. C 4, 10, 3: post_count is the 4 posts on this page, found_posts the 10 that match in total, and max_num_pages is 10 divided by 4, rounded up: 3.
  4. C is_admin(): Admin list screens run a main query too, so is_main_query alone does not exclude them; is_admin() returns early for every admin request.
  5. B All four published posts, without any warning: cat takes category IDs; the string news is not one, so the filter is dropped silently and every published post comes back. category_name takes the slug.

Exit Ticket

  1. The Loop walks the posts the main query already found; the_post() moves to the next one and sets the global $post (and fires loop_start the first time).
  2. A pair: the_title() prints HTML-ready text for the page; get_the_title() returns the value, for an attribute (with esc_attr()), a string, or a comparison. Same for the_permalink() / get_permalink() (esc_url()) and the_date() / get_the_date() (esc_html()).
  3. Three per page: a pre_get_posts callback in functions.php (or a plugin), returning early on is_admin() or ! $query->is_main_query(), then if ( $query->is_home() ) $query->set( 'posts_per_page', 3 );.

Common Wrong Answers and What They Reveal

  • Q1 C. Believes WordPress makes missing templates. Show the hierarchy falling through to index.php.
  • Q3 B. Knows the_title( $before, $after ) but not that attributes need their own escaping.
  • Q5 A or B. Mixes up "WordPress is loaded" and "the main query has run". Redraw the request order.
  • Q8 A. Thinks the global is_home() describes the query being built. Ask how many queries run on the blog home.
  • Q9 B. Confuses post_count with posts_per_page.
  • Q10 B or C. Thinks the reset is optional inside templates. Rerun the broken navigation.

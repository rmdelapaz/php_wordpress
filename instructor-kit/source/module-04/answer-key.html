Checkpoint 1 · Model Answer

The task is on the workbook's Checkpoint 1 page; the starter is labs/module-04/checkpoint-1/checkpoint_starter/pagesco-checkpoint.php. The model answer, labs/module-04/checkpoint-1/checkpoint_solution/pagesco-checkpoint.php:

<?php
/**
 * Plugin Name: Pages & Co. Checkpoint 1
 * Description: Checkpoint 1 (Modules 1 and 2), model answer: three small additions to the store notice and the footer.
 */

/**
 * (a) Adds the newest News post to the store notice.
 *
 * @param string $text The notice text so far (plain text).
 * @return string
 */
function pagesco_checkpoint_latest_news( $text ) {
	$posts = get_posts(
		array(
			'category_name' => 'news',
			'numberposts'   => 1,
		)
	);

	if ( ! $posts ) {
		return $text;
	}

	return $text . ' Latest news: ' . get_the_title( $posts[0] ) . '.';
}
add_filter( 'pagesco_store_notice', 'pagesco_checkpoint_latest_news', 30 );

/**
 * (b) Prints a link to Maria's author archive inside the notice bar.
 */
function pagesco_checkpoint_ask_link() {
	$user = get_user_by( 'login', 'maria' );

	if ( ! $user ) {
		return;
	}

	echo ' · <a href="' . esc_url( get_author_posts_url( $user->ID ) ) . '">' . esc_html( 'Ask ' . $user->display_name ) . '</a>';
}
add_action( 'pagesco_store_notice_end', 'pagesco_checkpoint_ask_link', 20 );

/**
 * (c) Prints the number of published pages in the footer.
 */
function pagesco_checkpoint_page_count() {
	global $wpdb;

	$count = (int) $wpdb->get_var(
		$wpdb->prepare(
			"SELECT COUNT(*) FROM {$wpdb->posts} WHERE post_type = %s AND post_status = %s",
			'page',
			'publish'
		)
	);

	echo '<p class="pagesco-pages">Published pages: ' . esc_html( $count ) . '</p>';
}
add_action( 'wp_footer', 'pagesco_checkpoint_page_count' );

3.1 · Theme Anatomy & the Template Hierarchy: self-check

Q1
Twenty Twenty-Five is active. Which candidate list does WordPress build for the About page, /about/ (page ID 12)?
A) about, page, index
B) page-about, page-12, page, singular, index
C) single-page-about, single-page, single, singular, index
D) page-12, page-about, page, index
Why: Pages go slug first, then ID, then page, singular and index; Lesson 3.1's template-map log shows exactly page-about.php, page-12.php, page.php and then the fall-through to singular and index.
A is wrong: Hierarchy names are type-slug, never the slug alone.
C is wrong: single-{type}-{slug} is the chain of posts and custom post types; pages have their own.
D is wrong: The slug comes before the ID, and singular is missing.
Q2
What does this print on the course site?
wp eval 'echo implode( ", ", get_template_hierarchy( "author-devon" ) ), "\n";'
author-devon, author, archive, index
Why: Devon is user 3, but get_template_hierarchy() works from the slug alone, so the ID-based name author-3 that a real request adds is missing (Lesson 3.1, Exercise 1). Every archive passes through archive; every list ends in index.
Q3
A client's classic theme has wp_head() in header.php and wp_footer() in footer.php, but no wp_body_open(). What happens to the Pages & Co. store notice?
A) A PHP warning names the missing function
B) WordPress calls wp_body_open itself, as it does for block themes
C) The notice moves to the footer
D) It disappears, with no message anywhere
Why: pagesco-site.php adds its callback to wp_body_open, and in a classic theme only the theme fires that action. Nobody fires it, so nothing is printed and nothing is wrong as far as PHP knows (Lesson 3.1, Common Mistakes 3).
A is wrong: A hook that never fires is not an error.
B is wrong: Only template-canvas.php, for block themes, fires it on the theme's behalf.
C is wrong: A callback runs only on the hook it was added to.
Q4
Every function in Twenty Twenty-Five's functions.php is wrapped in if ( ! function_exists( ... ) ). Why?
A) So a child theme can define a function of the same name first and replace it
B) So WordPress can load functions.php twice
C) PHP 8.5 requires it for theme functions
D) So the functions run only in the block editor
Why: A child theme's functions.php is loaded BEFORE its parent's. If it defines twentytwentyfive_editor_style(), the parent skips its own: that is how a theme someone else maintains is customized without editing it (Lesson 3.4).
B is wrong: Loading it twice would still be a mistake; the guard is about replacing, not repeating.
C is wrong: PHP has no such rule; redeclaring a function is simply a fatal error.
D is wrong: function_exists() says nothing about where code runs.
Q5
Settings > Reading shows the latest posts on the front page. The theme has front-page.html, home.html and index.html. Which template draws http://localhost:8080/?
A) home.html
B) index.html
C) front-page.html
D) The theme cannot have both front-page.html and home.html
Why: The front page's list is front-page, home, index: front-page comes first whatever the front page shows. home is only the list of latest posts, used here when the theme has no front-page.
A is wrong: home would win only without a front-page template.
B is wrong: index is the last resort.
D is wrong: Both are normal: front-page for the front page, home for the blog index wherever it lives.
Q6
Name the filter that changes the list of candidate templates for category archives, before WordPress looks for files.
category_template_hierarchy
Why: Each type has its own {$type}_template_hierarchy filter (template.php line 62); Lesson 3.1's template-map tool hooks all eighteen. template_include is the other hook: it filters the final file path, after the choice.

3.2 · Building a Block Theme: self-check

Q7
On the course site after Lesson 3.2 (pagesco active), what does this print?
wp eval 'echo wp_get_global_settings( array( "layout", "wideSize" ) ), "\n";'
1180px
Why: wp_get_global_settings() reads the merged theme.json data (core, theme, Site Editor) by path: settings.layout.wideSize is pagesco's 1180px. Code that needs a design value asks for it instead of repeating the number.
Q8
In theme.json, "fontSize": "var:preset|font-size|large" under styles. What does WordPress print in the page's CSS?
A) font-size: large
B) font-size: 1.75rem
C) font-size: var(--wp--preset--font-size--large)
D) font-size: var(--large)
Why: The shorthand points at the preset, and the preset is a CSS custom property, so a style variation or the Styles panel can change the size in one place. Lesson 3.2's body rule shows the same for colors: background-color: var(--wp--preset--color--paper).
A is wrong: That would be the CSS keyword large, not your preset.
B is wrong: The value is never copied in: that is the point of presets.
D is wrong: Custom properties from theme.json always carry the --wp--preset--TYPE-- prefix (here --wp--preset--font-size--).
Q9
Which of these blocks is written SELF-CLOSING in a template file, with no HTML of its own?
A) Group
B) Heading
C) Paragraph
D) Post Title
Why: Post Title is dynamic: PHP renders it on every request from the post being viewed, so the file holds only <!-- wp:post-title {"level":1} /-->. Group, Heading and Paragraph are static: their exact saved HTML sits between the comments.
A is wrong: Group is static: its <div> (or <main>) is in the file.
B is wrong: Heading is static, with its <h1> in the file.
C is wrong: Paragraph is static, with its <p> in the file.
Q10
A live site (WP_DEBUG off) gets a theme.json with a trailing comma. What do visitors see?
A) The site in core's default design: the theme's colors, fonts and sizes are gone, with no message
B) A critical error page
C) The notice wp_json_file_decode(): Syntax error at the top of every page
D) Nothing changes: WordPress skips the bad line
Why: WordPress cannot parse the file, so it uses no theme.json at all (zero oxblood variables in Lesson 3.2's Mistake 1). The Notice exists, but only with WP_DEBUG on, in the page and in debug.log. The notice names the file, not the line: $schema in VS Code finds it.
B is wrong: It is a Notice, not a fatal error: the page still renders.
C is wrong: Only with WP_DEBUG and WP_DEBUG_DISPLAY on, as on the course site.
D is wrong: JSON is parsed as a whole; one syntax error loses the whole file.
Q11
A template contains <!-- wp:template-part {"slug":"footer","tagName":"footer"} /-->. Which file of the theme does it include, and what does the tagName do?
parts/footer.html; it wraps the part in a <footer> element (the contentinfo landmark)
Why: The slug is the file name in parts/ without .html (a typo such as heder renders nothing for visitors). tagName gives screen-reader users the header, main and footer landmarks; Lesson 3.2 checks them with curl.
Q12
What does "defaultPalette": false in settings.color do?
A) Deletes the theme's own palette
B) Hides WordPress's own palette from the editors, so they choose from the theme's colors
C) Turns off all color controls
D) Removes --wp--preset--color--black and --white from the page
Why: The editors then offer only Paper, Ink, Oxblood, Sage and Slate. Core still prints black and white as custom properties (Lesson 3.2's preset grep shows both). Turning off the free color picker is a different setting, custom: false (the lesson's quiz Q4).
A is wrong: Your palette is what remains.
C is wrong: Controls stay; only the default swatches go.
D is wrong: Both are still printed: the lesson's output starts with them.

3.2 · Building a Block Theme: predict, then run

P3
Predict the output, then run it.
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/nothing-here/
404
Why: pagesco's 404.html draws the page, and WordPress still answers with status 404 so search engines do not index it. Lesson 3.2's verification loop checks exactly this.
P4
Predict the output, then run it.
curl -s http://localhost:8080/ | grep -o '\.has-oxblood-color{[^}]*}'
.has-oxblood-color{color: var(--wp--preset--color--oxblood) !important;}
Why: Every palette color produces a class rule using its custom property, with !important so a color chosen for one block beats the theme's other rules.

The Lesson Pages' Own Quick Quizzes

Lesson 3.1 · Theme Anatomy & the Template Hierarchy
  1. A singular.html: The page chain is page-about, page-12, page, singular, index. The theme has no page template, so the first match is singular.html.
  2. C A hybrid: PHP templates plus a theme.json: No templates/index.html, so it is not a block theme, but it has a theme.json: a classic theme with block features, a hybrid.
  3. B page.html: There is no front-page.html, and with a static front page WordPress follows the page chain next, so page.html draws it.
  4. C Her save stored a copy as a wp_template post, and that copy wins over the file: Saving in the Site Editor stores a wp_template post with the source custom, and that copy wins over the theme file until it is reset.
  5. B add_filter( 'single_template_hierarchy', ... ) returning a changed array: single_template_hierarchy is the filter WordPress applies to the candidate list for single posts; a callback receives the array and returns the list to search.
Lesson 3.2 · Building a Block Theme
  1. B --wp--preset--color--oxblood: Every palette color becomes --wp--preset--color--SLUG in the global styles, which is what var:preset|color|oxblood stands for.
  2. A style.css and templates/index.html: style.css carries the theme header and templates/index.html is the template every request can fall back to. theme.json and functions.php are optional.
  3. C The page without a footer, and no message: The Template Part block finds no part with that slug and renders nothing. Only logged-in users see a hint, so check slugs while logged in.
  4. A In settings.color: the palette, plus custom set to false: What the editors offer is a setting: settings.color.palette lists the colors and settings.color.custom set to false removes the free picker.
  5. B Decide which version is right, then reset or delete the saved copy (exporting it first if it should be kept): The post is a Site Editor copy that wins over the file. Reset it in the Site Editor or delete it with wp post delete ID --force, after exporting it if the owner's change should be kept.

Exit Ticket

  1. archive.html. The candidates are author-maria, author-2, author, archive, index; the theme has none of the first three, so archive answers. (index would answer only without archive.)
  2. Palette: settings.color.palette (what editors may choose from). Background: styles.color.background, written var:preset|color|paper so it follows the preset.
  3. Two of: a template-part slug that matches no file in parts/ (silent for visitors; logged in you see "Template part has been deleted or is unavailable"); a Site Editor copy (wp_template or wp_template_part post) that wins over the file. A JSON syntax error removes the styles, not the header.

Common Wrong Answers and What They Reveal

  • Q1 C (single-page-...). Applies the post chain to pages. Pages have their own chain; show the demo's log for /about/.
  • Q3 A (a warning). Expects PHP to complain about a hook nobody fires. A hook that never fires is silent by design.
  • Q5 A (home.html). The most common hierarchy mistake of all: home is the latest-posts list. front-page comes first.
  • Q8 B (1.75rem). Thinks presets are copied in. They are referenced: that is what makes style variations possible (Lesson 3.3).
  • Q10 B or C. Confuses the course site (WP_DEBUG on) with a live site. On a live site the design just goes plain.
  • Q12 D. Has not looked at the preset grep: black and white are always printed.

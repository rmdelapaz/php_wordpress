Lessons

3.1

Theme Anatomy & the Template Hierarchy

By the end you can
  • Explain what belongs in a theme and what belongs in a plugin, and where WordPress records which theme is active
  • Tell block, classic and hybrid themes apart by their files, and confirm it with wp_is_block_theme() and wp_theme_has_theme_json()
  • Find your way around a block theme: style.css, theme.json, templates/, parts/, patterns/, styles/ and functions.php in Twenty Twenty-Five
  • Predict which template WordPress uses for a URL, for block themes and classic themes, from the template hierarchy
  • Watch WordPress make that choice on a running site with the *_template_hierarchy filters and template_include
Key ideas
  • A theme owns presentation: content stays in the database, features in plugins; switching themes keeps both. The template and stylesheet options record the active theme.
  • Block themes: templates/*.html, parts/*.html, theme.json (true, true). Classic: PHP templates (false, false). Hybrid: classic plus theme.json (false, true).
  • Twenty Twenty-Five: style.css (the header), theme.json (settings and styles), templates/, parts/, patterns/ (3.3), styles/ (3.3), functions.php (hooks, 4.3). Read it; never edit it.
  • The template hierarchy: a candidate list from most specific to index; the first file the theme has wins. Slugs, not titles; posts include the post type (single-post-hello-world).
  • front-page = the site's front page, whatever it shows; home = the list of latest posts.
  • Block templates are rendered by core's template-canvas.php, which calls wp_head(), wp_body_open() and wp_footer(); a classic theme must call them itself.
  • Tools: get_template_hierarchy(), get_block_templates(), the {$type}_template_hierarchy and template_include filters; Site Editor saves are wp_template posts that win over files.
Worked example: block or classic, without switching

Lesson 3.1 asked the ACTIVE theme what kind it is. You can ask any installed theme without switching to it. First its files (in the WP-CLI container shell):

ls -1 wp-content/themes/twentytwentythree
assets
parts
patterns
readme.txt
screenshot.png
style.css
styles
templates
theme.json

templates/ and theme.json, no index.php: a block theme, and no functions.php at all (Twenty Twenty-Three needs no PHP). WordPress agrees: wp_get_themes() returns a WP_Theme object per folder, and is_block_theme() checks for templates/index.html:

wp eval 'foreach ( wp_get_themes() as $slug => $t ) { printf( "%-18s block: %s\n", $slug, $t->is_block_theme() ? "yes" : "no" ); }'
twentytwentyfive   block: yes
twentytwentyfour   block: yes
twentytwentythree  block: yes

On a client site with ten themes installed, this one line tells you which are block themes before you switch to any of them.

3.2

Building a Block Theme

By the end you can
  • Write a theme header in style.css that WordPress reads and checks on activation
  • Define a design system in theme.json: settings (palette, fonts, sizes, spacing, layout) and styles (global, elements, blocks), and read the CSS WordPress generates from it
  • Write templates and template parts in block markup, combining static blocks with dynamic ones such as the Query Loop, Post Title and Post Content
  • Activate and verify a block theme with WP-CLI and the Site Editor, with site features such as the store notice still working
  • Diagnose an invalid theme.json, a missing template part and a Site Editor copy that overrides your file
Key ideas
  • Two files make a block theme: style.css (the header WordPress reads and checks on activation: Requires at least, Requires PHP) and templates/index.html.
  • theme.json settings = what is available (palette, font families and sizes, spacing, layout widths, controls); styles = what is applied (the page, elements, single block types).
  • Every preset becomes a custom property and classes: oxblood → --wp--preset--color--oxblood, .has-oxblood-color; var:preset|color|oxblood in theme.json. Use presets, never hex values.
  • Static blocks carry their exact HTML in the file; dynamic blocks (Site Title, Navigation, Query Loop, Post Title, Post Content) are self-closing and rendered by PHP.
  • Template parts live in parts/ and are included by slug; tagName gives the header, main and footer landmarks.
  • Quiet failures: a JSON syntax error drops the whole theme.json (a Notice only with WP_DEBUG); a wrong part slug renders nothing for visitors; a Site Editor copy wins over your file.
Worked example: from a preset to a class to the CSS

On your site after Lesson 3.2: follow the footer's dark band from the template part to the page. The part asks for presets by slug:

grep -o '"backgroundColor":"ink","textColor":"paper"' wp-content/themes/pagesco/parts/footer.html
"backgroundColor":"ink","textColor":"paper"

WordPress turns the attributes into classes on the Group's <div>:

curl -s http://localhost:8080/ | grep -o '<div class="wp-block-group alignfull has-paper-color has-ink-background-color[^"]*"'
<div class="wp-block-group alignfull has-paper-color has-ink-background-color has-text-color has-background has-link-color wp-elements-1 has-global-padding is-layout-constrained wp-block-group-is-layout-constrained"

and prints one rule per palette color, pointing at the custom property:

curl -s http://localhost:8080/ | grep -o '\.has-ink-background-color{[^}]*}'
.has-ink-background-color{background-color: var(--wp--preset--color--ink) !important;}

Three steps, one name: ink. Change the color of ink in theme.json (or let a style variation do it in Lesson 3.3) and the footer follows, because no file contains #1f2a2e except theme.json. The !important makes a color chosen for one block beat every other rule.

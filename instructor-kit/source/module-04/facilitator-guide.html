Session 4: Theme Anatomy and Building a Block Theme

How to teach Session 4: a ten-minute warm-up and Checkpoint 1 on Modules 1 and 2 (a 30-minute individual must-use plugin task with a five-row rubric), then Twenty Twenty-Five taken apart and the template hierarchy logged on a running site, and the birth of pagesco: the smallest block theme, a theme.json design system and the CSS it generates, a header part, two quiet mistakes, a book-fair theme lab and the start of the pagesco project.

How to Use This Guide

  • Same rhythm for both lessons: frame (one mental model) → live demo (you type, they type along) → guided lab (a kit lab, new practice) → start the lesson's own project. Exercises, quizzes, journals and the rest of each project are homework.
  • Session 4 is a checkpoint session: the first 40 minutes are a short warm-up and Checkpoint 1 on Modules 1 and 2, so both lessons get less room time than usual. The cuts are planned below; do not let the checkpoint run over.
  • Every command below was run to produce the output printed under it, on WordPress 7.1.3, PHP 8.5, MySQL 9.7 and WP-CLI 2.12, on the site exactly as the lessons leave it: the checkpoint and Lesson 3.1 on the site of Lesson 2.3, Lesson 3.2 on the site of Lesson 3.1. What it checks

One small must-use plugin that uses every Module 1 and 2 skill at once: callbacks hooked by name with priorities, a filter that returns (2.3), Lesson 2.3's own custom hooks, WordPress functions that take an arguments array (1.3), the content model (posts in a category, a user and her author archive, 2.1), a prepared $wpdb query on the posts table (2.2), escaping at output and the pagesco_ prefix (1.3). Nothing from Module 3 is tested.

Theme Anatomy & the Template Hierarchy

Objectives (from the lesson page)
  • Explain what belongs in a theme and what belongs in a plugin, and where WordPress records which theme is active
  • Tell block, classic and hybrid themes apart by their files, and confirm it with wp_is_block_theme() and wp_theme_has_theme_json()

Mental model to say

"Pages & Co. moves into a newly decorated shop. The books (content) and the till system (plugins) move across unchanged; the shelving, the signs, the paint (the theme) are new. A good fit-out can be replaced next year without losing a single book. That is the test for where code belongs: would we keep this after a redesign? Then it is a plugin."

Then the three kinds, on the board: block = templates/*.html + theme.json (true, true); classic = PHP templates (false, false); hybrid = classic plus a theme.json (false, true; not an official name). "You will meet all three on client sites for years."

Then the information desk: "A customer asks for Dune. The bookseller checks the most specific place first: a display for this book? a shelf for Frank Herbert? the science fiction section? Every shop has general shelves: in WordPress that is index, and every theme must have it." Write most specific first, the first one the theme has wins, index last.

Three mistakes to expect, and how to coach each
  • "home means the home page." Coach with the log from the demo and one question: "What does the front page show today, posts or a page?" home is the list of latest posts, wherever it lives. (Self-check Q5, lesson quiz Q3.)
  • Titles instead of slugs, or the type missing. page-About Us, single-hello-world. Coach: "Where would WordPress get that name from?" The slug, and posts include their post type. (Self-check Q1.)
  • Editing Twenty Twenty-Five to try something. Coach: "Who updates that folder?" Read it, never edit it; experiments go in a throwaway theme of their own, as in the project's Steps 2 to 5.

Checks for understanding

Ask these out loud during the demo and the lab:

  • What makes a theme a block theme? Answer: a templates/index.html (wp_is_block_theme() is true); theme.json alone makes it hybrid.
  • Which file does WordPress include for a block theme's page? Answer: core's wp-includes/template-canvas.php, which renders the block template and calls wp_head, wp_body_open and wp_footer.
  • The News category gets its own design. Which file? Answer: templates/category-news.html (slug before ID); every other category still falls through to archive.
  • A Site Editor save on a template: where does it go? Answer: a wp_template post with source custom, which wins over the file.

3.2

Building a Block Theme

70 min
Objectives (from the lesson page)
  • Write a theme header in style.css that WordPress reads and checks on activation
  • Define a design system in theme.json: settings (palette, fonts, sizes, spacing, layout) and styles (global, elements, blocks), and read the CSS WordPress generates from it
  • Write templates and template parts in block markup, combining static blocks with dynamic ones such as the Query Loop, Post Title and Post Content
  • Activate and verify a block theme with WP-CLI and the Site Editor, with site features such as the store notice still working
  • Diagnose an invalid theme.json, a missing template part and a Site Editor copy that overrides your file

Mental model to say

"Designing a shop interior, you write a style guide first (the colors, the typefaces, the spacing), then floor plans for each room, then the signs you hang at every entrance. A block theme has the same three layers: theme.json is the style guide, templates are the floor plans, template parts are the signs. Change the style guide and every room follows."

Then the two halves of theme.json, side by side on the board: settings = what is available (the palette, font sizes, spacing steps, widths, which controls editors see); styles = what is applied (the page, elements such as links and headings, single block types), usually by pointing at a preset. And the file list from the template map: style.css, theme.json, two parts, six templates, no functions.php.

Three mistakes to expect, and how to coach each
  • Hex values in templates. "style":{"color":{"background":"#e3eadf"}} copied from somewhere. Coach: "What happens when the shop rebrands?" Presets: "backgroundColor":"sage". (Self-check Q8, the journal prompt.)
  • Hand-edited static markup that the editor calls invalid. Coach: "Build it in the Site Editor, open the Code editor, copy the markup" (the lesson's tip), and never save there for real in this course: a save makes a copy.
  • "My change does nothing." Three quiet causes, in this order: a JSON syntax error (debug.log), a slug that matches no file (look logged in), a Site Editor copy (wp post list --post_type=wp_template,wp_template_part). (Self-checks Q10 and Q11, lesson quiz Q5.)

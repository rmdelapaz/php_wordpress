7.2 · Custom REST Endpoints: self-check

Q1
A route registers 'methods' => WP_REST_Server::CREATABLE. Which HTTP method does that endpoint answer?
A) GET
B) POST
C) POST, PUT and PATCH
D) DELETE
Why: READABLE is GET, CREATABLE POST, EDITABLE 'POST, PUT, PATCH', DELETABLE DELETE. The constants say what you mean; the events route uses READABLE and CREATABLE on one route.
A is wrong: That is READABLE.
C is wrong: That is EDITABLE.
D is wrong: That is DELETABLE.
Q2
On the course site after Lesson 7.2 (Books per list = 6, eleven books): what does this print?
wp eval '$r = rest_do_request( new WP_REST_Request( "GET", "/pagesco/v1/books" ) ); echo $r->get_status(), " ", count( $r->get_data() ), " ", $r->get_headers()["X-WP-TotalPages"], "\n";'
200 6 2
Why: rest_do_request() runs the route without HTTP: the same validation, permission check and callback. per_page defaults to the Books per list setting (6), so six books and two pages.
Q3
An anonymous client POSTs to /pagesco/v1/events WITHOUT a title. Which answer does it get first?
A) 400 rest_missing_callback_param: arguments are validated before the permission check
B) 401 rest_forbidden: the permission check comes first
C) 500: the callback fails on a missing title
D) 201: the event is created without a title
Why: The order is validate, sanitize, permission, callback. A missing required argument stops the request at the first desk, before anyone asks who the client is (the predict item P2 shows it with rest_do_request()).
B is wrong: Only once the arguments are valid.
C is wrong: The callback never runs.
D is wrong: required stops it.
Q4
Maria sends a bad starts_at AND a negative capacity. The answer names only starts_at. Why?
A) capacity is not validated
B) The schema stops at the first error it finds in alphabetical order
C) A negative capacity is turned into 0
D) validate_callbacks run first; the schema checks of the other arguments run in the sanitizing step, which a failed validation never reaches
Why: Lesson 7.2, Step 3: starts_at has a validate_callback; capacity's minimum is checked by the schema during sanitizing. Clients should expect errors one round at a time.
A is wrong: Fix the date and the capacity error comes next.
B is wrong: There is no alphabetical rule.
C is wrong: The schema refuses it; nothing is coerced.
Q5
Which permission_callback fits a route that DELETES events?
A) '__return_true': the callback checks the ID
B) 'is_user_logged_in'
C) A check of current_user_can( 'edit_others_posts' ) that returns a WP_Error with rest_authorization_required_code()
D) None: DELETE routes are protected by WordPress
Why: Every write needs a capability check as specific as the job; rest_authorization_required_code() gives 401 to nobody and 403 to a logged-in user who may not. The lesson's Exercise 3 reuses can_manage_events().
A is wrong: Anyone on the internet could delete events.
B is wrong: Any subscriber is logged in.
D is wrong: WordPress protects nothing you do not check (and warns when the key is missing).
Q6
GET /pagesco/v1/books/14 asks for the Events page (a page, not a book). Why does the answer say only "No book was found with that ID." and not "that is a page"?
An endpoint must not tell visitors what exists behind an ID they may not see: drafts, private books and other post types all get the same 404
Why: Leaking existence is information disclosure. get_book() requires a published book and answers one 404 for everything else.

7.2 · Custom REST Endpoints: predict, then run

P1
Predict the output, then run it.
curl -s 'http://localhost:8080/wp-json/pagesco/v1/books?per_page=0'; echo
{"code":"rest_invalid_param","message":"Invalid parameter(s): per_page","data":{"status":400,"params":{"per_page":"per_page must be between 1 (inclusive) and 100 (inclusive)"},"details":{"per_page":{"code":"rest_out_of_bounds","message":"per_page must be between 1 (inclusive) and 100 (inclusive)","data":null}}}}
Why: per_page has a minimum of 1: the schema refuses 0 with 400 before the callback runs, with the same message core's routes use.
P2
Predict the output, then run it.
wp eval '$r = rest_do_request( new WP_REST_Request( "POST", "/pagesco/v1/events" ) ); echo $r->get_status(), " ", $r->get_data()["code"], "\n";'
400 rest_missing_callback_param
Why: Validation comes before the permission check: the missing required title stops the request at the first desk (400 rest_missing_callback_param), although nobody is logged in.

7.3 · External APIs, Transients & WP-Cron: self-check

Q7
The supplier's host does not resolve, and code calls wp_remote_retrieve_body( $response ) on the WP_Error. What does it get?
A) A fatal error
B) null and a Warning
C) The error message
D) An empty string
Why: The wp_remote_retrieve_*() helpers accept a WP_Error and return '' (or 0) instead of failing: safe to call, but '' decodes to null, so check is_wp_error() first anyway.
A is wrong: That is why the helpers exist.
B is wrong: No message at all.
C is wrong: That is $response->get_error_message().
Q8
What does this print, for a transient nobody ever set?
wp eval 'var_dump( get_transient( "pagesco_books_nothing_here" ) );'
bool(false)
Why: get_transient() returns false for "missing or expired". That is why a cache must never STORE false (it would look missing), and why the project stores an array even for a failure.
Q9
A plugin fetches a book cover from a URL an editor types into a field. Which function?
A) wp_safe_remote_get(): it refuses private networks and odd ports
B) wp_remote_get() with a short timeout
C) file_get_contents()
D) wp_remote_head()
Why: A URL from a user could point at http://192.168.1.1/ or a cloud metadata service: server-side request forgery. The safe variants refuse those before connecting; the site's own host stays allowed.
B is wrong: A timeout does not stop the request reaching an internal address.
C is wrong: It bypasses the HTTP API's protections and filters.
D is wrong: It is just a HEAD request.
Q10
You want to run the daily sync now, while developing, without moving tomorrow's 03:00 run. What do you type?
A) wp cron event run pagesco_books_daily_sync
B) wp eval 'do_action( "pagesco_books_daily_sync" );'
C) wp cron test
D) curl -s http://localhost:8080/wp-cron.php
Why: WP-CLI's event run reschedules a recurring event from now (a 03:00 job run at 10:15 moves to 10:15); firing the hook yourself runs the work and leaves the schedule alone (Lesson 7.3's warning box).
A is wrong: It moves the schedule.
C is wrong: It only checks the loopback.
D is wrong: It runs what is DUE; tomorrow's 03:00 is not.
Q11
Where does the supplier's API key belong?
A) In the plugin's Client class, as a constant
B) In a transient, refreshed daily
C) In wp-config.php (or an environment variable it reads), on each site
D) In the REST API response, for the JavaScript
Why: A key in code ends up in Git, backups and every copy of the plugin, and the live site needs a different one. wp config set writes the constant; the live site gets its own.
A is wrong: Code is shared; secrets are not.
B is wrong: Transients can vanish at any time.
D is wrong: Never send secrets to browsers.
Q12
On the course site after Lesson 7.3: what does this print?
wp cron event list --hook=pagesco_books_daily_sync --fields=hook,recurrence
| pagesco_books_daily_sync | 1 day |
Why: Exactly one daily event: Activator schedules it once, guarded by wp_next_scheduled(), and deactivation clears it. Two rows here would be Common Mistake 2 (scheduling on every request).

7.3 · External APIs, Transients & WP-Cron: predict, then run

Predict the output, then run it.
wp eval 'var_dump( is_wp_error( wp_remote_get( "http://localhost:8080/supplier-sandbox/v1/availability" ) ) );'
bool(false)
Why: The sandbox answers 401 with JSON, which is a perfectly good HTTP response: not a WP_Error. Only the status code tells you it failed.
P4
Predict the output, then run it.
wp eval 'echo wp_safe_remote_get( "http://10.0.0.1/" )->get_error_message(), "\n";'
A valid URL was not provided.
Why: wp_safe_remote_get() refuses private networks before connecting: "A valid URL was not provided." (the site's own host stays allowed).

The Lesson Pages' Own Quick Quizzes

Lesson 7.2 · Custom REST Endpoints
  1. A rest_api_init: rest_api_init fires when WordPress builds the REST server, only on requests that need it; registering anywhere else triggers a called incorrectly notice.
  2. C 8 books, and X-WP-Total: 11, X-WP-TotalPages: 2: per_page defaults to Settings::get( 'books_per_page' ), now 8, so page 1 has 8 books and the headers say 11 in total on 2 pages.
  3. B The callback receives 500: the maximum is not checked: With a sanitize_callback of its own, the argument is no longer run through rest_parse_request_arg, so the maximum is never checked and the callback receives 500.
  4. A A function that returns current_user_can( 'edit_others_posts' ), or a WP_Error with rest_authorization_required_code(): A write needs a capability check; edit_others_posts lets editors and administrators add shop-wide events, and the function answers 401 or 403 otherwise.
  5. C 500: Without a status of 404 in the error data, WordPress sends 500 Internal Server Error with data null.
Lesson 7.3 · External APIs, Transients & WP-Cron
  1. C A normal response array; wp_remote_retrieve_response_code() returns 503: An error status is still a response: an array whose code wp_remote_retrieve_response_code() reports as 503, with the HTML as the body. Only a missing answer is a WP_Error.
  2. A In the object cache only, where it may be evicted before the hour is over: With an external object cache, transients are stored in the cache only, and may be evicted before they expire; without one they are two rows in wp_options.
  3. B In the activation callback, after checking wp_next_scheduled(), with wp_clear_scheduled_hook() on deactivation: Schedule once on activation, guarded by wp_next_scheduled(), and clear it with wp_clear_scheduled_hook() on deactivation; the callback itself is added on every request.
  4. B With the first request after 3:00, around 8 a.m.: WP-Cron checks for due events on requests; the first request after 3:00, here the first visitor around 8 a.m., starts it. A system cron calling wp cron event run --due-now removes that dependency.
  5. C So that a broken supplier is not asked, and waited for, on every screen view: Without a cached failure, every Books screen view would call the broken supplier again and wait for its timeout; five minutes protects both sites and still retries soon.

Exit Ticket

  1. The four desks: validate (schema and validate_callbacks), sanitize (schema or sanitize_callbacks, defaults), permission (permission_callback), callback.
  2. Three failures: no answer (a WP_Error: DNS, connection, timeout); an error status (401, 404, 503: a normal response); a body that is not the expected data (HTML, no items).
  3. The daily job: in the activation callback, if ( ! wp_next_scheduled( $hook ) ); wp_clear_scheduled_hook() on deactivation; the callback added on every request.

Common Wrong Answers and What They Reveal

  • Q1 C. Mixes CREATABLE and EDITABLE: show WP_REST_Server's constants.
  • Q3 B (401 first). Thinks permission comes first: redraw the four desks and run P2.
  • Q4 B. Guessing at the schema's behavior: the validate_callbacks run first, then sanitizing.
  • Q5 B (is_user_logged_in). Any subscriber is logged in: a capability names the job.
  • Q7 B or C. Has not met the helpers' tolerance of WP_Error; still check is_wp_error() first.
  • Q10 A. Uses WP-CLI's event run: it moves the schedule.
  • Q11 A. Puts secrets in code: they end up in Git and in every copy.

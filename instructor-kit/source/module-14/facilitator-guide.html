How to teach the session where the shop opens API counters of its own and starts calling another company's: routes with arguments, schemas, errors and permission checks, then a careful HTTP client, transients that survive a broken supplier, WP-Cron jobs scheduled once, and an ability for assistants.

  1. W1 (Lesson 6.4). curl asks /find-a-book/?genre=fantasy. How many books does the server send with the hidden attribute? Answer: 9 of eleven: the server evaluated data-wp-bind--hidden for each book (two fantasy books stay visible).
  2. W2 (Lesson 6.4). Why does selectGenre need withSyncEvent()? Answer: It calls event.preventDefault(); since 6.8 actions may run after the event, too late to stop the link.
  3. W3 (Lesson 7.1). A client gets 403 rest_cannot_edit. Fix the request, the credentials or the role? Answer: The role: 403 means "I know you, and no" (Devon on Maria's book). 401 would be the credentials.
  4. W4 (Lesson 7.1). How does a client learn how many pages the catalog has at per_page=5, without reading the books? Answer: A HEAD request (curl -I) and the header: X-WP-TotalPages: 3 on the projector site.
  5. W5 (Lesson 7.1). Why can the Stock at a glance widget POST to /wp/v2/books with plain apiFetch, and an outside script cannot? Answer: apiFetch sends Maria's cookie AND the page's wp_rest nonce; a script has neither, so it needs an application password.

7.2

Custom REST Endpoints

70 min
Objectives (from the lesson page)
  • Register routes with register_rest_route() on rest_api_init, as a feature class of the plugin
  • Declare arguments with types, defaults, limits and enums, and add your own validate_callback and sanitize_callback without losing the built-in checks
  • Describe responses with a JSON Schema, and return WP_REST_Response objects with headers and status codes
  • Return errors as WP_Error with the right status, and know what WordPress does with one that has none
  • Write a real permission_callback for every route, and explain why __return_true is only for public reads

Mental model to say

"Core's counter handles everything for everyone, so its menu is long and its packages are big. The shop opens a window of its own with a short printed menu: 'books, by genre or stock, sorted three ways, ten details each' and 'events: read them, or add one if you work here'. The menu is the route and its arguments; the card describing each package is the schema; the sign 'staff only' on the second item is the permission callback. A window without such a sign serves anyone who walks up."

Then the four desks on the board, in order: validate (types, ranges, enums, your validate_callback) → sanitize (strings become integers, defaults fill in) → permission (may this user?) → callback (gets clean, typed values). "A request that fails at a desk never reaches the next."

Three mistakes to expect, and how to coach each
  • No permission_callback, or __return_true on a write. Coach: "Who may call this, and what stops everyone else?" Look at the response headers of your own routes. (Self-check Q5.)
  • A sanitize_callback that switches the schema off (absint on per_page). Coach: "Which function checks the maximum now?" Keep rest_validate_request_arg as the validate_callback. (The debug handout.)
  • A WP_Error without a status, or an error that leaks existence. Coach: "What status does a client see? What does the message tell a stranger?" (Self-check Q6.)

Checks for understanding

Ask these out loud during the demo and the lab:

  • In which order do the desks run? Answer: validate, sanitize, permission, callback.
  • Why WP_Query and not get_posts() in get_books()? Answer: found_posts and max_num_pages for the X-WP-Total headers.
  • What does rest_authorization_required_code() return? Answer: 401 when nobody is logged in, 403 when someone is.
  • What does a WP_Error without a status become? Answer: a 500 with "data":null (lesson quiz Q5).

Workbook self-check, items Q1 to Q6 (learners do them at the end of the block or at home).

Answers: Q1 B) POST; Q2 200 6 2; Q3 A) 400 rest_missing_callback_param: arguments are validated before the permission check; Q4 D) validate_callbacks run first; the schema checks of the other arguments run in the sanitizing step, which a failed validation never reaches; Q5 C) A check of current_user_can( 'edit_others_posts' ) that returns a WP_Error with rest_authorization_required_code(); Q6 An endpoint must not tell visitors what exists behind an ID they may not see: drafts, private books and other post types all get the same 404. 7.3

External APIs, Transients & WP-Cron

80 min
Objectives (from the lesson page)
  • Call an external API with wp_remote_get() and wp_remote_post(), and handle each way it can fail: no answer, an error status, or an answer that is not what you expected

Mental model to say

"When a bookseller wants to know whether the distributor has more copies of The Great Gatsby, she calls. Sometimes the line is busy, sometimes nobody answers, sometimes the person reads the wrong list. A good bookseller writes the answer on a sticky note with the time, so the next colleague does not call again, and at closing time somebody works through a checklist."

Then the three pieces on the board: the phone = wp_remote_get() and friends; the sticky note = a transient, which may fall off the wall early, so you always check; the closing checklist = WP-Cron, which WordPress works through when the next visitor walks in after closing time. "A page that shows supplier data never waits for the supplier when a fresh note exists, and the nightly job keeps the note fresh."

Three mistakes to expect, and how to coach each
  • Trusting the answer: only is_wp_error() checked, then $data['items'] on a maintenance page: two Warnings and a confident "0 copies". Coach: "Which of the three failures does this line handle?" (The guided lab, the debug handout.)
  • Scheduling on every request: four daily events after three commands. Coach: "Where does a plugin do things exactly once?" Activation, guarded by wp_next_scheduled(). (The cron lab.)
  • A cache that never hits: storing false, or checking if ( $cached ) for a value that can be 0. Coach: "What does get_transient() return when nothing is there?" (Self-check Q8, the debug handout.)

Checks for understanding

Ask these out loud during the demo and the lab:

  • A 503 from the supplier: WP_Error or array? Answer: an array; only no answer at all is a WP_Error (lesson quiz Q1).
  • Where does a transient live on this site, and on one with Redis? Answer: two non-autoloaded rows in wp_options; in the object cache, where it may be evicted early.
  • A job due at 3:00 on a shop without night visitors: when does it run? Answer: with the first request after 3:00.

Closing

Exit ticket (3 questions, no notes, 4 minutes)

Learners answer in the workbook's Exit Ticket box or on a sticky note.

  1. Name the four desks a REST request passes, in order. Answer: validate, sanitize, permission, callback.
  2. Name the three ways a call to another server can fail. Answer: no answer (WP_Error: DNS, refused, timeout); an error status (a normal response); a body that is not the data you expect.
  3. Where does a plugin schedule its daily job, and what guards it? Answer: in the activation callback, guarded by wp_next_scheduled(); cleared on deactivation.

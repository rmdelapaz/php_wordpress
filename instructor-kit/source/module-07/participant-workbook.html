Lesson

4.3

functions.php: Supports, Assets, Menus & Widgets

By the end you can
  • Explain when functions.php runs and choose the right hook for theme setup, widgets and assets
  • Declare theme supports such as title-tag and html5 with add_theme_support(), and say which ones block themes get automatically
  • Enqueue a stylesheet and a deferred script with wp_enqueue_style() and wp_enqueue_script(), with dependencies and a version that busts browser caches
  • Register a menu location and a widget area, print them with wp_nav_menu() and dynamic_sidebar(), and fill them from WP-CLI
  • Add the accessibility and translation basics every theme needs: a skip link, screen-reader text, labeled navigation and strings WordPress can translate
Key ideas
  • functions.php runs on every request while the theme is active (admin, REST and WP-CLI included): code goes in prefixed callbacks on the right hook.
  • Supports on after_setup_theme: title-tag, automatic-feed-links, post-thumbnails, responsive-embeds, html5 with an array. Block themes get most of them, and their title, automatically.
  • Enqueue on wp_enqueue_scripts: a prefixed handle, get_parent_theme_file_uri(), dependencies, the theme's Version; scripts with 'strategy' => 'defer', 'in_footer' => true.
  • Menus: register_nav_menus() (locations), the owner assigns, wp_nav_menu() behind has_nav_menu(). Widget areas: register_sidebar() with a fixed id on widgets_init, is_active_sidebar() + dynamic_sidebar(); widgets are blocks since 5.8.
  • Accessibility: a skip link, .screen-reader-text CSS, labeled navigation, real buttons, visible focus. Translation: a literal text domain; 6.8+ loads a theme's languages/ itself.
Worked example: what a classic theme leaves in the database

pagesco-classic is inactive at the end of Lesson 4.3, but what you set up for it is still in the database, in the theme's own option:

wp option get theme_mods_pagesco-classic --format=json
{"nav_menu_locations":{"primary":4},"custom_css_post_id":-1,"sidebars_widgets":{"time":1793006210,"data":{"wp_inactive_widgets":["block-2","block-3","block-4","block-5","block-6"],"footer":["block-7"]}}}

The menu location (primary → menu 4) and the widget area's contents (footer → block-7) are theme mods of pagesco-classic. The menu itself is a term:

wp menu list --fields=term_id,name,slug,count
+---------+-----------+-----------+-------+
| term_id | name      | slug      | count |
+---------+-----------+-----------+-------+
| 4       | Main menu | main-menu | 3     |
+---------+-----------+-----------+-------+

Switch to pagesco-classic again and both come straight back; pagesco's header uses its Navigation block instead, and a block theme has no widget areas.

Glossary

TermMeaning
after_setup_themeThe action for theme supports and menu locations, right after functions.php is loaded
theme supportA feature a classic theme switches on with add_theme_support() (title-tag, html5 ...)
enqueuePutting a stylesheet or script on WordPress's list with a handle, dependencies and a version
handleThe unique, prefixed name of an enqueued file (pagesco-classic-style; the element id adds -css or -js)
menu locationA named place in a template where the owner's menu appears (register_nav_menus())
widget areaA slot for widgets (register_sidebar() with an id), printed with dynamic_sidebar()
skip link"Skip to content": the first focusable link, jumping past the header to <main>
.screen-reader-textThe class for text meant to be heard, not seen; classic themes must style it
FernhillThe Part 1 project: a block theme for the Fernhill Community Garden (a fictional client)

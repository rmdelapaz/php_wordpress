Session 18 12 self-check items Confidential

9.1 · Self-check

Q1
Milestone 7: composer lint finds 11 warnings, all in HoldsTable.php (DirectQuery and NoCaching). What does the reference do?
A) Adds a phpcs:ignore comment to every query
B) Turns the two sniffs off in phpcs.xml.dist for the whole plugin
C) Documents ONE exception in phpcs.xml.dist, for that file, with its reason: a custom table has no WordPress API, and holds are per user and change with every click, so a cache would mostly be invalidated before it is read
D) Moves the holds into post meta so the warnings go away
Why: Lesson 8.1's rule: fix a finding when the fix is cheap, document an exception when it is not, where the events table's exception already is. The events, read by every visitor, ARE cached (Lesson 8.2): the decision is per table, with a reason.
A is wrong: Eleven ignore comments hide the decision instead of writing it down once.
B is wrong: That would also silence the sniffs for code that should be fixed.
D is wrong: That trades a documented decision for the slow meta queries the lesson argued against.
Q2
On the reference after Milestone 8, what does this print? Why did the THEME's version change too?
wp eval 'echo wp_get_theme( "pagesco" )->get( "Version" ), " ", PAGESCO_BOOKS_VERSION, "\n";'
1.2.0 1.2.0: the theme's template and pattern changed, and without development mode the live site caches pattern files until the theme's Version changes (Lesson 8.4)
Why: A new feature is a minor version (1.2.0) for the plugin; the theme gets one because templates/single-book.html and patterns/featured-books.php changed. Version_audit in the kit's labs reads all five places a version lives.
Q3
Milestone 9, on the rehearsal server: right after wp plugin install /deploy/pagesco-books-1.2.0.zip --force, SHOW TABLES LIKE finds no holds table. Why not yet?
A) wp plugin install ran with the OLD plugin in memory, and wp db query does not start WordPress: no new code has run init yet
B) The ZIP was built without src/Holds
C) The database user may not create tables
D) Tables are only created by the activation hook, so it never will be
Why: The next command that loads WordPress (wp theme install, in the lesson) runs the new code; on init, HoldsTable::maybe_upgrade() finds no version option and creates the table. On a real server the first page view does the same.
B is wrong: That ZIP would stop every request with "Class not found" (Common Mistake 1), not leave a quiet gap.
C is wrong: pagesco_app has CREATE (Lesson 8.4's grants); the table appears one command later.
D is wrong: That is exactly what maybe_upgrade() is for.
Q4
After the deploy, the rehearsal server answers 404 for /my-holds/. What is the right fix?
A) Import the development database on the live site
B) Deploy the plugin again with --force
C) Flush the permalinks on the development site
D) Create the page ON the live site (it is content: it lives in the database), with wp post create, as the readme's upgrade notice says
Why: Code goes up, content stays (Lesson 8.4). The page made in Milestone 5 is a row in the development database. The recorded run: 404 before, 200 after creating it.
A is wrong: That would overwrite the live shop's real data with test customers and test holds.
B is wrong: The code is already there; the page is not code.
C is wrong: The live site's permalinks are fine: the page simply does not exist there.
Q5
Milestone 7 measures the front page at 31 queries for a visitor; the baseline was 22. Where do the nine come from, and why does the reference accept them?
three per staff pick (get_page_by_path() for the slug, then the book and its meta) for the live prices; indexed primary-key lookups under a millisecond each, the page has no per-user content so a page cache serves it, and an object cache keeps them
Why: Decide with numbers (Lesson 8.2) and write the decision down. A book's page stays at 25: the Reserve block leaves before its first query when nobody is logged in.
Q6
Why does each Cancel button on My holds carry an aria-label that names its book?
<button type="submit" class="wp-element-button" aria-label="Cancel the hold on 1984">Cancel</button>
<button type="submit" class="wp-element-button" aria-label="Cancel the hold on Dune">Cancel</button>
A) Search engines index aria-labels
B) A screen reader would otherwise read "Cancel, Cancel, Cancel" with no way to tell which hold each one cancels
C) WordPress requires an aria-label on every button
D) It makes the button work without JavaScript
Why: Every control needs a name that makes sense out of context (Lesson 8.3). The visible text stays short; the accessible name says what it acts on.
A is wrong: Accessibility names are for assistive technology, not search.
C is wrong: Nothing in core enforces it.
D is wrong: The form works without JavaScript because it posts to admin-post.php.

9.1 · Predict, then run

P1
Predict the output, then run it.
wp eval 'echo count( PagesCo\Books\Holds\HoldsTable::waiting( "2000-01-01" ) ), "\n";'
2
Why: waiting() returns the holds that are waiting and whose pickup date is on or after the date given; from 2000-01-01 nothing counts as expired, so both waiting holds of the saved site (Jordan's Dune and 1984) count. From today the answer depends on the day: that is the computed "expired".

Predict the output, then run it.
wp option get pagesco_books_holds_db_version

Why: The schema version the code wrote after creating the table; maybe_upgrade() compares it with HoldsTable::DB_VERSION on every init and installs again only when the code is newer.

9.2 · Self-check

Q7
A front end on another origin asks the shop's API. What does this print, and does it make the holds routes public?
curl -s -I -H 'Origin: https://shop.example' http://localhost:8080/wp-json/pagesco/v1/books \
  | tr -d '\r' | grep -i '^access-control-allow-origin'
Access-Control-Allow-Origin: https://shop.example; no: WordPress echoes any origin, so a page anywhere may READ the answers, but the permission callbacks still refuse (a visitor gets 401 from /holds)
Why: CORS decides what a browser lets a page read, not who may act. Safety comes from the permission callbacks and nonces, never from CORS (Lesson 9.2's key takeaway).
Q8
A headless storefront shows the heading "Pages &amp; Co." (the entity, as text). What is the right fix?
A) Switch the heading to innerHTML
B) Change the site title in Settings to "Pages and Co."
C) Know which fields are HTML: decode the stored-escaped name once to text (DOMParser), then put it on the page with textContent
D) Escape it again with encodeURIComponent()
Why: blogname is stored HTML-escaped and the REST index returns it that way (Lesson 1.2, 9.2's Common Mistake 1). textContent is safe and shows the entity literally; innerHTML would show the ampersand and run any HTML in the field.
A is wrong: It fixes the ampersand and opens the page to any HTML that reaches the field.
B is wrong: Changes the shop's name to hide a bug.
D is wrong: URL encoding is for addresses, not text on the page.
Q9
What does WordPress 7.1 ship for AI?
A) Plumbing: the AI client (wp_ai_client_prompt()), the Connectors screen and a switch to turn AI off; no model, no provider and no core feature
B) A small built-in model for alt text
C) A paid OpenAI integration enabled on every site
D) Nothing: AI is only in the separate AI plugin
Why: On the course site wp_supports_ai() is true, but no installed provider offers a model, so prompts return a WP_Error; core never calls the client itself (Q10).
B is wrong: Core ships no model.
C is wrong: Providers are separate plugins, inactive until installed, and need a key.
D is wrong: The client and Connectors ARE in core since 7.0; the features are in plugins.
Q10
What does this print on the course site, and what does it tell you?
grep -rl 'wp_ai_client_prompt *(' wp-admin wp-includes
wp-includes/ai-client.php: only the file that defines the function; no core screen, block or feature calls the AI client
Why: Core provides one shared, provider-neutral client; plugins (the WordPress project's AI plugin first) build the features.
Q11
Lesson 9.2's model-check.php lists the pagesco/check-stock ability as a tool for a model. Which name does the model see?
A) pagesco/check-stock
B) check_stock
C) pagesco-check-stock
D) wpab__pagesco__check-stock
Why: The ability's name made safe for function-calling APIs: the prefix wpab__ and the slash as a double underscore. The resolver then runs the ability as the current user: data for Maria, ability_invalid_permissions for Devon.
A is wrong: Function-calling APIs do not allow the slash.
B is wrong: The namespace stays in the name.
C is wrong: A double underscore replaces the slash, after the wpab__ prefix.
Q12
Before the repository goes public, Lesson 9.2 searches with git log --all -S, not only the current files. Why?
a secret that was committed once and deleted later is still in the history, and anyone who clones the repository can read it; -S lists every commit that added or removed the string, on every branch
Why: The kit's publish_scan lab checks the files on disk (what you are about to commit); the history search checks what you already committed. Both, before publishing.

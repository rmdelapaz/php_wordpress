The lesson's checklist, on the slide and in the workbook:

  1. The problem (30 seconds): the sticky notes, in one sentence each from the brief.

Three mistakes to expect, and how to coach each
  • Fixing the proof instead of the code. A failing smoke test line "fixed" by changing the test's grep, a lint warning silenced for the whole plugin. Coach: "What does this line of the checklist protect? Make the code do that."
  • Importing the development database to make the live site match. The 404 on My holds tempts everyone. Coach: "Code goes up, content comes down, configuration stays. Which is a page?" (Q4.)
  • A showcase that is a code tour. Ten minutes of scrolling through classes. Coach with the checklist: the problem in one sentence, then the browser, then the proof, then ONE decision.
Checks for understanding

Ask during the studio:

  • Why does the theme get a new version although its PHP did not change? Answer: its template and pattern changed, and the live pattern cache only notices a new Version.
  • What would have caught a ZIP without src/Holds? Answer: listing the ZIP and loading a new class with its own autoloader before upload (the lesson's quiz Q5).
  • Which data does a deploy change on the live site? Answer: none but what the new code creates itself (the holds table); the page and the test customer are created by hand on live.

Workbook self-check, items Q1 to Q6.

Answers: Q1 C) Documents ONE exception in phpcs.xml.dist, for that file, with its reason: a custom table has no WordPress API, and holds are per user and change with every click, so a cache would mostly be invalidated before it is read; Q2 1.2.0 1.2.0: the theme's template and pattern changed, and without development mode the live site caches pattern files until the theme's Version changes (Lesson 8.4); Q3 A) wp plugin install ran with the OLD plugin in memory, and wp db query does not start WordPress: no new code has run init yet; Q4 D) Create the page ON the live site (it is content: it lives in the database), with wp post create, as the readme's upgrade notice says; Q5 three per staff pick (get_page_by_path() for the slug, then the book and its meta) for the live prices; indexed primary-key lookups under a millisecond each, the page has no per-user content so a page cache serves it, and an object cache keeps them; Q6 B) A screen reader would otherwise read "Cancel, Cancel, Cancel" with no way to tell which hold each one cancels. Full set with explanations in the Answer Key.

Mental model to say

"A traditional WordPress site is a shop where the stockroom and the shop floor are one building: the theme is the shop floor. Headless keeps the stockroom, WordPress with the stock, the rules and the staff entrance, and sends goods out through a loading door, the API, to shop windows anywhere: a website built with another framework, a phone app, a kiosk." Then the trade, on the board: what the theme gave for free (templates, the Site Editor, previews, plugins' front ends, one deployment) has to be rebuilt in front. "It pays for apps and many front ends; it costs a second deployment and every preview."

Then AI in core in one sentence: "WordPress 7 ships plumbing: a client plugins can use, a screen for a provider's key, a switch to turn it off. No model, no provider, no AI feature." Then contributing (make.wordpress.org, a team, one meeting, evidence in every report) and careers (agency, freelance, in-house, a plugin business, headless) in one minute each: the lesson has the tables, the learners read them at home.

Three mistakes to expect, and how to coach each
  • Treating CORS as security. "I will restrict the origin and the API is safe." Coach: "curl sends no Origin and ignores CORS. Who refuses a visitor on /holds?" (The permission callback: the guided lab's last line.)
  • A generate_text() result printed as text. The lesson's Common Mistake 2: a WP_Error into esc_html() is a fatal error on every book page. Coach: "What does it return when no model exists? On every fresh site."
  • Reading only the first page. Six books, no error. Coach: "What does X-WP-TotalPages say?" (The kit's debug_headless_client.php.)

🔌 Lesson 7.2: Custom REST Endpoints

In Lesson 7.1 the core books route said no to the shop's most natural question, "the fantasy books, cheapest first", and answered easy ones with 13 KB of fields nobody asked for. Today the plugin opens counters of its own under the namespace pagesco/v1: a compact, filterable books route whose page size follows the shop's settings, and an events route that reads and writes Lesson 5.5's custom table. Along the way you learn the parts every endpoint is made of, and the one you must never leave out: the check of who may use it.

🎯 Learning Objectives

  • Return errors as WP_Error with the right status, and know what WordPress does with one that has none

🪟 A Counter of the Shop's Own

Core's /wp/v2/books is a general-purpose route: it knows posts, terms and registered meta, and serves the editor perfectly. For the shop's own clients (a Book Filter for a big catalog, a partner's site, the inventory system) it has three problems you met in Lesson 7.1: it cannot sort by price or filter by stock (meta means nothing to it), it filters genres by ID while the shop's addresses use slugs (?genre=fantasy, Lesson 6.4), and each book is a large object full of fields (guid, template, class_list, _links…) that have nothing to do with books. You could bend the core route with filters, but a route of your own is cleaner: its own shape, its own rules, documented by its own schema.

💡 Mental model: a window with a printed menu

Core's counter handles everything for everyone, so its menu is long and its packages are big. The shop opens a window of its own with a short printed menu: "books, by genre or stock, sorted three ways, ten details each" and "events: read them, or add one if you work here". The menu is the route and its arguments; the printed card describing each package is the schema; and the sign "staff only" on the second item is the permission callback. A window without such a sign serves anyone who walks up.

The plan, with the names from the course's spine (the namespace is vendor/version: when a future pagesco/v2 changes the shape, v1 clients keep working):

🚪 Your First Route

A route is registered with register_rest_route( $namespace, $route, $args ), inside a callback on rest_api_init, the action WordPress fires when it builds the REST server (only on requests that need it). The $args array names the HTTP methods, the callback that answers, and the permission callback that decides who may ask. Like every part of the plugin, the endpoint is a feature class (Lesson 5.1). Create wordpress/wp-content/plugins/pagesco-books/src/Rest/BooksEndpoint.php, a first version:

<?php
/**
 * The shop's own books routes, under the pagesco/v1 namespace.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Rest;

use PagesCo\Books\BookPostType;
use PagesCo\Books\Feature;
use PagesCo\Books\GenreTaxonomy;
use PagesCo\Books\Settings;
use WP_Post;
use WP_REST_Request;
use WP_REST_Server;

/**
 * A compact catalog for the shop's JavaScript and partners: one book = ten plain fields.
 */
final class BooksEndpoint implements Feature {

	/**
	 * The namespace of every route the plugin adds: vendor/version.
	 */
	public const NAMESPACE = 'pagesco/v1';

	/**
	 * Registers the routes when the REST API starts, not on every request.
	 */
	public function register(): void {
		add_action( 'rest_api_init', array( $this, 'register_routes' ) );
	}

	/**
	 * Tells the REST server about the route: its method, callback and permission check.
	 */
	public function register_routes(): void {
		register_rest_route(
			self::NAMESPACE,
			'/books',
			array(
				'methods'             => WP_REST_Server::READABLE,
				'callback'            => array( $this, 'get_books' ),
				'permission_callback' => '__return_true',
			)
		);
	}

	/**
	 * GET /pagesco/v1/books: the first books of the catalog, in title order.
	 *
	 * @param WP_REST_Request $request The request.
	 */
	public function get_books( WP_REST_Request $request ) {
		$books = get_posts(
			array(
				'post_type'      => BookPostType::NAME,
				'post_status'    => 'publish',
				'posts_per_page' => (int) Settings::get( 'books_per_page' ),
				'orderby'        => 'title',
				'order'          => 'ASC',
			)
		);

		return rest_ensure_response( array_map( array( $this, 'prepare_book' ), $books ) );
	}

	/**
	 * One book as the API shows it: plain values, in real types.
	 *
	 * @param WP_Post $book A published book.
	 */
	public function prepare_book( WP_Post $book ): array {
		$genres = get_the_terms( $book, GenreTaxonomy::NAME );

		return array(
			'id'        => $book->ID,
			'title'     => $book->post_title,
			'slug'      => $book->post_name,
			'link'      => get_permalink( $book ),
			'author'    => (string) get_post_meta( $book->ID, 'pagesco_author', true ),
			'price'     => (float) get_post_meta( $book->ID, 'pagesco_price', true ),
			'in_stock'  => (bool) get_post_meta( $book->ID, 'pagesco_in_stock', true ),
			'pages'     => (int) get_post_meta( $book->ID, 'pagesco_pages', true ),
			'published' => (string) get_post_meta( $book->ID, 'pagesco_published', true ),
			'genres'    => is_array( $genres ) ? wp_list_pluck( $genres, 'slug' ) : array(),
		);
	}
}
  • The namespace is a constant, so the events endpoint later uses the same one. The class lives in src/Rest/, so its namespace is PagesCo\Books\Rest (PSR-4, Lesson 5.1), and the use lines import the plugin's classes and WordPress's REST classes, which live in the global namespace.
  • WP_REST_Server::READABLE is the string 'GET'; CREATABLE is 'POST', EDITABLE is 'POST, PUT, PATCH', DELETABLE is 'DELETE'. The constants say what you mean.
  • permission_callback is required on every route. __return_true, a core function that returns true, says "anyone": right for a public catalog, the same books every visitor sees on the site.
  • The callback gets a WP_REST_Request and returns data. rest_ensure_response() wraps an array in a WP_REST_Response, which WordPress turns into JSON. The page size is the Books per list setting from Lesson 5.4, as promised there: the shop changes every default-length list, on the site and in the API, from one screen.
  • prepare_book() decides the shape: ten fields, each cast to the type a client expects ((float), (bool), (int)), because meta comes out of the database as strings. The title is the plain title as typed: JSON is data, and whoever prints it escapes it (as the Lesson 7.1 widget did with textContent).

📝 Arguments: Validate, Sanitize, Describe

A route's args list the parameters it accepts, from the query string, a form or a JSON body (WordPress merges them into the request; read them as $request['genre']). Each argument is described with JSON Schema keywords, and WordPress uses that description three ways:

  1. Validation before your callback runs: a wrong type, a number out of range or a value not in the enum stops the request with 400 rest_invalid_param, with a message per parameter. Your callback never sees bad input.
  2. Sanitizing: "5" from a query string becomes the integer 5, "true" becomes true; missing arguments get their default.
  3. Documentation: an OPTIONS request, and the /wp-json/pagesco/v1 index, list every argument with its description, type and limits.

With a type and no callbacks, WordPress does validation and sanitizing from the schema by itself (rest_validate_request_arg() and rest_sanitize_request_arg(), together rest_parse_request_arg()). For rules a schema cannot express, such as "a genre that exists", you add a validate_callback (return true, or a WP_Error whose message tells the client what is wrong) and a sanitize_callback (return the cleaned value). The order is: validate, sanitize, then the permission check, then your callback. Replace src/Rest/BooksEndpoint.php with the full version:

<?php
/**
 * The shop's own books routes: GET /pagesco/v1/books and /pagesco/v1/books/<id>.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Rest;

use PagesCo\Books\BookPostType;
use PagesCo\Books\Feature;
use PagesCo\Books\GenreTaxonomy;
use PagesCo\Books\Settings;
use WP_Error;
use WP_Post;
use WP_Query;
use WP_REST_Request;
use WP_REST_Response;
use WP_REST_Server;

/**
 * A compact, filterable catalog for the shop's JavaScript and partners: one book = ten plain fields.
 */
final class BooksEndpoint implements Feature {

	/**
	 * The namespace of every route the plugin adds: vendor/version.
	 */
	public const NAMESPACE = 'pagesco/v1';

	/**
	 * The schema, built once per request.
	 *
	 * @var array|null
	 */
	private ?array $schema = null;

	/**
	 * Registers the routes when the REST API starts, not on every request.
	 */
	public function register(): void {
		add_action( 'rest_api_init', array( $this, 'register_routes' ) );
	}

	/**
	 * Tells the REST server about the two routes: their methods, callbacks, permissions and arguments.
	 */
	public function register_routes(): void {
		register_rest_route(
			self::NAMESPACE,
			'/books',
			array(
				array(
					'methods'             => WP_REST_Server::READABLE,
					'callback'            => array( $this, 'get_books' ),
					'permission_callback' => '__return_true',
					'args'                => $this->collection_args(),
				),
				'schema' => array( $this, 'get_schema' ),
			)
		);

		register_rest_route(
			self::NAMESPACE,
			'/books/(?P<id>\d+)',
			array(
				array(
					'methods'             => WP_REST_Server::READABLE,
					'callback'            => array( $this, 'get_book' ),
					'permission_callback' => '__return_true',
					'args'                => array(
						'id' => array(
							'description' => __( 'The book ID.', 'pagesco-books' ),
							'type'        => 'integer',
							'minimum'     => 1,
						),
					),
				),
				'schema' => array( $this, 'get_schema' ),
			)
		);
	}

	/**
	 * The query arguments GET /books accepts. With a type and no sanitize_callback, WordPress
	 * validates and sanitizes each one against its schema (rest_parse_request_arg).
	 */
	private function collection_args(): array {
		return array(
			'page'     => array(
				'description' => __( 'The page of results.', 'pagesco-books' ),
				'type'        => 'integer',
				'default'     => 1,
				'minimum'     => 1,
			),
			'per_page' => array(
				'description' => __( 'Books per page. Default: the Books per list setting.', 'pagesco-books' ),
				'type'        => 'integer',
				'default'     => (int) Settings::get( 'books_per_page' ),
				'minimum'     => 1,
				'maximum'     => 100,
			),
			'genre'    => array(
				'description'       => __( 'Only books in this genre (a genre slug).', 'pagesco-books' ),
				'type'              => 'string',
				'default'           => '',
				'sanitize_callback' => 'sanitize_key',
				'validate_callback' => array( $this, 'validate_genre' ),
			),
			'in_stock' => array(
				'description' => __( 'true: only books in stock; false: only sold-out books.', 'pagesco-books' ),
				'type'        => 'boolean',
			),
			'orderby'  => array(
				'description' => __( 'The order of the books.', 'pagesco-books' ),
				'type'        => 'string',
				'enum'        => array( 'title', 'newest', 'price' ),
				'default'     => 'title',
			),
		);
	}

	/**
	 * Accepts '' (all genres) or the slug of an existing genre.
	 *
	 * @param mixed $value The genre argument as sent.
	 * @return true|WP_Error
	 */
	public function validate_genre( $value ) {
		if ( ! is_string( $value ) ) {
			return new WP_Error( 'rest_invalid_type', __( 'genre must be a genre slug.', 'pagesco-books' ) );
		}
		if ( '' === $value || term_exists( sanitize_key( $value ), GenreTaxonomy::NAME ) ) {
			return true;
		}

		return new WP_Error( 'pagesco_unknown_genre', __( 'genre must be the slug of an existing genre.', 'pagesco-books' ) );
	}

	/**
	 * GET /pagesco/v1/books: one page of books, with the totals in the X-WP-Total headers.
	 *
	 * @param WP_REST_Request $request The request, its arguments already validated and sanitized.
	 * @return WP_REST_Response|WP_Error
	 */
	public function get_books( WP_REST_Request $request ) {
		$query_args = array(
			'post_type'      => BookPostType::NAME,
			'post_status'    => 'publish',
			'posts_per_page' => $request['per_page'],
			'paged'          => $request['page'],
			'orderby'        => 'title',
			'order'          => 'ASC',
		);

		if ( 'newest' === $request['orderby'] ) {
			$query_args['orderby'] = 'date';
			$query_args['order']   = 'DESC';
		} elseif ( 'price' === $request['orderby'] ) {
			$query_args['meta_key'] = 'pagesco_price';
			$query_args['orderby']  = 'meta_value_num';
		}

		if ( '' !== $request['genre'] ) {
			$query_args['tax_query'] = array(
				array(
					'taxonomy' => GenreTaxonomy::NAME,
					'field'    => 'slug',
					'terms'    => $request['genre'],
				),
			);
		}

		if ( isset( $request['in_stock'] ) ) {
			$query_args['meta_query'] = array(
				array(
					'key'   => 'pagesco_in_stock',
					'value' => $request['in_stock'] ? '1' : '',
				),
			);
		}

		$query = new WP_Query( $query_args );

		if ( $request['page'] > 1 && $request['page'] > $query->max_num_pages ) {
			return new WP_Error(
				'pagesco_invalid_page',
				__( 'The page number is larger than the number of pages.', 'pagesco-books' ),
				array( 'status' => 400 )
			);
		}

		$response = rest_ensure_response( array_map( array( $this, 'prepare_book' ), $query->posts ) );
		$response->header( 'X-WP-Total', (string) $query->found_posts );
		$response->header( 'X-WP-TotalPages', (string) $query->max_num_pages );

		return $response;
	}

	/**
	 * GET /pagesco/v1/books/<id>: one published book, or a 404 error.
	 *
	 * @param WP_REST_Request $request The request; $request['id'] comes from the route's pattern.
	 * @return WP_REST_Response|WP_Error
	 */
	public function get_book( WP_REST_Request $request ) {
		$book = get_post( $request['id'] );

		if ( ! $book || BookPostType::NAME !== $book->post_type || 'publish' !== $book->post_status ) {
			return new WP_Error(
				'pagesco_book_not_found',
				__( 'No book was found with that ID.', 'pagesco-books' ),
				array( 'status' => 404 )
			);
		}

		return rest_ensure_response( $this->prepare_book( $book ) );
	}

	/**
	 * One book as the API shows it: plain values, in the types the schema promises.
	 *
	 * @param WP_Post $book A published book.
	 */
	public function prepare_book( WP_Post $book ): array {
		$genres = get_the_terms( $book, GenreTaxonomy::NAME );

		return array(
			'id'        => $book->ID,
			'title'     => $book->post_title,
			'slug'      => $book->post_name,
			'link'      => get_permalink( $book ),
			'author'    => (string) get_post_meta( $book->ID, 'pagesco_author', true ),
			'price'     => (float) get_post_meta( $book->ID, 'pagesco_price', true ),
			'in_stock'  => (bool) get_post_meta( $book->ID, 'pagesco_in_stock', true ),
			'pages'     => (int) get_post_meta( $book->ID, 'pagesco_pages', true ),
			'published' => (string) get_post_meta( $book->ID, 'pagesco_published', true ),
			'genres'    => is_array( $genres ) ? wp_list_pluck( $genres, 'slug' ) : array(),
		);
	}

	/**
	 * The JSON Schema of one book: what clients may rely on. OPTIONS requests return it.
	 */
	public function get_schema(): array {
		if ( null === $this->schema ) {
			$this->schema = array(
				'$schema'    => 'http://json-schema.org/draft-04/schema#',
				'title'      => 'pagesco-book',
				'type'       => 'object',
				'properties' => array(
					'id'        => array( 'type' => 'integer', 'readonly' => true ),
					'title'     => array( 'type' => 'string' ),
					'slug'      => array( 'type' => 'string' ),
					'link'      => array( 'type' => 'string', 'format' => 'uri' ),
					'author'    => array( 'type' => 'string' ),
					'price'     => array( 'type' => 'number' ),
					'in_stock'  => array( 'type' => 'boolean' ),
					'pages'     => array( 'type' => 'integer' ),
					'published' => array( 'type' => 'string', 'format' => 'date' ),
					'genres'    => array(
						'type'  => 'array',
						'items' => array( 'type' => 'string' ),
					),
				),
			);
		}

		return $this->schema;
	}
}

What changed, from the top:

  • Two routes, each an array of endpoints (here one each) plus a route-level 'schema'. The second route's pattern (?P<id>\d+) captures the ID into $request['id'], and its id argument types it, so /books/abc does not even match and /books/0 fails validation.
  • collection_args(): page and per_page with minimums and a maximum of 100 (core's limit), per_page defaulting to the setting; in_stock a boolean without a default (missing means "do not filter"); orderby an enum of the same three orders as Lesson 6.3's Book List.
  • genre has both callbacks. validate_genre() accepts '' or the slug of an existing term (term_exists()), the same "validate against what is allowed" rule as Lesson 6.4's ?genre=, and does not repeat the input in its message. Because it brings its own callbacks, the schema checks do not run for it (Common Mistake 2): the callback also checks the type itself.
  • get_books() builds a WP_Query (Lesson 4.2) from arguments that are already valid, typed and defaulted: no isset(), no absint(), no clamping in the callback. It uses WP_Query rather than get_posts() because it needs found_posts and max_num_pages for the headers.
  • get_schema() describes one book. It is built once per request and cached in a property, as core's controllers do.

🛂 permission_callback: Who May

The permission callback runs for every request, after the arguments are validated and before your callback. It receives the request and returns true (go ahead), false, or a WP_Error (refuse, with that error). It is Lesson 5.3's capability check for the REST API: the current user is already known (cookie plus nonce, or application password, Lesson 7.1), so the question is only "may this user do this?":

// Who may add or change events: staff who may edit everyone's posts (editors and administrators).
public function can_manage_events() {
	if ( current_user_can( 'edit_others_posts' ) ) {
		return true;
	}

	return new WP_Error(
		'rest_forbidden',
		__( 'Sorry, you are not allowed to manage events.', 'pagesco-books' ),
		array( 'status' => rest_authorization_required_code() )
	);
}

(A fragment of the project's class.) rest_authorization_required_code() returns 401 when nobody is logged in and 403 when someone is: the "who are you?" and "you may not" of Lesson 7.1, chosen for you. Returning false works too; WordPress then answers rest_forbidden, "Sorry, you are not allowed to do that.", with the same status rule, and your own error simply says more.

🛑 Never __return_true on a route that changes anything

'permission_callback' => '__return_true' on a POST, PUT or DELETE endpoint means anyone on the internet can call it, with no login, no nonce and no rate limit; within days of going live, bots that scan for open endpoints will. Checking inside the callback instead does not help either: by then the request has passed the server's permission step, and every future change to the callback must remember the check. For writes, check a capability, as specific as the job (edit_others_posts for shop-wide content, edit_post with the ID for one item, manage_options for settings). __return_true is for reads of public data, like the catalog.

Two more rules from Lesson 5.3 carry over. A permission check about a specific item uses the meta capability with its ID, current_user_can( 'edit_post', $request['id'] ), so roles and ownership both count. And a permission callback answers only "may this user?"; whether the input makes sense belongs to validation.

What it means: a WP_Error without array( 'status' => … ) is sent as 500 Internal Server Error, with "data":null. 🛠️ Step 1: The events endpoint (18 min)

One route, /events, with two endpoints: GET for anyone, POST for staff. Create wordpress/wp-content/plugins/pagesco-books/src/Rest/EventsEndpoint.php:

<?php
/**
 * The shop's events route: GET and POST /pagesco/v1/events.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Rest;

use PagesCo\Books\EventsTable;
use PagesCo\Books\Feature;
use PagesCo\Books\Settings;
use WP_Error;
use WP_REST_Request;
use WP_REST_Response;
use WP_REST_Server;

/**
 * Lists the events from the custom table, and lets staff add one, through EventsTable (Lesson 5.5).
 */
final class EventsEndpoint implements Feature {

	/**
	 * Registers the route when the REST API starts.
	 */
	public function register(): void {
		add_action( 'rest_api_init', array( $this, 'register_routes' ) );
	}

	/**
	 * One route, two endpoints: anyone may read, staff may write.
	 */
	public function register_routes(): void {
		register_rest_route(
			BooksEndpoint::NAMESPACE,
			'/events',
			array(
				array(
					'methods'             => WP_REST_Server::READABLE,
					'callback'            => array( $this, 'get_events' ),
					'permission_callback' => '__return_true',
					'args'                => array(
						'limit'    => array(
							'description' => __( 'How many events at most. Default: the Events to show setting.', 'pagesco-books' ),
							'type'        => 'integer',
							'default'     => (int) Settings::get( 'events_limit' ),
							'minimum'     => 1,
							'maximum'     => 50,
						),
						'location' => array(
							'description' => __( 'Only events at this location (exact match).', 'pagesco-books' ),
							'type'        => 'string',
							'default'     => '',
						),
					),
				),
				array(
					'methods'             => WP_REST_Server::CREATABLE,
					'callback'            => array( $this, 'create_event' ),
					'permission_callback' => array( $this, 'can_manage_events' ),
					'args'                => array(
						'title'     => array(
							'description'       => __( 'The event\'s name.', 'pagesco-books' ),
							'type'              => 'string',
							'required'          => true,
							'minLength'         => 1,
							'maxLength'         => 200,
							'sanitize_callback' => 'sanitize_text_field',
							'validate_callback' => 'rest_validate_request_arg',
						),
						'starts_at' => array(
							'description'       => __( 'Local date and time, such as 2027-12-16 19:00.', 'pagesco-books' ),
							'type'              => 'string',
							'required'          => true,
							'validate_callback' => array( $this, 'validate_starts_at' ),
							'sanitize_callback' => array( $this, 'sanitize_starts_at' ),
						),
						'location'  => array(
							'description'       => __( 'Where in the shop.', 'pagesco-books' ),
							'type'              => 'string',
							'default'           => '',
							'maxLength'         => 200,
							'sanitize_callback' => 'sanitize_text_field',
							'validate_callback' => 'rest_validate_request_arg',
						),
						'capacity'  => array(
							'description' => __( 'Seats, or 0 for an event open to all.', 'pagesco-books' ),
							'type'        => 'integer',
							'default'     => 0,
							'minimum'     => 0,
							'maximum'     => 65535,
						),
					),
				),
				'schema' => array( $this, 'get_schema' ),
			)
		);
	}

	/**
	 * Who may add or change events: staff who may edit everyone's posts (editors and administrators).
	 *
	 * @return true|WP_Error
	 */
	public function can_manage_events() {
		if ( current_user_can( 'edit_others_posts' ) ) {
			return true;
		}

		return new WP_Error(
			'rest_forbidden',
			__( 'Sorry, you are not allowed to manage events.', 'pagesco-books' ),
			array( 'status' => rest_authorization_required_code() )
		);
	}

	/**
	 * Accepts a local date and time written Y-m-d H:i, such as 2027-12-16 19:00.
	 *
	 * @param mixed $value The starts_at argument as sent.
	 * @return true|WP_Error
	 */
	public function validate_starts_at( $value ) {
		$date = is_string( $value ) ? \DateTime::createFromFormat( '!Y-m-d H:i', $value ) : false;

		if ( $date && $date->format( 'Y-m-d H:i' ) === $value ) {
			return true;
		}

		return new WP_Error( 'pagesco_invalid_date', __( 'starts_at must be a date and time such as 2027-12-16 19:00.', 'pagesco-books' ) );
	}

	/**
	 * Turns a valid starts_at into the table's DATETIME format.
	 *
	 * @param string $value A value validate_starts_at() accepted.
	 */
	public function sanitize_starts_at( $value ): string {
		return $value . ':00';
	}

	/**
	 * GET /pagesco/v1/events: events in date order, from the custom table.
	 *
	 * @param WP_REST_Request $request The request.
	 */
	public function get_events( WP_REST_Request $request ): WP_REST_Response {
		$events = EventsTable::find( $request['limit'], $request['location'] );

		return rest_ensure_response( array_map( array( $this, 'prepare_event' ), $events ) );
	}

	/**
	 * POST /pagesco/v1/events: adds an event and answers 201 Created with it.
	 *
	 * @param WP_REST_Request $request The request, its arguments validated and sanitized.
	 * @return WP_REST_Response|WP_Error
	 */
	public function create_event( WP_REST_Request $request ) {
		$id = EventsTable::add( $request['title'], $request['starts_at'], $request['location'], $request['capacity'] );

		if ( ! $id ) {
			return new WP_Error( 'pagesco_event_not_saved', __( 'The event could not be saved.', 'pagesco-books' ), array( 'status' => 500 ) );
		}

		$response = rest_ensure_response(
			$this->prepare_event(
				(object) array(
					'id'        => $id,
					'title'     => $request['title'],
					'starts_at' => $request['starts_at'],
					'location'  => $request['location'],
					'capacity'  => $request['capacity'],
				)
			)
		);
		$response->set_status( 201 );

		return $response;
	}

	/**
	 * One event as the API shows it. Table rows arrive as strings; the API promises real types.
	 *
	 * @param object $event A row from EventsTable::find(), or the same shape.
	 */
	public function prepare_event( object $event ): array {
		return array(
			'id'        => (int) $event->id,
			'title'     => $event->title,
			'starts_at' => mysql2date( 'Y-m-d\TH:i:s', $event->starts_at, false ),
			'location'  => $event->location,
			'capacity'  => (int) $event->capacity,
		);
	}

	/**
	 * The JSON Schema of one event.
	 */
	public function get_schema(): array {
		return array(
			'$schema'    => 'http://json-schema.org/draft-04/schema#',
			'title'      => 'pagesco-event',
			'type'       => 'object',
			'properties' => array(
				'id'        => array( 'type' => 'integer', 'readonly' => true ),
				'title'     => array( 'type' => 'string' ),
				'starts_at' => array( 'type' => 'string', 'format' => 'date-time' ),
				'location'  => array( 'type' => 'string' ),
				'capacity'  => array( 'type' => 'integer' ),
			),
		);
	}
}
  • Defaults from the settings: limit defaults to Events to show (Lesson 5.4), like the [pagesco_events] shortcode, with a maximum of 50, the shortcode's clamp.
  • title and location need sanitize_text_field() (no tags, no line breaks) and the schema's length check, so they name both callbacks: your sanitizer and rest_validate_request_arg (Common Mistake 2). required makes a missing title a 400 before anything else.
  • starts_at has a format no schema keyword expresses: the shop's local time, written 2027-12-16 19:00. validate_starts_at() parses it with DateTime::createFromFormat() and compares it back, which also rejects impossible dates such as February 30 (Lesson 5.3's valid_date() idea); sanitize_starts_at() adds the seconds the DATETIME column expects. (\DateTime has a backslash: it is PHP's class, outside the plugin's namespace.)
  • capacity is an integer from 0 to 65535, the range of the SMALLINT UNSIGNED column from Lesson 5.5: the schema protects the database from values it would refuse or cut.
  • create_event() calls EventsTable::add(), answers 201 Created with the new event, and a real 500 if the insert failed. prepare_event() turns the table's strings into the types the schema promises, and the date into ISO 8601 (2027-12-16T19:00:00), the format JSON clients expect.

The schema is a promise to clients. Check every book of the catalog against it with rest_validate_value_from_schema(), and print how many are valid. Then show what the function says about a book whose price is the string "free".

❓ Common Questions at This Stage

Should my endpoints extend WP_REST_Controller?

Core's own routes are classes that extend WP_REST_Controller, which names the parts (register_routes(), get_items(), get_item(), create_item(), *_permissions_check(), prepare_item_for_response(), get_item_schema(), get_collection_params()) and gives helpers such as add_additional_fields_to_object(), so register_rest_field() works on your route too. For a plugin with many routes, or one that should feel exactly like core, extend it. The course's endpoints use the same parts with the plugin's own feature pattern, which is easier to read the first time; moving to the controller class later is mostly renaming.

Why version the namespace when there is only v1?

Because the shape will change one day (a price with a currency, genres as objects), and clients you do not control (a partner's site, an app on old phones) cannot all update the same day. With pagesco/v2 next to v1, both work while clients move. Adding a field is not a breaking change and needs no new version; removing or retyping one is.

Can another site's JavaScript call my endpoints (CORS)?

For public GET routes, yes: WordPress answers with Access-Control-Allow-Origin set to the requesting origin and exposes the X-WP-Total headers. Cookie authentication from another origin is not accepted (no nonce can come from there), which is the point; other sites' servers use application passwords. To restrict origins, filter rest_pre_serve_request or the allowed headers.

Should public routes be cached?

The books route runs two small queries, so not yet. On a busy site, page caches usually skip /wp-json/, and a popular endpoint can keep its answer in a transient keyed by its arguments, cleared when a book is saved. Lesson 7.3 introduces transients and Lesson 8.2 measures when caching pays off.

📝 Lesson Summary

🎓 Key Takeaways

  • Register routes with register_rest_route( 'vendor/v1', '/route', … ) on rest_api_init; a route holds one or more endpoints (methods + callback + permission callback + args) and a schema
  • Arguments with a type are validated and sanitized from their schema (ranges, enums, required, defaults); a sanitize_callback of your own replaces that, so keep 'validate_callback' => 'rest_validate_request_arg' next to it
  • Order of work: validate, sanitize, permission, callback; your callback receives clean, typed values
  • Return data, a WP_REST_Response (status, headers such as X-WP-Total), or a WP_Error with a prefixed code and an explicit status; without one, it is a 500
  • Every route has a permission_callback; __return_true only for public reads, a capability check for every write, rest_authorization_required_code() for 401/403
  • A JSON Schema documents the response (OPTIONS), and rest_do_request() calls routes from PHP without HTTP

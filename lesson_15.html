📚 Lesson 5.2: Custom Post Types, Taxonomies & Meta

Pages & Co. sells books, but WordPress only knows about posts and pages so far. In this lesson you teach it about books: a book post type with its own archive at /books/, a genre taxonomy to file them under, and the book details (author, price, pages) as meta the REST API and the block editor can read. Each one is a feature class in the plugin you built last lesson. Then you fill the shelves, seeding the eleven classics from the Pages & Co. catalog with one WP-CLI command.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Register a custom post type with register_post_type() on init, with labels, an archive and REST support
  • Register a custom taxonomy with register_taxonomy() and attach it to the post type
  • Register typed post meta with register_post_meta(), and explain why the keys are public and show_in_rest
  • Add a meta box and extra admin columns so editors can see and change a book's details
  • Flush rewrite rules at the right moment, and seed content safely with a WP-CLI script

  • 🧩 WordPress 7.1 on PHP 8.5 (register_post_meta with a label is 6.7+; nothing here needs 7.x)

📚 Why Books Deserve Their Own Type

Lesson 2.1 showed that in WordPress everything is a row in wp_posts, told apart by its post_type: a blog entry is a post, the About page is a page, an uploaded image is an attachment. A custom post type is simply a new value for that column, with its own admin menu, its own URLs and its own editing screen. Pages & Co. could store each book as a page, but then a book would sit in the same list as "About" and "Contact", have no price or author of its own, and share the /about/-style URLs. A book type gives the shop a Books menu, an archive at /books/, a single-book URL like /books/dune/, and a clean place to hang the details.

💡 Mental model: a new drawer in the same filing cabinet

In Lesson 2.1 we called wp_posts one big filing cabinet. A custom post type is a new labelled drawer in it, not a new cabinet: books are stored in the same table as posts and pages, with the same columns, so everything you already know (the Loop, WP_Query, revisions, the block editor) works on them for free. A taxonomy is the colored tabs you clip onto the files to group them (a book's genres), and meta is the index card you tuck into each file with its specific facts (this book's price, its author, its page count).

Three WordPress functions do the work, all called on the init action (the moment, from Lesson 2.3, when WordPress is ready and asks every plugin to register its things):

FunctionRegistersIn the project
register_post_type()A kind of contentbook
register_taxonomy()A way to group that contentgenre
register_post_meta()A named field on each itempagesco_author, pagesco_price, …

Each becomes a feature class in pagesco-books, following the rule from Lesson 5.1: one class in src/ implementing Feature, added to Plugin::feature_classes(). The post type and taxonomy also touch the URL rules, so the activation hook finally gets its second job.

📗 The Book Post Type

Create wordpress/wp-content/plugins/pagesco-books/src/BookPostType.php. The class registers the type on init; it also exposes a NAME constant, so no other file has to spell 'book' as a string (and risk a typo WordPress would silently treat as a different type):

<?php
/**
 * The book post type: the shop's catalog.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Registers the book post type on init.
 */
final class BookPostType implements Feature {

	/**
	 * The post type's name, stored in wp_posts.post_type.
	 */
	public const NAME = 'book';

	/**
	 * Hooks the registration into init.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'register_post_type' ) );
	}

	/**
	 * Registers the post type. Also called by Activator::activate().
	 */
	public function register_post_type(): void {
		register_post_type(
			self::NAME,
			array(
				'labels'        => array(
					'name'          => __( 'Books', 'pagesco-books' ),
					'singular_name' => __( 'Book', 'pagesco-books' ),
					'add_new_item'  => __( 'Add Book', 'pagesco-books' ),
					'edit_item'     => __( 'Edit Book', 'pagesco-books' ),
					'new_item'      => __( 'New Book', 'pagesco-books' ),
					'view_item'     => __( 'View Book', 'pagesco-books' ),
					'view_items'    => __( 'View Books', 'pagesco-books' ),
					'search_items'  => __( 'Search Books', 'pagesco-books' ),
					'not_found'     => __( 'No books found.', 'pagesco-books' ),
					'all_items'     => __( 'All Books', 'pagesco-books' ),
					'archives'      => __( 'Book Archives', 'pagesco-books' ),
					'item_updated'  => __( 'Book updated.', 'pagesco-books' ),
				),
				'public'        => true,
				'has_archive'   => 'books',
				'rewrite'       => array( 'slug' => 'books' ),
				'show_in_rest'  => true,
				'rest_base'     => 'books',
				'menu_position' => 5,
				'menu_icon'     => 'dashicons-book',
				'supports'      => array( 'title', 'editor', 'excerpt', 'thumbnail', 'custom-fields' ),
			)
		);
	}
}

The $args are the whole personality of the type. The ones that matter most here:

ArgumentWhat it does
public => trueVisitors can reach books; a shorthand that also sets show_ui, show_in_nav_menus and more
has_archive => 'books', rewrite => ['slug' => 'books']The archive at /books/ and single books at /books/<slug>/
show_in_rest => true, rest_base => 'books'Edit books in the block editor (it talks to REST) and expose /wp/v2/books (Module 7)
menu_icon, menu_positionA Dashicon and where the Books menu sits in wp-admin
supportsWhich editor panels appear: a title, the block editor, an excerpt, a featured image, and custom-fields (required for meta to reach REST)

🏷️ The Genre Taxonomy

WordPress already has two taxonomies you met in Lesson 2.1: categories (hierarchical) and tags (flat). A custom taxonomy adds your own. Books are grouped by genre (Fiction, Science Fiction, Classic, Fantasy, Dystopian), and genres can nest, so the taxonomy is hierarchical like categories. Create src/GenreTaxonomy.php:

<?php
/**
 * The genre taxonomy for books.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Registers the genre taxonomy on init.
 */
final class GenreTaxonomy implements Feature {

	/**
	 * The taxonomy's name, stored in wp_term_taxonomy.taxonomy.
	 */
	public const NAME = 'genre';

	/**
	 * Hooks the registration into init.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'register_taxonomy' ) );
	}

	/**
	 * Registers the taxonomy for books. Also called by Activator::activate().
	 */
	public function register_taxonomy(): void {
		register_taxonomy(
			self::NAME,
			array( BookPostType::NAME ),
			array(
				'labels'            => array(
					'name'          => __( 'Genres', 'pagesco-books' ),
					'singular_name' => __( 'Genre', 'pagesco-books' ),
					'search_items'  => __( 'Search Genres', 'pagesco-books' ),
					'all_items'     => __( 'All Genres', 'pagesco-books' ),
					'edit_item'     => __( 'Edit Genre', 'pagesco-books' ),
					'add_new_item'  => __( 'Add Genre', 'pagesco-books' ),
					'not_found'     => __( 'No genres found.', 'pagesco-books' ),
				),
				'hierarchical'      => true,
				'show_admin_column' => true,
				'show_in_rest'      => true,
				'rest_base'         => 'genres',
				'rewrite'           => array( 'slug' => 'genre' ),
			)
		);
	}
}

The second argument of register_taxonomy() is the post type (or an array of them) the taxonomy attaches to, here BookPostType::NAME. show_admin_column => true adds a Genres column to the Books list for free; show_in_rest with rest_base => 'genres' exposes /wp/v2/genres and lets the editor show a Genres panel. wp taxonomy list --fields=name,label,object_type,hierarchical
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/genre/fiction/

Flushing where it belongs: the activation hook

⚠️ Registering is not enough on activation

You might expect the activation hook to just call flush_rewrite_rules() and trust that init already registered the type and taxonomy. It has not, on that one request: when WordPress activates a plugin it loads your file in a sandbox, and the plugin's own init callback does not run before the activation callback fires. So the activator must register them itself first, then flush. (Every request after activation registers them normally on init.)

Now that both the type and the taxonomy exist, write the activator once, for both. Replace src/Activator.php with this version (the Bookseller role from Lesson 5.1 stays; add_role() does nothing when the role already exists):

<?php
/**
 * What happens when the plugin is activated or deactivated.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Activation and deactivation callbacks (uninstall.php cleans up for good).
 */
final class Activator {

	/**
	 * Runs once, when an administrator activates the plugin.
	 */
	public static function activate(): void {
		$author = get_role( 'author' );

		add_role(
			'pagesco_bookseller',
			'Bookseller',
			$author ? $author->capabilities : array( 'read' => true )
		);

		// init has already run on this request: register the post type and taxonomy now, so their rules exist.
		( new BookPostType() )->register_post_type();
		( new GenreTaxonomy() )->register_taxonomy();
		flush_rewrite_rules();
	}

	/**
	 * Runs once, when the plugin is deactivated. Keeps all data.
	 */
	public static function deactivate(): void {
		// Remove the post type's and taxonomy's rules, so /books/ stops answering while the plugin is off.
		unregister_post_type( BookPostType::NAME );
		unregister_taxonomy( GenreTaxonomy::NAME );
		flush_rewrite_rules();
	}
}

Deactivate and reactivate to run it, and confirm both archives still answer and the rules vanish while the plugin is off:

wp plugin deactivate pagesco-books
wp plugin activate pagesco-books
curl -s -o /dev/null -w 'books active: %{http_code}\n' http://localhost:8080/books/
wp plugin deactivate pagesco-books
curl -s -o /dev/null -w 'books off:    %{http_code}\n' http://localhost:8080/books/
wp plugin activate pagesco-books

Output

With the plugin off, /books/ is a 404: the type is no longer registered, Activator::deactivate() flushed the rules away, and the URL means nothing. That is exactly what you want, so a deactivated plugin leaves no broken links behind.

🗂️ Book Meta

A book's title is the post title and its description is the post content, but its author, price, page count, publication date and stock are facts that belong to the book and nothing else. Those are post meta: key/value rows in wp_postmeta (Lesson 2.2). You can store meta with update_post_meta() without registering anything, but register_post_meta() tells WordPress the shape of each key, so it can type-check values, show them in the REST API, and let the block editor and block bindings read them. Create src/BookMeta.php:

<?php
/**
 * The book's details, stored as post meta.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Registers the book meta keys on init.
 */
final class BookMeta implements Feature {

	/**
	 * Hooks the registration into init.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'register_meta' ) );
	}

	/**
	 * The book's meta keys with their types and labels.
	 *
	 * @return array<string, array{type: string, label: string}>
	 */
	public static function fields(): array {
		return array(
			'pagesco_author'    => array(
				'type'  => 'string',
				'label' => __( 'Author', 'pagesco-books' ),
			),
			'pagesco_price'     => array(
				'type'  => 'number',
				'label' => __( 'Price', 'pagesco-books' ),
			),
			'pagesco_pages'     => array(
				'type'  => 'integer',
				'label' => __( 'Pages', 'pagesco-books' ),
			),
			'pagesco_published' => array(
				'type'  => 'string',
				'label' => __( 'First published', 'pagesco-books' ),
			),
			'pagesco_in_stock'  => array(
				'type'  => 'boolean',
				'label' => __( 'In stock', 'pagesco-books' ),
			),
			'pagesco_isbn'      => array(
				'type'  => 'string',
				'label' => __( 'ISBN', 'pagesco-books' ),
			),
		);
	}

	/**
	 * Registers every key for the book post type: one value per book, visible in the REST API.
	 */
	public function register_meta(): void {
		foreach ( self::fields() as $key => $field ) {
			register_post_meta(
				BookPostType::NAME,
				$key,
				array(
					'type'         => $field['type'],
					'label'        => $field['label'],
					'single'       => true,
					'show_in_rest' => true,
				)
			);
		}
	}
}

Two arguments earn their place. 'single' => true means one value per book (so get_post_meta( $id, 'pagesco_price', true ) returns the number, not an array). 'show_in_rest' => true publishes the key in /wp/v2/books and lets the editor read and write it.

✅ Why the keys do not start with an underscore

A meta key that starts with _ (like the _edit_lock and _pingme keys you saw in Lesson 2.2) is protected: WordPress hides it from the Custom Fields box and refuses to expose it in REST unless you write a permission callback. Our keys are named pagesco_author, pagesco_price and so on, with the project's prefix but no leading underscore, precisely because the shop wants them public: the REST API returns them, and in Module 6 a block binds a heading to pagesco_price through the core/post-meta source, which only works for registered, REST-visible, unprotected keys.

wp eval 'foreach ( array_keys( get_registered_meta_keys( "post", "book" ) ) as $k ) { echo $k, "\n"; }'

🖥️ Seeing Books in the Admin

Registered meta reaches the block editor's Custom Fields panel, but a raw key/value list is a poor way to type a price. Two small admin features make the Books screen pleasant: a meta box, a labelled form under the editor, and extra columns in the books list. Both live under a sub-namespace, PagesCo\Books\Admin, which (Lesson 5.1's PSR-4 rule) maps to src/Admin/.

A "Book details" meta box

Create src/Admin/BookMetaBox.php. It adds the box on the book screen, renders a form filled with the saved values, and saves them when the book is saved:

<?php
/**
 * The "Book details" box on the book editing screen.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Admin;

use PagesCo\Books\BookPostType;
use PagesCo\Books\Feature;

/**
 * Shows the book meta as a form under the editor and saves it with the book.
 */
final class BookMetaBox implements Feature {

	/**
	 * Hooks the box into the book screen and the save into save_post_book.
	 */
	public function register(): void {
		add_action( 'add_meta_boxes_' . BookPostType::NAME, array( $this, 'add' ) );
		add_action( 'save_post_' . BookPostType::NAME, array( $this, 'save' ) );
	}

	/**
	 * Adds the box to the book editing screen.
	 */
	public function add(): void {
		add_meta_box(
			'pagesco-book-details',
			__( 'Book details', 'pagesco-books' ),
			array( $this, 'render' ),
			BookPostType::NAME,
			'normal',
			'high'
		);
	}

	/**
	 * Prints the form fields, filled with the saved values.
	 *
	 * @param \WP_Post $post The book being edited.
	 */
	public function render( $post ): void {
		wp_nonce_field( 'pagesco_books_save_details', 'pagesco_books_details_nonce' );

		$author    = get_post_meta( $post->ID, 'pagesco_author', true );
		$price     = get_post_meta( $post->ID, 'pagesco_price', true );
		$pages     = get_post_meta( $post->ID, 'pagesco_pages', true );
		$published = get_post_meta( $post->ID, 'pagesco_published', true );
		$isbn      = get_post_meta( $post->ID, 'pagesco_isbn', true );
		$in_stock  = get_post_meta( $post->ID, 'pagesco_in_stock', true );
		?>
		<p>
			<label for="pagesco-author"><?php esc_html_e( 'Author', 'pagesco-books' ); ?></label><br>
			<input type="text" id="pagesco-author" name="pagesco_author" class="widefat" value="<?php echo esc_attr( $author ); ?>">
		</p>
		<p>
			<label for="pagesco-price"><?php esc_html_e( 'Price (USD)', 'pagesco-books' ); ?></label><br>
			<input type="number" id="pagesco-price" name="pagesco_price" min="0" step="0.01" value="<?php echo esc_attr( $price ); ?>">
		</p>
		<p>
			<label for="pagesco-pages"><?php esc_html_e( 'Pages', 'pagesco-books' ); ?></label><br>
			<input type="number" id="pagesco-pages" name="pagesco_pages" min="1" step="1" value="<?php echo esc_attr( $pages ); ?>">
		</p>
		<p>
			<label for="pagesco-published"><?php esc_html_e( 'First published', 'pagesco-books' ); ?></label><br>
			<input type="date" id="pagesco-published" name="pagesco_published" value="<?php echo esc_attr( $published ); ?>">
		</p>
		<p>
			<label for="pagesco-isbn"><?php esc_html_e( 'ISBN', 'pagesco-books' ); ?></label><br>
			<input type="text" id="pagesco-isbn" name="pagesco_isbn" value="<?php echo esc_attr( $isbn ); ?>">
		</p>
		<p>
			<label>
				<input type="checkbox" name="pagesco_in_stock" value="1" <?php checked( (bool) $in_stock ); ?>>
				<?php esc_html_e( 'In stock', 'pagesco-books' ); ?>
			</label>
		</p>
		<?php
	}

	/**
	 * Saves the fields when the book is saved from this form.
	 *
	 * @param int $post_id The book's ID.
	 */
	public function save( $post_id ): void {
		// Only when the request comes from this form, and only for users who may edit this book.
		if ( ! isset( $_POST['pagesco_books_details_nonce'] )
			|| ! wp_verify_nonce( sanitize_key( wp_unslash( $_POST['pagesco_books_details_nonce'] ) ), 'pagesco_books_save_details' ) ) {
			return;
		}
		if ( ! current_user_can( 'edit_post', $post_id ) ) {
			return;
		}

		$fields = wp_unslash( $_POST );

		update_post_meta( $post_id, 'pagesco_author', sanitize_text_field( $fields['pagesco_author'] ?? '' ) );
		update_post_meta( $post_id, 'pagesco_price', (float) ( $fields['pagesco_price'] ?? 0 ) );
		update_post_meta( $post_id, 'pagesco_pages', absint( $fields['pagesco_pages'] ?? 0 ) );
		update_post_meta( $post_id, 'pagesco_published', sanitize_text_field( $fields['pagesco_published'] ?? '' ) );
		update_post_meta( $post_id, 'pagesco_isbn', sanitize_text_field( $fields['pagesco_isbn'] ?? '' ) );
		update_post_meta( $post_id, 'pagesco_in_stock', isset( $fields['pagesco_in_stock'] ) );
	}
}

Three details carry the lesson's security habits, each one covered in depth next lesson:

  • wp_nonce_field() prints a hidden token, and wp_verify_nonce() checks it on save, so the save only runs for a form this site served (Lesson 2.3 mentioned nonces; Lesson 5.3 is all about them).
  • current_user_can( 'edit_post', $post_id ) makes sure the person may edit this book before writing anything.
  • Every value is sanitized on the way in: sanitize_text_field(), absint() for the page count, a cast to float for the price, and a plain boolean for the checkbox.

Author, price and stock columns

Create src/Admin/BookColumns.php. One filter adds the column headings after the title; one action prints each cell:

<?php
/**
 * Extra columns on the Books screen.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Admin;

use PagesCo\Books\BookPostType;
use PagesCo\Books\Feature;

/**
 * Shows each book's author, price and stock in the list of books.
 */
final class BookColumns implements Feature {

	/**
	 * Hooks into the list table of the book post type.
	 */
	public function register(): void {
		add_filter( 'manage_' . BookPostType::NAME . '_posts_columns', array( $this, 'add_columns' ) );
		add_action( 'manage_' . BookPostType::NAME . '_posts_custom_column', array( $this, 'print_column' ), 10, 2 );
	}

	/**
	 * Adds the columns after the title.
	 *
	 * @param string[] $columns Column keys and headings.
	 * @return string[]
	 */
	public function add_columns( $columns ) {
		$new = array();
		foreach ( $columns as $key => $heading ) {
			$new[ $key ] = $heading;
			if ( 'title' === $key ) {
				$new['pagesco_author']   = __( 'Author', 'pagesco-books' );
				$new['pagesco_price']    = __( 'Price', 'pagesco-books' );
				$new['pagesco_in_stock'] = __( 'Stock', 'pagesco-books' );
			}
		}
		return $new;
	}

	/**
	 * Prints one cell of a custom column.
	 *
	 * @param string $column  The column key.
	 * @param int    $post_id The book in this row.
	 */
	public function print_column( $column, $post_id ): void {
		switch ( $column ) {
			case 'pagesco_author':
				echo esc_html( get_post_meta( $post_id, 'pagesco_author', true ) );
				break;
			case 'pagesco_price':
				echo esc_html( '$' . number_format_i18n( (float) get_post_meta( $post_id, 'pagesco_price', true ), 2 ) );
				break;
			case 'pagesco_in_stock':
				echo get_post_meta( $post_id, 'pagesco_in_stock', true )
					? esc_html__( 'In stock', 'pagesco-books' )
					: esc_html__( 'Sold out', 'pagesco-books' );
				break;
		}
	}
}

⚠️ Common Mistakes

1. Forgetting to flush, so single books 404

The commonest custom-post-type bug: the archive and single pages return 404 even though the code is right. It happens when the rewrite rules were not flushed after the type was registered. Reproduce it by resetting the rules to the state a browser install leaves and visiting a (not-yet-existing) book, then flushing:

wp option update rewrite_rules ''
curl -s -o /dev/null -w 'before flush: %{http_code}\n' http://localhost:8080/books/
wp rewrite flush
curl -s -o /dev/null -w 'after flush:  %{http_code}\n' http://localhost:8080/books/

Output

Success: Updated 'rewrite_rules' option.
before flush: 200
Success: Rewrite rules flushed.
after flush:  200

What it means: with no rules, WordPress cannot match /books/ and falls through to a 404; after a flush, the archive rule is back. Fix: flush on activation (as your Activator does), never on every request. Calling flush_rewrite_rules() on init is the classic performance mistake: it rewrites the whole rules option on every page load.

2. tax_input ignored when no user is logged in

When you create a book in code and try to set its genres with wp_insert_post()'s tax_input argument, the genres silently vanish if the current user cannot assign terms, and WP-CLI runs as no user. See it with a throwaway book:

BOOK=$(wp post create --post_type=book --post_title="Tax test" --post_status=draft --porcelain)
wp eval "wp_update_post( array( 'ID' => $BOOK, 'tax_input' => array( 'genre' => array( 'Fiction' ) ) ) );"
wp eval "var_export( wp_get_post_terms( $BOOK, 'genre', array( 'fields' => 'names' ) ) );"
wp post delete $BOOK --force

Output

array (
)Success: Deleted post 30.

What it means: tax_input is checked against the user's assign_terms capability, so in a script (which runs as no user) it is dropped and the genre list comes back as an empty array. Fix: set terms explicitly with wp_set_object_terms( $book_id, $genres, 'genre' ), which does not run the capability check. The seeding script uses exactly that. (This throwaway book took the next post ID, which is why the seeded catalog uses explicit IDs so everyone's Dune is still book 30.)

3. A meta value of the wrong type is refused by REST

register_post_meta() declared pagesco_pages an integer, so the REST API validates it. Send a string and watch it bounce (the runner sends this request as the editor Maria, who may edit books):

wp eval '$r = new WP_REST_Request( "POST", "/wp/v2/books" );
$r->set_body_params( array( "title" => "Bad pages", "status" => "draft", "meta" => array( "pagesco_pages" => "lots" ) ) );
$res = rest_do_request( $r );
echo $res->get_status(), "\n", wp_json_encode( $res->get_data()["code"] ?? "ok" ), "\n";
// The post was created before the meta was validated; remove the draft it left.
foreach ( get_posts( array( "post_type" => "book", "post_status" => "draft", "numberposts" => -1 ) ) as $p ) {
	wp_delete_post( $p->ID, true );
}' --user=maria

Output

400
"rest_invalid_type"

What it means: a 400 with rest_invalid_type: because the key is registered with 'type' => 'integer', the API rejects "lots". The post object was created first and the meta refused after, so the loop deletes the stray draft it left behind. That type declaration is doing real work. Fix: send the right type (a number), or, for data you store yourself, sanitize it first as the meta box does.

<?php
/**
 * Seeds the Pages & Co. catalog: the genres and the 11 books from books.json.
 *
 * Run from the WordPress root with WP-CLI: wp eval-file pagesco-seed/seed-books.php
 * Safe to run twice: books and genres that already exist are skipped.
 *
 * @package PagesCo\Books
 */

defined( 'ABSPATH' ) || exit;

if ( ! post_type_exists( 'book' ) || ! taxonomy_exists( 'genre' ) ) {
	WP_CLI::error( 'Activate the pagesco-books plugin first: the book post type and the genre taxonomy are missing.' );
}

$pagesco_data = json_decode( file_get_contents( __DIR__ . '/books.json' ), true );

// The genres, in this order, so their IDs are the same on every site.
foreach ( array( 'Fiction', 'Science Fiction', 'Classic', 'Fantasy', 'Dystopian' ) as $pagesco_genre ) {
	if ( ! term_exists( $pagesco_genre, 'genre' ) ) {
		$pagesco_term = wp_insert_term( $pagesco_genre, 'genre' );
		WP_CLI::log( sprintf( 'Genre %d: %s', $pagesco_term['term_id'], $pagesco_genre ) );
	}
}

$pagesco_editor = get_user_by( 'login', 'maria' );

foreach ( $pagesco_data['books'] as $pagesco_book ) {
	$pagesco_slug = sanitize_title( $pagesco_book['title'] );

	if ( get_page_by_path( $pagesco_slug, OBJECT, 'book' ) ) {
		WP_CLI::log( "Skipped {$pagesco_book['title']}: it already exists." );
		continue;
	}

	$pagesco_id = wp_insert_post(
		array(
			'post_type'   => 'book',
			'post_status' => 'publish',
			'post_title'  => $pagesco_book['title'],
			'post_name'   => $pagesco_slug,
			'post_author' => $pagesco_editor ? $pagesco_editor->ID : 1,
			// Fixed IDs (Dune is 30 ... Animal Farm is 40) so the whole class matches.
			'import_id'   => 29 + $pagesco_book['bookstore_id'],
			// One minute apart, so "newest first" lists are the same on every site.
			'post_date'   => gmdate( 'Y-m-d H:i:s', strtotime( '2026-10-01 10:00:00' ) + 60 * $pagesco_book['bookstore_id'] ),
			'meta_input'  => array(
				'pagesco_author'    => $pagesco_book['author'],
				'pagesco_price'     => $pagesco_book['price'],
				'pagesco_pages'     => $pagesco_book['pages'],
				'pagesco_published' => $pagesco_book['published'],
				'pagesco_in_stock'  => $pagesco_book['in_stock'],
			),
		),
		true
	);

	if ( is_wp_error( $pagesco_id ) ) {
		WP_CLI::warning( "{$pagesco_book['title']}: " . $pagesco_id->get_error_message() );
		continue;
	}

	// wp_set_object_terms(), not tax_input: see Common Mistakes.
	wp_set_object_terms( $pagesco_id, $pagesco_book['genres'], 'genre' );

	WP_CLI::log( sprintf( 'Book %d: %s', $pagesco_id, $pagesco_book['title'] ) );
}

WP_CLI::success( sprintf( '%d books in the catalog.', wp_count_posts( 'book' )->publish ) );

The runner writes books.json for you in the next block; on your own machine it came out of the zip.

<?php
/**
 * Seeds the Pages & Co. catalog: the genres and the 11 books from books.json.
 *
 * Run from the WordPress root with WP-CLI: wp eval-file pagesco-seed/seed-books.php
 * Safe to run twice: books and genres that already exist are skipped.
 *
 * @package PagesCo\Books
 */

defined( 'ABSPATH' ) || exit;

if ( ! post_type_exists( 'book' ) || ! taxonomy_exists( 'genre' ) ) {
	WP_CLI::error( 'Activate the pagesco-books plugin first: the book post type and the genre taxonomy are missing.' );
}

$pagesco_data = json_decode( file_get_contents( __DIR__ . '/books.json' ), true );

// The genres, in this order, so their IDs are the same on every site.
foreach ( array( 'Fiction', 'Science Fiction', 'Classic', 'Fantasy', 'Dystopian' ) as $pagesco_genre ) {
	if ( ! term_exists( $pagesco_genre, 'genre' ) ) {
		$pagesco_term = wp_insert_term( $pagesco_genre, 'genre' );
		WP_CLI::log( sprintf( 'Genre %d: %s', $pagesco_term['term_id'], $pagesco_genre ) );
	}
}

$pagesco_editor = get_user_by( 'login', 'maria' );

foreach ( $pagesco_data['books'] as $pagesco_book ) {
	$pagesco_slug = sanitize_title( $pagesco_book['title'] );

	if ( get_page_by_path( $pagesco_slug, OBJECT, 'book' ) ) {
		WP_CLI::log( "Skipped {$pagesco_book['title']}: it already exists." );
		continue;
	}

	$pagesco_id = wp_insert_post(
		array(
			'post_type'   => 'book',
			'post_status' => 'publish',
			'post_title'  => $pagesco_book['title'],
			'post_name'   => $pagesco_slug,
			'post_author' => $pagesco_editor ? $pagesco_editor->ID : 1,
			// Fixed IDs (Dune is 30 ... Animal Farm is 40) so the whole class matches.
			'import_id'   => 29 + $pagesco_book['bookstore_id'],
			// One minute apart, so "newest first" lists are the same on every site.
			'post_date'   => gmdate( 'Y-m-d H:i:s', strtotime( '2026-10-01 10:00:00' ) + 60 * $pagesco_book['bookstore_id'] ),
			'meta_input'  => array(
				'pagesco_author'    => $pagesco_book['author'],
				'pagesco_price'     => $pagesco_book['price'],
				'pagesco_pages'     => $pagesco_book['pages'],
				'pagesco_published' => $pagesco_book['published'],
				'pagesco_in_stock'  => $pagesco_book['in_stock'],
			),
		),
		true
	);

	if ( is_wp_error( $pagesco_id ) ) {
		WP_CLI::warning( "{$pagesco_book['title']}: " . $pagesco_id->get_error_message() );
		continue;
	}

	// wp_set_object_terms(), not tax_input: see Common Mistakes.
	wp_set_object_terms( $pagesco_id, $pagesco_book['genres'], 'genre' );

	WP_CLI::log( sprintf( 'Book %d: %s', $pagesco_id, $pagesco_book['title'] ) );
}

WP_CLI::success( sprintf( '%d books in the catalog.', wp_count_posts( 'book' )->publish ) );

🏋️ Exercise 4: Register One More Meta Key (Stretch)

Suppose the shop wants to show each book's reading time. Register one more public meta key for books, pagesco_reading_minutes (an integer), compute and store it for Dune as its page count times two, and confirm it reaches REST. Do it from a throwaway must-use plugin so BookMeta and the catalog stay exactly as the project left them, then remove the file and the stored value.

💡 Hint

Call register_post_meta( 'book', 'pagesco_reading_minutes', array( 'type' => 'integer', 'single' => true, 'show_in_rest' => true ) ) on init in mu-plugins/exercise-reading-time.php. A key registered show_in_rest shows in /wp/v2/books/30?_fields=meta once it has a value. In the real plugin you would instead add one entry to BookMeta::fields(), which the loop would register for you.

✅ Solution 
<?php
/**
 * Plugin Name: Exercise: Reading Time
 */

add_action(
	'init',
	function () {
		register_post_meta(
			'book',
			'pagesco_reading_minutes',
			array(
				'type'         => 'integer',
				'single'       => true,
				'show_in_rest' => true,
			)
		);
	}
);
wp eval 'update_post_meta( 30, "pagesco_reading_minutes", (int) get_post_meta( 30, "pagesco_pages", true ) * 2 );'
wp eval 'echo in_array( "pagesco_reading_minutes", array_keys( get_registered_meta_keys( "post", "book" ) ), true ) ? "registered\n" : "no\n";'
wp post meta get 30 pagesco_reading_minutes
rm wp-content/mu-plugins/exercise-reading-time.php
wp eval 'delete_post_meta( 30, "pagesco_reading_minutes" );'

Registering one key took the same register_post_meta() call the plugin uses in a loop; in BookMeta it would have been a single new entry in fields(). ❓ Common Questions at This Stage

Should I use a plugin like ACF, Meta Box or CMB2 instead of writing this?

Those are good tools. Advanced Custom Fields, Meta Box and CMB2 give you fields and meta boxes through a settings screen or a short array, and for a client site built quickly they save real time. The course registers meta and a box by hand for three reasons: you learn what those plugins do under the hood (they all call register_post_meta and add_meta_box); the Pages & Co. plugin stays free of a dependency that would have to be installed on every site it runs on; and your fields reach the REST API and block bindings with no extra configuration. On a real project, reach for ACF when the client needs to add fields themselves, and hand-register meta when you want a lightweight, portable, version-controlled plugin.

Should the post type be registered in a plugin or in the theme?

Always a plugin. Content outlives design: if book lived in the theme's functions.php, switching themes would unregister the type and every book would vanish from the admin (the rows stay in the database, but nothing displays or edits them). That is the whole reason Pages & Co. keeps its catalog in pagesco-books and its looks in the pagesco theme, the split Lesson 3.4 drew.

What is the difference between a taxonomy and a meta field for something like genre?

Use a taxonomy when many items share a value you want to browse or filter by: genres are shared across books and have their own archive pages, so genre is a taxonomy. Use meta for a fact that belongs to one item and that you mostly read, not browse: a price or a page count is meta. A rough test: if you would want a /genre/fantasy/ page listing everything with that value, it is a taxonomy; if not, it is meta.

Do I lose my books if I deactivate the plugin?

No. Deactivating stops the type being registered, so the books disappear from the admin and their URLs 404, but the rows stay in wp_posts and their meta in wp_postmeta. Reactivate and everything returns. Only uninstall.php deletes data, and the one you wrote in Lesson 5.1 only removes the role so far; whether deleting the plugin should also delete the books is a real decision, which the FAQ of Lesson 5.4 revisits.

📝 Lesson Summary

🎓 Key Takeaways

  • A custom post type is a new value in wp_posts.post_type; register it with register_post_type() on init, with labels, has_archive, a rewrite slug and show_in_rest
  • A custom taxonomy groups a post type; register_taxonomy()'s second argument is the type it attaches to
  • register_post_meta() gives a meta key a type, a label and REST visibility; keep shop keys free of a leading underscore so they stay public and bindable
  • New post types and taxonomies add rewrite rules: flush them on activation (and in the activator register them first, because init has not run yet on that request), never on init
  • A meta box plus admin columns make the data editable and visible; the save path uses a nonce, a capability check and sanitization (Lesson 5.3)
  • Seed content with an idempotent WP-CLI script and wp_set_object_terms(), not tax_input, so it works with no user logged in

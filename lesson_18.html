🗓️ Lesson 5.5: Shortcodes, $wpdb & Custom Tables

Since Lesson 2.1 the Events page has promised that "the full calendar is coming soon." Today it arrives. Events are not like books: the shop has many of them, each one a few fixed fields, always listed by date and never written in the block editor. That makes them a good fit for something WordPress lets you do but asks you to think twice about: a table of your own. You will create it with dbDelta(), upgrade it with a versioned migration, read and write it with $wpdb and prepare(), and put it on the page with a [pagesco_events] shortcode. A second shortcode, [pagesco_book], drops a book card into any post.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Register shortcodes with add_shortcode() whose callbacks return escaped HTML, with attributes handled by shortcode_atts()
  • Decide when a custom table is the right storage, and when post types, meta, taxonomies or options are
  • Create and upgrade a table with dbDelta() and a schema version stored in an option
  • Read and write rows with $wpdb: insert(), update(), delete(), get_row(), get_var(), get_results(), always through prepare() or format arrays
  • Remove the table and its version option in uninstall.php

  • 📋 Prerequisites Lesson 5.4: Admin Pages, Settings API & Options

🔖 Shortcodes: Small Tags, Real Output

A shortcode is a tag in square brackets, such as [gallery] or [embed], that an editor types into content and WordPress replaces with HTML when the content is displayed. Core ships a few ([caption], [gallery], [audio], [video], [playlist], [embed]); plugins add their own. They are older than blocks, and for anything an editor arranges visually, blocks are now the better tool (Module 6 builds them). Shortcodes are still the quickest way to put plugin output into content anywhere: a paragraph, the Shortcode block, a classic widget, a classic theme's template.

💡 Mental model: a placeholder card in the shop window

Picture the shop window display with a small card that reads "Book of the Month goes here". Whoever dresses the window does not need to know the price or the stock; every morning someone swaps the card for the real book. A shortcode is that card: the editor writes [pagesco_book id="30"], and on every page view your callback swaps it for the book's current title, price and stock. Change the price in the catalog and every card follows.

The mechanics are one function and one rule. add_shortcode( $tag, $callback ), called on init, connects a tag to a callback. The callback receives the attributes, any enclosed content and the tag name, and returns the HTML. WordPress runs do_shortcode() on the_content at priority 11 (you saw it in Lesson 2.3's Exercise 3), right after wpautop, and puts whatever you return where the tag was. Create wordpress/wp-content/plugins/pagesco-books/src/Shortcodes/BookShortcode.php (a new PagesCo\Books\Shortcodes sub-namespace, so a new src/Shortcodes/ folder):

<?php
/**
 * The [pagesco_book id="30"] shortcode.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Shortcodes;

use PagesCo\Books\BookPostType;
use PagesCo\Books\Feature;

/**
 * Prints a one-line card for a book: title (linked), author, price and stock.
 */
final class BookShortcode implements Feature {

	/**
	 * The shortcode's tag, the name inside the brackets.
	 */
	public const TAG = 'pagesco_book';

	/**
	 * Registers the shortcode on init.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'add_shortcode' ) );
	}

	/**
	 * Tells WordPress which callback renders [pagesco_book].
	 */
	public function add_shortcode(): void {
		add_shortcode( self::TAG, array( $this, 'render' ) );
	}

	/**
	 * Returns the card's HTML; never echoes.
	 *
	 * @param array|string $atts The attributes written in the shortcode ('' when there are none).
	 * @return string
	 */
	public function render( $atts ) {
		$atts = shortcode_atts( array( 'id' => 0 ), $atts, self::TAG );
		$book = get_post( absint( $atts['id'] ) );

		if ( ! $book || BookPostType::NAME !== $book->post_type || 'publish' !== $book->post_status ) {
			return '';
		}

		$author   = get_post_meta( $book->ID, 'pagesco_author', true );
		$price    = (float) get_post_meta( $book->ID, 'pagesco_price', true );
		$in_stock = (bool) get_post_meta( $book->ID, 'pagesco_in_stock', true );

		return sprintf(
			'<span class="pagesco-book"><a href="%1$s">%2$s</a> %3$s, <span class="pagesco-book__price">%4$s</span> <span class="pagesco-book__stock">%5$s</span></span>',
			esc_url( get_permalink( $book ) ),
			esc_html( get_the_title( $book ) ),
			/* translators: %s: the book's author. */
			esc_html( sprintf( __( 'by %s', 'pagesco-books' ), $author ) ),
			esc_html( '$' . number_format_i18n( $price, 2 ) ),
			$in_stock ? esc_html__( 'In stock', 'pagesco-books' ) : esc_html__( 'Sold out', 'pagesco-books' )
		);
	}
}

Everything Lesson 5.3 taught applies, because a shortcode's output lands in a public page: the ID is forced to an integer with absint(), the post is checked to be a published book (no drafts or private posts leaking through a shortcode), and every value is escaped for its context. The card is a <span>, so it fits inside a sentence as well as on a line of its own. List the feature (after Admin\SettingsPage::class,) and run a shortcode by hand with do_shortcode():

sed -i '/Admin\\SettingsPage::class,/a\			Shortcodes\\BookShortcode::class,' wp-content/plugins/pagesco-books/src/Plugin.php

🎛️ Attributes and shortcode_atts()

Attributes arrive as an array of strings, or as an empty string when the tag has none. shortcode_atts( $defaults, $atts, $tag ) turns that into a predictable array: every key from the defaults is present, values the editor gave replace the defaults, and attributes you did not declare are dropped. The third argument also creates a filter, shortcode_atts_pagesco_book, so other code can adjust the attributes (Exercise 4 uses it). Watch it handle four ways of writing the tag:

<?php
$cases = array(
	'[pagesco_book id="33"]',               // another book
	'[pagesco_book id="12"]',               // ID 12 is the About page, not a book
	'[pagesco_book]',                       // no attributes at all
	'[pagesco_book ID="35" color="red"]',   // upper-case name, unknown attribute
);
foreach ( $cases as $case ) {
	echo $case, "\n  => '", do_shortcode( $case ), "'\n";
}

Output

[pagesco_book id="33"]
  => '<span class="pagesco-book"><a href="http://localhost:8080/books/the-great-gatsby/">The Great Gatsby</a> by F. Scott Fitzgerald, <span class="pagesco-book__price">$8.99</span> <span class="pagesco-book__stock">Sold out</span></span>'
[pagesco_book id="12"]
  => ''
[pagesco_book]
  => ''
[pagesco_book ID="35" color="red"]
  => '<span class="pagesco-book"><a href="http://localhost:8080/books/the-hobbit/">The Hobbit</a> by J.R.R. Tolkien, <span class="pagesco-book__price">$10.99</span> <span class="pagesco-book__stock">In stock</span></span>'

Line by line: Gatsby is found and shows "Sold out"; the About page is not a book, so the callback returns an empty string and the tag simply disappears; with no attributes id is the default 0, which finds nothing; and attribute names are lowercased by the parser, so ID still works while color, never declared, is ignored. Returning '' for bad input is a deliberate choice: a visitor should never see an error message because an editor mistyped an ID. (Delete the test file: rm shortcode-cases.php.)

rm shortcode-cases.php

✅ Shortcode or block?

Write a block when an editor should see and arrange the output in the editor (a preview, controls in the sidebar, no syntax to remember). Write a shortcode when the output must work everywhere text goes, including places blocks do not reach, or as a quick, stable interface for content that already exists. Many plugins offer both, sharing one PHP function that builds the HTML; Lesson 6.3's dynamic block can call the same code these shortcodes use.

🗄️ When a Custom Table Is Right

Lesson 2.2 compared WordPress's storage choices; now you are about to use the last one. The default answer for plugin data is not a custom table: post types, meta and taxonomies give you the admin screens, the REST API, revisions, caching, export and import for free. A table of your own gives up all of that. So ask what the data looks like:

The data is…Store it asPages & Co. example
Content people write, edit and publishA post type (+ meta)Books (Lesson 5.2)
A shared label to group and browse byA taxonomyGenres
A few site-wide valuesAn optionSettings (Lesson 5.4)
Many rows with the same few fields, queried by those fields (dates, ranges, counts), not edited as contentA custom tableEvents; later perhaps orders, bookings, logs

Events fit the last row: every event has the same five facts, the page always asks "the next few events in date order", and nobody needs revisions of an event or a block editor to write one. Stored as posts with meta, "events in date order" would mean a join on wp_postmeta and sorting a string column (the trap from Lesson 2.2); in a table, starts_at is a real DATETIME column with an index. The price you pay: you write the schema, the queries, any admin screen, the upgrade path and the cleanup yourself. This lesson does each of those.

🏗️ Creating the Table with dbDelta()

WordPress creates and upgrades its own tables with a function from wp-admin/includes/upgrade.php: dbDelta(). You give it the CREATE TABLE statement for the table as it should be; it compares that with the database and creates the table, or adds the columns and indexes that are missing. That makes one statement serve both new installs and upgrades. It is also picky about how the statement is written:

  • One column or index per line, with CREATE TABLE in capitals and the table name right after it
  • A PRIMARY KEY, and indexes written as KEY name (column)
  • The site's character set and collation appended with $wpdb->get_charset_collate()
  • The table name built from $wpdb->prefix, never a hard-coded wp_ (Lesson 2.2's rule; on multisite every site has its own prefix)

Here is the first version of the events table: an ID, a title, the start (in the shop's local time), the location and a created_at time stamp in UTC. A schema version, the constant DB_VERSION, is stored in the option pagesco_books_db_version once the table is built. Create src/EventsTable.php:

<?php
/**
 * The shop's events, kept in a custom table.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Creates and upgrades the {prefix}pagesco_events table, and reads and writes its rows.
 */
final class EventsTable implements Feature {

	/**
	 * The schema version this code expects. Raise it whenever schema() changes.
	 */
	public const DB_VERSION = 1;

	/**
	 * The option that records the schema version installed in this database.
	 */
	public const VERSION_OPTION = 'pagesco_books_db_version';

	/**
	 * Checks the schema on every request, so a plugin update upgrades the table without a reactivation.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'maybe_upgrade' ) );
	}

	/**
	 * The table's full name, with this site's table prefix.
	 */
	public static function name(): string {
		global $wpdb;

		return $wpdb->prefix . 'pagesco_events';
	}

	/**
	 * Runs install() when the database is older than this code.
	 */
	public function maybe_upgrade(): void {
		if ( (int) get_option( self::VERSION_OPTION, 0 ) < self::DB_VERSION ) {
			self::install();
		}
	}

	/**
	 * Creates the table, or brings an existing one up to schema(), and records the version.
	 */
	public static function install(): void {
		require_once ABSPATH . 'wp-admin/includes/upgrade.php';

		dbDelta( self::schema() );
		update_option( self::VERSION_OPTION, self::DB_VERSION );
	}

	/**
	 * The CREATE TABLE statement in the exact shape dbDelta() expects.
	 */
	private static function schema(): string {
		global $wpdb;

		$table   = self::name();
		$collate = $wpdb->get_charset_collate();

		return "CREATE TABLE {$table} (
			id bigint unsigned NOT NULL AUTO_INCREMENT,
			title varchar(200) NOT NULL,
			starts_at datetime NOT NULL,
			location varchar(200) NOT NULL DEFAULT '',
			created_at datetime NOT NULL,
			PRIMARY KEY  (id),
			KEY starts_at (starts_at)
		) {$collate};";
	}

	/**
	 * Adds one event and returns its ID (0 if the insert failed).
	 *
	 * @param string $title     The event's name.
	 * @param string $starts_at Local date and time, Y-m-d H:i:s.
	 * @param string $location  Where in the shop.
	 */
	public static function add( string $title, string $starts_at, string $location ): int {
		global $wpdb;

		$inserted = $wpdb->insert(
			self::name(),
			array(
				'title'      => $title,
				'starts_at'  => $starts_at,
				'location'   => $location,
				'created_at' => current_time( 'mysql', true ),
			),
			array( '%s', '%s', '%s', '%s' )
		);

		return $inserted ? (int) $wpdb->insert_id : 0;
	}

	/**
	 * Returns events in date order, optionally only those at one location.
	 *
	 * @param int    $limit    How many events at most.
	 * @param string $location Exact location, or '' for every location.
	 * @return object[] Rows with id, title, starts_at, location.
	 */
	public static function find( int $limit, string $location = '' ): array {
		global $wpdb;

		if ( '' === $location ) {
			$sql = $wpdb->prepare(
				'SELECT id, title, starts_at, location FROM %i ORDER BY starts_at ASC LIMIT %d',
				self::name(),
				$limit
			);
		} else {
			$sql = $wpdb->prepare(
				'SELECT id, title, starts_at, location FROM %i WHERE location = %s ORDER BY starts_at ASC LIMIT %d',
				self::name(),
				$location,
				$limit
			);
		}

		return $wpdb->get_results( $sql );
	}
}

Two moments build the table, and you need both. Activation: Activator::activate() calls EventsTable::install(), so the table exists from the first request. Upgrades: when a site updates the plugin, WordPress replaces its files but does not run the activation hook again (Lesson 5.1's life cycle). So the feature also compares the stored version with DB_VERSION on init; that costs one autoloaded get_option() and runs install() only when the code is newer than the database. Replace src/Activator.php (only the last lines of activate() are new):

<?php
/**
 * What happens when the plugin is activated or deactivated.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Activation and deactivation callbacks (uninstall.php cleans up for good).
 */
final class Activator {

	/**
	 * Runs once, when an administrator activates the plugin.
	 */
	public static function activate(): void {
		$author = get_role( 'author' );

		add_role(
			'pagesco_bookseller',
			'Bookseller',
			$author ? $author->capabilities : array( 'read' => true )
		);

		// init has already run on this request: register the post type and taxonomy now, so their rules exist.
		( new BookPostType() )->register_post_type();
		( new GenreTaxonomy() )->register_taxonomy();
		flush_rewrite_rules();

		// Create the events table, or bring it up to date (Lesson 5.5).
		EventsTable::install();
	}

	/**
	 * Runs once, when the plugin is deactivated. Keeps all data.
	 */
	public static function deactivate(): void {
		// Remove the post type's and taxonomy's rules, so /books/ stops answering while the plugin is off.
		unregister_post_type( BookPostType::NAME );
		unregister_taxonomy( GenreTaxonomy::NAME );
		flush_rewrite_rules();
	}
}

The table exists with the five columns, id is the auto-increment primary key, starts_at carries an index (MUL), and version 1 is recorded. (In SQL, at the MySQL prompt or with wp db query, you type the real name wp_pagesco_events; in PHP you always build it from $wpdb->prefix, which is what EventsTable::name() does.) The integer columns are written without display widths (bigint unsigned, not bigint(20) unsigned): MySQL 8 and later ignore those widths and print the type without them, and dbDelta() in 7.1 compares the two forms correctly either way.

🔌 Reading and Writing Rows with $wpdb

$wpdb (Lesson 1.3 and 2.2) is WordPress's database object. For your own table you will use six of its methods, and the rule from Lesson 5.3 holds for all of them: values reach SQL only through placeholders, either in $wpdb->prepare() or as the format arrays of the write helpers.

MethodReturnsUse it for
insert( $table, $data, $formats )rows inserted or false; the new ID in $wpdb->insert_idAdding a row
update( $table, $data, $where, $formats, $where_formats )rows changed or falseChanging rows
delete( $table, $where, $where_formats )rows deleted or falseRemoving rows
get_var( $sql )one valueCOUNT(*), a single field
get_row( $sql )one row as an objectFetching by ID
get_results( $sql )an array of row objectsLists

The formats are the same placeholders prepare() uses: %s string, %d integer, %f float, and for table and column names %i, which quotes an identifier with backticks. Walk one test event through its whole life in a script in the WordPress root:

<?php
use PagesCo\Books\EventsTable;

global $wpdb;
$table = EventsTable::name();

$id = EventsTable::add( 'Test event', '2027-10-31 12:00:00', 'Back office' );
echo "insert: new ID $id\n";

$row = $wpdb->get_row( $wpdb->prepare( 'SELECT title, location FROM %i WHERE id = %d', $table, $id ) );
echo "get_row: {$row->title} in the {$row->location}\n";

$changed = $wpdb->update( $table, array( 'location' => 'Café' ), array( 'id' => $id ), array( '%s' ), array( '%d' ) );
echo "update: $changed row(s) changed\n";

echo 'prepare: ', $wpdb->prepare( 'SELECT COUNT(*) FROM %i WHERE location = %s', $table, "Children's corner" ), "\n";

$deleted = $wpdb->delete( $table, array( 'id' => $id ), array( '%d' ) );
echo "delete: $deleted row(s) deleted\n";
echo 'rows left: ', $wpdb->get_var( $wpdb->prepare( 'SELECT COUNT(*) FROM %i', $table ) ), "\n";

Output

insert: new ID 1
get_row: Test event in the Back office
update: 1 row(s) changed
prepare: SELECT COUNT(*) FROM `wp_pagesco_events` WHERE location = 'Children\'s corner'
delete: 1 row(s) deleted
rows left: 0

Insert, read, change, delete, each with its values passed separately from the SQL. The prepare: line shows what reaches MySQL: the table name in backticks from %i, the apostrophe in "Children's corner" escaped inside quotes, so it cannot end the string early. Notice also what EventsTable::add() hides from its callers: the table name, the formats and the created_at stamp. Keeping all SQL for a table in one class means the shortcode, and later a REST endpoint, never write SQL themselves. Remove the script:

rm events-crud.php

🧩 Version note: %i needs WordPress 6.2

The identifier placeholder arrived in WordPress 6.2. The plugin's header says Requires at least: 6.8, so it is safe here. On a plugin that must support older versions, table names cannot go through prepare(): you interpolate {$wpdb->prefix} (a value WordPress controls, never user input) and keep placeholders for every value, which is what most older plugins you will read do.

⚠️ Common Mistakes

1. A shortcode that echoes instead of returning

The most common shortcode bug, written as a throwaway must-use plugin and placed on a test page:

<?php
/**
 * Plugin Name: Mistake: Echoing Shortcode
 */

add_shortcode(
	'pagesco_hours',
	function () {
		echo '<p class="pagesco-hours">Open until 9 p.m. on Thursdays.</p>';
	}
);
<!-- wp:paragraph -->
<p>Our opening hours:</p>
<!-- /wp:paragraph -->

<!-- wp:shortcode -->
[pagesco_hours]
<!-- /wp:shortcode -->
wp post create hours-test.html --post_type=page --post_title="Hours test" --post_name=hours-test --post_status=publish --porcelain > /dev/null
curl -s http://localhost:8080/hours-test/ | head -n 2
curl -s http://localhost:8080/hours-test/ | grep -c 'Our opening hours'

Output

<p class="pagesco-hours">Open until 9 p.m. on Thursdays.</p><!DOCTYPE html>
<html lang="en-US">
1

What it means: the hours appear above <!DOCTYPE html>, outside the page, while the paragraph that introduces them sits in the content further down. echo prints the moment the callback runs, and a block theme renders the whole template, content included, before it prints the <head> (the same effect as Lesson 2.3's Common Mistake 1). In a classic theme the text would land at the top of the content area instead: wrong, but less obviously. No warning, no notice. Fix: build a string and return it; if you prefer writing HTML in template style, wrap it in ob_start() … return ob_get_clean();. Clean up:

wp post delete $(wp post list --post_type=page --name=hours-test --field=ID) --force > /dev/null
rm hours-test.html wp-content/mu-plugins/mistake-echo.php

2. Changing the schema without raising the version

Say the shop wants a host for each event. You add the column to schema(), reload, and… nothing. The sed line adds host after created_at as you would in your editor:

sed -i 's/^\t\t\tcreated_at datetime NOT NULL,$/&\n\t\t\thost varchar(100) NOT NULL,/' wp-content/plugins/pagesco-books/src/EventsTable.php
grep -n "host varchar" wp-content/plugins/pagesco-books/src/EventsTable.php
curl -s -o /dev/null http://localhost:8080/
wp option get pagesco_books_db_version
wp db query "SELECT COUNT(*) AS host_columns FROM information_schema.COLUMNS WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'wp_pagesco_events' AND COLUMN_NAME = 'host'"

Output

75:			host varchar(100) NOT NULL,
1
host_columns
0

What it means: the code describes a host column, but the table has none (0). maybe_upgrade() only runs install() when the stored version is lower than DB_VERSION, and both are still 1, so dbDelta() never saw the new statement. The first query that reads host would fail with "Unknown column". Fix: every schema change comes with a higher DB_VERSION; the project does exactly that for capacity. Take the host line out again:

sed -i '/host varchar(100)/d' wp-content/plugins/pagesco-books/src/EventsTable.php

3. Expecting dbDelta() to rename or drop

dbDelta() only adds. Rename a column in the statement and it adds a new, empty column next to the old one. See it on a throwaway table:

<?php
require_once ABSPATH . 'wp-admin/includes/upgrade.php';
global $wpdb;
$table   = $wpdb->prefix . 'pagesco_demo';
$collate = $wpdb->get_charset_collate();

print_r( dbDelta( "CREATE TABLE {$table} (
	id bigint unsigned NOT NULL AUTO_INCREMENT,
	location varchar(200) NOT NULL DEFAULT '',
	PRIMARY KEY  (id)
) {$collate};" ) );

// "Rename" location to venue:
print_r( dbDelta( "CREATE TABLE {$table} (
	id bigint unsigned NOT NULL AUTO_INCREMENT,
	venue varchar(200) NOT NULL DEFAULT '',

🛠️ Step 1: Migrate to version 2: seats per event (10 min)

Readings and book clubs have limited seats. Add a capacity column (0 means open to all) and, because the schema changed, raise DB_VERSION to 2. add() and find() learn the new column too. Replace src/EventsTable.php:

<?php
/**
 * The shop's events, kept in a custom table.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books;

/**
 * Creates and upgrades the {prefix}pagesco_events table, and reads and writes its rows.
 */
final class EventsTable implements Feature {

	/**
	 * The schema version this code expects. Raise it whenever schema() changes.
	 */
	public const DB_VERSION = 2;

	/**
	 * The option that records the schema version installed in this database.
	 */
	public const VERSION_OPTION = 'pagesco_books_db_version';

	/**
	 * Checks the schema on every request, so a plugin update upgrades the table without a reactivation.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'maybe_upgrade' ) );
	}

	/**
	 * The table's full name, with this site's table prefix.
	 */
	public static function name(): string {
		global $wpdb;

		return $wpdb->prefix . 'pagesco_events';
	}

	/**
	 * Runs install() when the database is older than this code.
	 */
	public function maybe_upgrade(): void {
		if ( (int) get_option( self::VERSION_OPTION, 0 ) < self::DB_VERSION ) {
			self::install();
		}
	}

	/**
	 * Creates the table, or brings an existing one up to schema(), and records the version.
	 */
	public static function install(): void {
		require_once ABSPATH . 'wp-admin/includes/upgrade.php';

		dbDelta( self::schema() );
		update_option( self::VERSION_OPTION, self::DB_VERSION );
	}

	/**
	 * The CREATE TABLE statement in the exact shape dbDelta() expects.
	 */
	private static function schema(): string {
		global $wpdb;

		$table   = self::name();
		$collate = $wpdb->get_charset_collate();

		return "CREATE TABLE {$table} (
			id bigint unsigned NOT NULL AUTO_INCREMENT,
			title varchar(200) NOT NULL,
			starts_at datetime NOT NULL,
			location varchar(200) NOT NULL DEFAULT '',
			capacity smallint unsigned NOT NULL DEFAULT 0,
			created_at datetime NOT NULL,
			PRIMARY KEY  (id),
			KEY starts_at (starts_at)
		) {$collate};";
	}

	/**
	 * Adds one event and returns its ID (0 if the insert failed).
	 *
	 * @param string $title     The event's name.
	 * @param string $starts_at Local date and time, Y-m-d H:i:s.
	 * @param string $location  Where in the shop.
	 * @param int    $capacity  Seats, or 0 for an open event.
	 */
	public static function add( string $title, string $starts_at, string $location, int $capacity ): int {
		global $wpdb;

		$inserted = $wpdb->insert(
			self::name(),
			array(
				'title'      => $title,
				'starts_at'  => $starts_at,
				'location'   => $location,
				'capacity'   => $capacity,
				'created_at' => current_time( 'mysql', true ),
			),
			array( '%s', '%s', '%s', '%d', '%s' )
		);

		return $inserted ? (int) $wpdb->insert_id : 0;
	}

	/**
	 * Returns events in date order, optionally only those at one location.
	 *
	 * @param int    $limit    How many events at most.
	 * @param string $location Exact location, or '' for every location.
	 * @return object[] Rows with id, title, starts_at, location, capacity.
	 */
	public static function find( int $limit, string $location = '' ): array {
		global $wpdb;

		if ( '' === $location ) {
			$sql = $wpdb->prepare(
				'SELECT id, title, starts_at, location, capacity FROM %i ORDER BY starts_at ASC LIMIT %d',
				self::name(),
				$limit
			);
		} else {
			$sql = $wpdb->prepare(
				'SELECT id, title, starts_at, location, capacity FROM %i WHERE location = %s ORDER BY starts_at ASC LIMIT %d',
				self::name(),
				$location,
				$limit
			);
		}

		return $wpdb->get_results( $sql );
	}
}

🛠️ Step 3: The [pagesco_events] shortcode and the season's events (12 min)

Create src/Shortcodes/EventsShortcode.php. It takes two attributes: limit, whose default is the Events to show setting from Lesson 5.4, and location, which narrows the list to one place in the shop. The SQL stays in EventsTable::find():

<?php
/**
 * The [pagesco_events] shortcode.
 *
 * @package PagesCo\Books
 */

namespace PagesCo\Books\Shortcodes;

use PagesCo\Books\EventsTable;
use PagesCo\Books\Feature;
use PagesCo\Books\Settings;

/**
 * Lists the shop's events from the custom table.
 */
final class EventsShortcode implements Feature {

	/**
	 * The shortcode's tag.
	 */
	public const TAG = 'pagesco_events';

	/**
	 * Registers the shortcode on init.
	 */
	public function register(): void {
		add_action( 'init', array( $this, 'add_shortcode' ) );
	}

	/**
	 * Tells WordPress which callback renders [pagesco_events].
	 */
	public function add_shortcode(): void {
		add_shortcode( self::TAG, array( $this, 'render' ) );
	}

	/**
	 * Returns the list of events as HTML.
	 *
	 * @param array|string $atts limit (default: the Events to show setting) and location (default: all).
	 * @return string
	 */
	public function render( $atts ) {
		$atts = shortcode_atts(
			array(
				'limit'    => Settings::get( 'events_limit' ),
				'location' => '',
			),
			$atts,
			self::TAG
		);

		$limit  = min( 50, max( 1, absint( $atts['limit'] ) ) );
		$events = EventsTable::find( $limit, sanitize_text_field( $atts['location'] ) );

		if ( ! $events ) {
			return '<p class="pagesco-events-empty">' . esc_html__( 'No events are scheduled right now. Check back soon!', 'pagesco-books' ) . '</p>';
		}

		$items = '';
		foreach ( $events as $event ) {
			$seats = (int) $event->capacity
				/* translators: %d: number of seats. */
				? sprintf( _n( '%d seat', '%d seats', (int) $event->capacity, 'pagesco-books' ), (int) $event->capacity )
				: __( 'open to all', 'pagesco-books' );

			$items .= sprintf(
				'<li class="pagesco-event"><strong>%1$s</strong> <time datetime="%2$s">%3$s</time> <span class="pagesco-event__where">%4$s, %5$s</span></li>',
				esc_html( $event->title ),
				esc_attr( mysql2date( 'Y-m-d\TH:i', $event->starts_at, false ) ),
				esc_html( mysql2date( 'l, F j, g:i a', $event->starts_at ) ),
				esc_html( $event->location ),
				esc_html( $seats )
			);
		}

		return '<ul class="pagesco-events">' . $items . '</ul>';
	}
}

Dates are formatted with mysql2date(), which reads a MySQL DATETIME string as it is (the shop's local time) and translates the month and day names on a non-English site; the datetime attribute keeps a machine-readable copy. limit is clamped between 1 and 50, so [pagesco_events limit="100000"] cannot ask MySQL for a huge list, and location is sanitized and then passed as a %s placeholder. <?php
/**
 * Plugin Name: Exercise: Book Slug

add_filter(
	'shortcode_atts_pagesco_book',
	function ( $out, $pairs, $atts ) {
		if ( is_array( $atts ) && ! empty( $atts['slug'] ) ) {
			$book = get_page_by_path( sanitize_title( $atts['slug'] ), OBJECT, 'book' );
			if ( $book ) {
				$out['id'] = $book->ID;
			}
		}
		return $out;
	},
	10,
	3
);

❓ Common Questions at This Stage

Why are past events still listed?

The shortcode lists the table in date order and leaves the calendar's upkeep to whoever manages it: the seeded events are the coming season's, and the list always shows the first few. A real shop would hide events that have ended, either in the query (WHERE starts_at >= %s with current_time( 'mysql' ), a nice extension to try) or by clearing old rows on a schedule, the kind of job WP-Cron does in Lesson 7.3.

Why not store events as a post type, like books?

It would work, and for a shop that writes long event descriptions with images, a post type might even be better: the editor, revisions and REST come free. Pages & Co.'s events are short, structured rows listed by date, which is exactly where a table shines, and building one teaches you the tools (dbDelta(), migrations, $wpdb) that you need for data that can never be posts, such as orders, bookings or logs. In Lesson 7.2 the events get a REST route of their own, /pagesco/v1/events, since core's routes do not know about your table.

Should deactivation drop the table?

No. Deactivating is often temporary (troubleshooting, an update); dropping the table would destroy the calendar every time. Deactivation undoes runtime effects such as rewrite rules and scheduled events; only uninstall.php deletes data. The table is also included in wp db export backups automatically, because it lives in the same database with the same prefix.

Do shortcodes still work in block themes and the Site Editor?

Yes, wherever content is filtered through do_shortcode(): post content (in a paragraph or the Shortcode block) and classic widgets. The Shortcode block also renders shortcodes typed into templates in the Site Editor. What you do not get is a preview in the editor: editors see [pagesco_events] as text. That is the main reason Module 6 turns the book card into a block.

📝 Lesson Summary

🎓 Key Takeaways

  • A shortcode is add_shortcode( $tag, $callback ) on init; the callback returns escaped HTML and never echoes
  • shortcode_atts( $defaults, $atts, $tag ) fills defaults, drops undeclared attributes and creates the shortcode_atts_{$tag} filter; validate every attribute as untrusted input
  • Choose a custom table only for many uniform rows queried by their fields; post types, taxonomies and options come with far more for free
  • dbDelta() creates a table or adds missing columns and indexes from a carefully formatted CREATE TABLE; it never renames or drops
  • Store a schema version in an option, compare it on every request, and raise it with every schema change, because plugin updates do not rerun activation
  • Every $wpdb value goes through placeholders (%s, %d, %f, %i) in prepare() or the format arrays of insert(), update() and delete()

🔁 Lesson 4.1: The Loop & Template Tags

Module 3 built Pages & Co. the modern way, from blocks. Now you step into the world most existing WordPress sites still live in: classic themes, where every template is a PHP file. At the heart of each one is a few lines of code called the Loop, plus a family of small functions, the template tags, that print a post's title, date, author and content. You will build pagesco-classic, the shop's classic theme, from a single file to a set of templates and template parts, and finish by giving it a theme.json, which makes it a hybrid.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Explain what the Loop does with the main query, step by step, and write it correctly with have_posts() and the_post()
  • Use template tags and their the_ / get_ pairs, and choose between printing and returning (and escaping) a value
  • Split a classic theme into header.php, footer.php and template parts with get_template_part(), including passing arguments
  • Use conditional tags such as is_home(), is_singular() and is_search(), and say when they work and when they are called too early
  • Build pagesco-classic with index.php, singular.php and 404.php, and turn it into a hybrid theme with theme.json

  • 📋 Prerequisites Lesson 3.4: Child Themes & Customizing Existing Themes
  • 🛠️ You will build pagesco-classic, a classic theme for Pages & Co. with templates, template parts and a theme.json, active for the rest of Module 4
  • 🧩 WordPress 7.1 on PHP 8.5 (nothing here needs 7.x; passing arguments to get_template_part() needs WordPress 5.5 or later)

🔁 The Loop

Before WordPress loads a single template, it has already done the hard part. In Lesson 3.1 you watched template-loader.php choose a template; just before that, WordPress turned the URL into a database query and ran it. That query is the main query, and its results wait in the global $wp_query object (Lesson 1.3 named it): one post for /hello-world/, the three News posts for /category/news/, every match for /?s=dune. A classic template does not fetch posts. It only walks through the list WordPress already found, and that walk is the Loop.

💡 Mental model: the reading list at the till

A customer hands the bookseller a list of books they ordered. The bookseller does not search the shop again; the list is done. They go down it one line at a time: "is there another book on the list?" (have_posts()), "take the next one off the pile and put it on the counter" (the_post()), then read out its title, author and price (template tags), and start again. When the list is empty, they stop. If they forget to take the next book off the pile, they read out the same title forever.

A classic theme in two files

You met a throwaway classic theme in Lesson 3.1. This time you build one to keep. Create the folder wordpress/wp-content/themes/pagesco-classic/ and its header, style.css. It follows the rules from Lesson 3.2: the text domain matches the folder, and so does the function prefix you will use, pagesco_classic_:

Then the one template every theme must have, index.php. A classic template prints the whole document, so it calls wp_head(), wp_body_open() and wp_footer() itself (Lesson 3.1's third Common Mistake, and the reason your store notice from Lesson 2.3 will appear). The <title> comes from wp_get_document_title() for now; Lesson 4.3 hands that job to WordPress with a theme support. The Loop is the if / while block in the middle:

<?php
/**
 * The main template file. For now it does everything itself.
 *
 * @package pagesco-classic
 */

?>
<!DOCTYPE html>
<html <?php language_attributes(); ?>>
<head>
	<meta charset="<?php bloginfo( 'charset' ); ?>">
	<title><?php echo esc_html( wp_get_document_title() ); ?></title>
	<?php wp_head(); ?>
</head>
<body <?php body_class(); ?>>
<?php wp_body_open(); ?>
<main>
	<?php
	if ( have_posts() ) {
		while ( have_posts() ) {
			the_post();
			the_title( '<h2>', '</h2>' );
		}
	} else {
		echo '<p>Nothing here yet.</p>';
	}
	?>
</main>
<?php wp_footer(); ?>
</body>
</html>

On a single post or page, the main query holds one post, and classic templates still run the Loop over it. That is why you will see while ( have_posts() ) even in templates that only ever show one post.

What the four functions do

The Loop functions are thin wrappers around the main query. They live in wp-includes/query.php, and each one hands the work to the matching method of the WP_Query class in wp-includes/class-wp-query.php:

grep -n "^function have_posts\|^function the_post\|^function rewind_posts\|^function in_the_loop" wp-includes/query.php

Output

961:function have_posts() {
984:function in_the_loop() {
1001:function rewind_posts() {
1018:function the_post() {
  • have_posts() is $wp_query->have_posts(): true while there is a next post. When the list runs out it fires the loop_end action and rewinds, so a second Loop on the same page starts from the top.
  • the_post() moves to the next post and calls setup_postdata(), which sets the global $post (Lesson 1.3) and a few helpers such as the author. Every template tag reads that global. The first call also fires loop_start.
  • in_the_loop() tells code (and blocks, as you will see in Lesson 4.2) whether the Loop is running right now; rewind_posts() starts the list again.

⚠️ No the_post(), no end

while ( have_posts() ) { the_title(); } never ends: without the_post() the list never moves on, so have_posts() stays true and the same title is printed again and again until PHP's time limit stops the request (30 seconds in the course container, max_execution_time). If a page of your classic theme hangs and then fails, look for a Loop without the_post() first.

🏷️ Template Tags

the_title() is a template tag: a function that prints something about the current post. WordPress has dozens of them, and they come in pairs. A function starting with the_ prints the value, ready for HTML; its partner starting with get_ (or get_the_) returns it, so you can store it, test it or pass it somewhere else. Replace the Loop's body in index.php with a small article per post:

<?php
/**
 * The main template file. For now it does everything itself.
 *
 * @package pagesco-classic
 */

?>
<!DOCTYPE html>
<html <?php language_attributes(); ?>>
<head>
	<meta charset="<?php bloginfo( 'charset' ); ?>">
	<title><?php echo esc_html( wp_get_document_title() ); ?></title>
	<?php wp_head(); ?>
</head>
<body <?php body_class(); ?>>
<?php wp_body_open(); ?>
<main>
	<?php
	if ( have_posts() ) {
		while ( have_posts() ) {
			the_post();
			?>
			<article id="post-<?php the_ID(); ?>" <?php post_class(); ?>>
				<h2><a href="<?php the_permalink(); ?>"><?php the_title(); ?></a></h2>
				<p><?php echo esc_html( get_the_date() ); ?> by <?php the_author(); ?></p>
				<?php the_excerpt(); ?>
			</article>
			<?php
		}
	} else {
		echo '<p>Nothing here yet.</p>';
	}
	?>
</main>
<?php wp_footer(); ?>
</body>
</html>

One line at a time: the_ID() printed 16. post_class() printed a whole class="…" attribute describing the post (its ID, post type, status, format and category), the classic counterpart of the classes block themes add; stylesheets and plugins rely on them, so always include it. the_permalink() printed the URL, the_title() the title, get_the_date() returned the date in the format from Settings > General, which esc_html() escaped before echo, the_author() printed the author's display name, and the_excerpt() built a short summary from the content, because the post has no hand-written excerpt: up to 55 words of text, markup removed, wrapped in a paragraph. Notice what is missing: the list of three books. The excerpt is built only from blocks that excerpt_remove_blocks() (wp-includes/blocks.php) counts as text, and a list whose items are core/list-item blocks is skipped. When a summary matters, write the excerpt by hand in the editor's Excerpt panel.

🛑 Printing is not the same as escaping

The the_ tags print values WordPress has prepared for HTML: the_permalink() runs esc_url(), the_content() runs the content filters (Lesson 2.3's Exercise 3 listed them), the_title() runs the title filters. What they prepare is HTML text, not an attribute value. When you put a value into an attribute, or print something you got from a get_ function, escape it yourself for that spot, the rule from Lesson 1.3: esc_attr( get_the_title() ) or the_title_attribute() in title="…", esc_url( get_permalink() ) in href, esc_html( get_the_date() ) as you just did.

One tag has a surprise in it. the_date() prints the date only for the first post of each day: its source in wp-includes/general-template.php checks is_new_day() and prints nothing for the second post published on the same day. That made sense for old blog layouts with a date heading per day; for a list where every post shows its date, use get_the_date() (or the_time( get_option( 'date_format' ) )), as this theme does.

🧩 Template Parts

Every template needs the same head, header and footer. Copying them into index.php, singular.php and 404.php would mean three places to fix every change. Classic themes split the page into pieces and load them with a few functions:

FunctionLoads (child theme first, then parent; Lesson 3.4)
get_header() / get_header( 'shop' )header.php / header-shop.php
get_footer(), get_sidebar()footer.php, sidebar.php
get_template_part( 'template-parts/content' )template-parts/content.php
get_template_part( 'template-parts/content', 'none' )template-parts/content-none.php, else template-parts/content.php
get_template_part( $slug, $name, $args )the same, with $args available inside the part as $args

All of them go through locate_template() (wp-includes/template.php), the function you watched switch from parent to child in Lesson 3.4, so a child theme of pagesco-classic could replace any part. Note that you pass the path without .php; Common Mistakes shows what happens otherwise. Create the header part, header.php. It is the top of the old index.php, plus a viewport meta tag and a site header that links the shop's name to the home page:

<?php
/**
 * The header: the document head and the top of every page.
 *
 * @package pagesco-classic
 */

?>
<!DOCTYPE html>
<html <?php language_attributes(); ?>>
<head>
	<meta charset="<?php bloginfo( 'charset' ); ?>">
	<meta name="viewport" content="width=device-width, initial-scale=1">
	<title><?php echo esc_html( wp_get_document_title() ); ?></title>
	<?php wp_head(); ?>
</head>
<body <?php body_class(); ?>>
<?php wp_body_open(); ?>
<header class="site-header">
	<p class="site-title"><a href="<?php echo esc_url( home_url( '/' ) ); ?>"><?php bloginfo( 'name' ); ?></a></p>
</header>
<main id="main" class="site-main">

It ends with an open <main>; footer.php closes it, prints the shop's address with a translatable string (Lesson 1.3) and calls wp_footer():

<?php
/**
 * The footer: the end of the main content and the bottom of every page.
 *
 * @package pagesco-classic
 */

?>
</main>
<footer class="site-footer">
	<p><?php esc_html_e( 'Pages & Co. · 12 Market Street · 555-0142', 'pagesco-classic' ); ?></p>
</footer>
<?php wp_footer(); ?>
</body>
</html>

Next, the article itself becomes a part, template-parts/content.php, so every list in the theme (the blog home, archives, search, and the front page you build in Lesson 4.2) shows posts the same way. Three changes from the version in index.php: the "by" line is now one translatable sentence with placeholders, a machine-readable <time datetime> wraps the date, and the date and author only appear for posts (search results can include pages). The heading level comes from $args, defaulting to 2, so a page that lists posts under an <h2> section heading can ask for <h3>:

<?php
/**
 * One post in a list: title, date and author, excerpt.
 *
 * @package pagesco-classic
 */

$pagesco_classic_level = isset( $args['heading_level'] ) ? absint( $args['heading_level'] ) : 2;
?>
<article id="post-<?php the_ID(); ?>" <?php post_class(); ?>>
	<?php the_title( '<h' . $pagesco_classic_level . ' class="entry-title"><a href="' . esc_url( get_permalink() ) . '">', '</a></h' . $pagesco_classic_level . '>' ); ?>
	<?php if ( 'post' === get_post_type() ) : ?>
		<p class="entry-meta">
			<?php
			printf(
				/* translators: 1: publish date, 2: author name. */
				esc_html__( '%1$s by %2$s', 'pagesco-classic' ),
				'<time datetime="' . esc_attr( get_the_date( 'c' ) ) . '">' . esc_html( get_the_date() ) . '</time>',
				esc_html( get_the_author() )
			);
			?>
		</p>
	<?php endif; ?>
	<div class="entry-summary">
		<?php the_excerpt(); ?>
	</div>
</article>

$args is whatever array the template passed as the third argument of get_template_part(), or an empty array; absint() (Lesson 1.3) makes sure only a number ends up in the tag name. The variable gets the theme's prefix because a template part shares its variables with nothing else, but WordPress coding standards treat it like a global (Lesson 3.3's patterns did the same). And a part for empty lists, template-parts/content-none.php, which says something more helpful on a search with no results:

<?php
/**
 * Shown when a list has no posts.
 *
 * @package pagesco-classic
 */

?>
<section class="no-results">
	<?php if ( is_search() ) : ?>
		<p><?php esc_html_e( 'No books or posts matched your search. Try another word.', 'pagesco-classic' ); ?></p>
		<?php get_search_form(); ?>
	<?php else : ?>
		<p><?php esc_html_e( 'Nothing here yet.', 'pagesco-classic' ); ?></p>
	<?php endif; ?>
</section>

❓ Conditional Tags

index.php asked is_home() and is_search() to choose its heading. Those are conditional tags: functions that answer yes or no about the current request. You have seen their names before, in Lesson 3.1, as the questions template-loader.php asks to pick a template. A theme asks the same questions to vary a template, and plugins ask them to decide whether to do something on this page.

TagTrue when the request is…
is_front_page()the site's front page, whatever it shows (Lesson 3.1)
is_home()the list of latest posts, wherever it lives
is_singular() / is_singular( 'post' )one post, page or other post type / one of that type
is_single(), is_page( 'about' )a single post (not a page) / that page (slug, ID or title)
is_archive(), is_category( 'news' ), is_author(), is_date()any archive / that category / an author / a date archive
is_search(), is_404(), is_paged()search results / not found / page 2 or later of a list (Lesson 4.2)
has_category(), has_excerpt(), in_the_loop()about the current post or the Loop rather than the request

They all read the main query (is_home() is $wp_query->is_home()), so they only know the answer after WordPress has run it. A small must-use plugin can show you their answers for a few URLs. It asks on template_redirect, the action from Lesson 2.3 that fires after the query and before the template. Create wordpress/wp-content/mu-plugins/pagesco-conditions.php:

<?php
/**
 * Plugin Name: Pages & Co. Conditions
 * Description: Lesson 4.1 tool: logs which conditional tags are true on each front-end request.
 */

/**
 * Writes the request path and the conditional tags that are true to debug.log.
 */
function pagesco_log_conditions() {
	$tags = array( 'is_front_page', 'is_home', 'is_singular', 'is_single', 'is_page', 'is_archive', 'is_category', 'is_author', 'is_search', 'is_404' );
	$true = array_filter( $tags, 'call_user_func' );

	$path = isset( $_SERVER['REQUEST_URI'] ) ? sanitize_text_field( wp_unslash( $_SERVER['REQUEST_URI'] ) ) : '';

	error_log( $path . ' -> ' . implode( ', ', $true ) );
}
add_action( 'template_redirect', 'pagesco_log_conditions' );

array_filter() calls call_user_func() with each function name and keeps the ones that return true. The request path comes from $_SERVER, so it is unslashed and sanitized before it is logged (Lesson 1.3). Request seven URLs from the WP-CLI container and read the log:

⚠️ Common Mistakes

For the first three, use a scratch template that the hierarchy picks for one URL only. From Lesson 3.1 you know category-news.php beats index.php for /category/news/, so every other page stays untouched while you experiment. You delete it at the end.

1. Concatenating a tag that prints

<?php
get_header();

while ( have_posts() ) {
	the_post();
	echo '<h2 class="mistake">' . the_title() . '</h2>';
}

get_footer();

Output (View Source)

<main id="main" class="site-main">
Book club: Dune<h2 class="mistake"></h2>Staff picks for the season<h2 class="mistake"></h2>Welcome to the new Pages &#038; Co. website<h2 class="mistake"></h2></main>

What it means: each title sits before an empty heading. PHP evaluates the whole expression on the right of echo first; while doing that it calls the_title(), which prints the title immediately and returns nothing (null), so the string that echo finally prints is <h2 class="mistake"></h2>. No error, just broken markup. Fix: inside a string, use the returning version, echo '<h2>' . esc_html( get_the_title() ) . '</h2>';, or let the tag wrap itself: the_title( '<h2>', '</h2>' );.

	the_post();

What it means: the block comments from Lesson 2.1 are in the page. get_the_content() returns post_content as it is stored; only the_content() runs the the_content filters, and those are what render blocks (do_blocks), expand shortcodes, turn image tags responsive and so on. ❓ Common Questions at This Stage

Does the_post() query the database for each post?

No. The main query fetched all the posts for the page in one go before the template ran, and the first call to the_post() also loads their authors into the cache at once (you can read that in WP_Query::the_post()). The Loop itself only moves a pointer through an array. What can cost a query per post is code you add inside it, such as fetching something for each post that is not cached; Lesson 8.2 measures that.

Why do some themes write endwhile; and endif; instead of braces?

That is PHP's alternative syntax (while ( have_posts() ) : the_post(); … endwhile;), common in templates because a lone endwhile; between blocks of HTML is easier to match than a }. Both work the same; this course uses braces in PHP-heavy code and the colon form around HTML (if ( … ) : ?> … <?php endif;), as in index.php's heading.

What does the Query Loop block have to do with this?

Everything. When a block theme's Query Loop is set to "inherit" the query, as in pagesco's templates, its Post Template block walks the very same $wp_query you looped over today; otherwise it builds a new WP_Query from its settings. You can read both branches in wp-includes/blocks/post-template.php. Lesson 4.2 writes those custom queries by hand, and Module 6's dynamic blocks use them in PHP.

Should I make a new classic theme for a client today?

Usually not: for a new site, a block theme gives the owner the Site Editor and you less PHP to maintain. You will still read and extend classic themes constantly, because most existing sites use them, and the Loop and template tags are also how plugins and dynamic blocks print posts. This module is about being fluent in both.

🎓 Key Takeaways

  • WordPress runs the main query before any template; the Loop (while ( have_posts() ) { the_post(); … }) walks its results, one post at a time, even on single posts
  • the_post() sets the global $post that every template tag reads; without it the Loop never ends
  • Template tags come in pairs: the_ prints HTML-ready text, get_ returns the value for you to escape for its context (esc_attr, esc_url, esc_html)
  • get_the_content() is raw block markup; the_content() renders it. the_date() prints once per day; get_the_date() every time
  • get_header(), get_footer() and get_template_part( $slug, $name, $args ) load parts through locate_template(), child theme first; no .php in the slug
  • Conditional tags read the main query, so they work in templates and in hooks from template_redirect on, and return false with a notice before that
  • A classic theme with a theme.json is a hybrid: presets and global styles, but no styles.css custom CSS

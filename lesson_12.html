🔎 Lesson 4.2: Custom Queries

Every Loop in Lesson 4.1 walked the main query, the list WordPress chose from the URL. Real pages need more: a front page with a welcome, the shop's pages and the latest news, a "More from the shop" box under each post, news pages of three posts each. In this lesson you ask WordPress for your own lists with WP_Query, change the main query the right way with pre_get_posts, add pagination that never ends in a 404, and learn the one cleanup call that keeps template tags pointing at the right post.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Tell the main query from secondary queries, and pick WP_Query, get_posts() or pre_get_posts for a task
  • Write WP_Query arguments for post types, categories, authors, dates, searches, ordering and limits, and read found_posts and max_num_pages
  • Run a secondary Loop on the same page as the main one and restore the current post with wp_reset_postdata()
  • Change the main query with a pre_get_posts callback guarded by is_main_query() and is_admin()
  • Paginate lists with the_posts_pagination(), and explain why paging a custom query in a template leads to a 404
  • ⏱️ Time 130 minutes
  • 📋 Prerequisites Lesson 4.1: The Loop & Template Tags
  • 🛠️ You will build functions.php with a pre_get_posts callback, paginated news, a front-page.php with several Loops, and a related-posts box for pagesco-classic
  • 🧩 WordPress 7.1 on PHP 8.5 (everything here works the same on any recent WordPress; WP_Query is unchanged in 7.x)
  • 🧱 Site your Pages & Co. site from Lesson 4.1, with pagesco-classic active

🗂️ The Main Query and Your Own Queries

For each request WordPress builds exactly one main query: it turns the URL into query variables (category_name=news, s=dune, paged=2), runs one WP_Query with them, and keeps the result in $wp_query. The template hierarchy, the conditional tags and the Loop of Lesson 4.1 all work from that one object. Any other list on the page comes from a secondary query: a WP_Query object your code creates with arguments of its own.

💡 Mental model: the customer's order and the shop's displays

The main query is the customer's order at the counter: they asked for News, so they get News, and the whole page is organized around it. Secondary queries are the displays the shop sets up next to the counter: "staff picks", "you might also like". They never change the customer's order. And when you want the order itself to be different, say "news comes in bundles of three", you do not grab the receipt after it is printed; you tell the person taking orders before they write it down. That is pre_get_posts.

⚙️ WP_Query Arguments

WP_Query takes one array of arguments, the arguments-array pattern from Lesson 1.3, and runs the query as soon as you create it. You met its SQL in Lesson 2.2; now you use it as a developer does, through the arguments. Save this as wordpress/query-news.php and run it from the WP-CLI container:

<?php
$pagesco_query = new WP_Query(
	array(
		'category_name'  => 'news',
		'posts_per_page' => 2,
		'orderby'        => 'title',
		'order'          => 'ASC',
	)
);

printf(
	"found_posts: %d, max_num_pages: %d, post_count: %d\n",
	$pagesco_query->found_posts,
	$pagesco_query->max_num_pages,
	$pagesco_query->post_count
);

while ( $pagesco_query->have_posts() ) {
	$pagesco_query->the_post();
	echo get_the_ID(), '  ', get_the_title(), "\n";
}

wp_reset_postdata();
wp eval-file query-news.php

Output

found_posts: 3, max_num_pages: 2, post_count: 2
17  Book club: Dune
16  Staff picks for the season

The query object carries three numbers you will use for pagination: post_count is how many posts it holds now (2, the page size), found_posts how many match in total (3 News posts), and max_num_pages how many pages of 2 that makes. The Loop is the one from Lesson 4.1, but every call goes to your object: $pagesco_query->have_posts() and $pagesco_query->the_post(). The bare have_posts() would ask the main query. the_post() on your object still sets the global $post, which is why the template tag get_the_title() works, and why wp_reset_postdata() at the end puts the global back (more on that in the next section).

Try several at once. This file runs one query per line and prints the titles each one found. Save it as wordpress/query-args.php:

<?php
/**
 * Runs a WP_Query and prints the titles it found.
 */
function pagesco_show_query( $label, $args ) {
	$query  = new WP_Query( $args );
	$titles = wp_list_pluck( $query->posts, 'post_title' );
	printf( "%-12s %s  (found_posts: %d)\n", $label, implode( ', ', $titles ), $query->found_posts );
}

pagesco_show_query( 'pages:', array( 'post_type' => 'page', 'post_name__in' => array( 'about', 'events', 'contact' ), 'orderby' => 'post_name__in' ) );
pagesco_show_query( 'devon:', array( 'author_name' => 'devon' ) );
pagesco_show_query( 'september:', array( 'date_query' => array( array( 'year' => 2026, 'month' => 9 ) ), 'order' => 'ASC' ) );
pagesco_show_query( 'club:', array( 's' => 'club', 'post_type' => 'any' ) );
pagesco_show_query( 'not news:', array( 'tax_query' => array( array( 'taxonomy' => 'category', 'field' => 'slug', 'terms' => 'news', 'operator' => 'NOT IN' ) ) ) );
pagesco_show_query( 'newest 2:', array( 'posts_per_page' => 2, 'no_found_rows' => true ) );
wp eval-file query-args.php

Line by line: post_name__in with 'orderby' => 'post_name__in' returned the three pages in the order you listed the slugs (by slug, so the code works on any copy of the site). Devon wrote one post. The date_query found the two September posts, oldest first. The search with 'post_type' => 'any' found a post and a page ("book clubs" is in the Events page). The NOT IN tax query left only Hello world! (Uncategorized). And the last line shows found_posts: 0: with no_found_rows WordPress skips the extra counting query (the SQL_CALC_FOUND_ROWS you saw in Lesson 2.2), which is the right choice for any list you will not paginate.

🔂 Secondary Loops and wp_reset_postdata()

A secondary Loop inside a template looks exactly like the one in query-news.php. The only new thing is what happens around it: the template was already showing a post from the main query, and $secondary->the_post() just replaced the global $post with the secondary query's post. Until something puts it back, every template tag after your Loop talks about the wrong post.

wp_reset_postdata() puts it back: it is a short function in wp-includes/query.php that asks the main query to set the global $post to its current post again:

grep -n "^function wp_reset_postdata" -A 7 wp-includes/query.php

Output

131-		$wp_query->reset_postdata();
132-	}

The rule is simple: every Loop over your own WP_Query ends with wp_reset_postdata(), right after the while, even when nothing seems to need it yet. Somebody will add a template tag below your Loop one day. You will see the failure in Common Mistakes and build the box correctly in the project.

💡 get_posts() needs no reset

get_posts() runs a WP_Query for you and returns the array of WP_Post objects, without touching the global $post, so there is nothing to reset as long as you pass each post to the functions you call (get_the_title( $post ), get_permalink( $post )) instead of calling setup_postdata(). Its defaults differ from WP_Query's, as you can read in get_posts() in wp-includes/post.php: 5 posts (numberposts), suppress_filters true, sticky posts ignored and no counting. Exercise 2 uses it.

🎚️ Changing the Main Query: pre_get_posts

The shop wants the news on the home page in pages of three. The tempting way is to ignore the main query in the template and run your own WP_Query with 'posts_per_page' => 3. It looks right on page 1 and breaks on page 2 (Common Mistakes, number 1), because WordPress decides whether /page/2/ exists from the main query. The right way is to change the main query itself, before it runs. WP_Query::get_posts() fires an action for that just before it builds the SQL:

grep -n "do_action_ref_array( 'pre_get_posts'" wp-includes/class-wp-query.php

Output

1916:		do_action_ref_array( 'pre_get_posts', array( &$this ) );

The action passes the query object, and your callback changes it with $query->set(). It fires for every WP_Query: the main one, every secondary one, the admin's post lists, WP-CLI's. So a callback first makes sure it has the query it means. Display choices belong to the theme, so this goes into pagesco-classic's first functions.php. You met functions.php in a child theme in Lesson 3.4; Lesson 4.3 is all about this file. Create wordpress/wp-content/themes/pagesco-classic/functions.php:

<?php
/**
 * Pages & Co. Classic functions and definitions.
 *
 * @package pagesco-classic
 */

/**
 * Shows three posts per page on the blog home.
 *
 * @param WP_Query $query The query WordPress is about to run.
 */
function pagesco_classic_adjust_main_query( $query ) {
	if ( is_admin() || ! $query->is_main_query() ) {
		return;
	}

	if ( $query->is_home() ) {
		$query->set( 'posts_per_page', 3 );
	}
}
add_action( 'pre_get_posts', 'pagesco_classic_adjust_main_query' );
  • is_admin(): leave the admin screens alone (their lists have their own "per page" setting).
  • $query->is_main_query(): only the main query, never a box somebody adds later.
  • $query->is_home(): ask the query object, not the global is_home(). While pre_get_posts runs, the main query has parsed the URL (so its is_home() knows the answer), but the global functions are only reliable once it is finished.
  • It is an action: the object is changed in place, nothing is returned.

Three posts on the home page; the News archive still shows all three of its posts because the callback only touches the blog home. The fourth post, Welcome, is on page 2 now, and visitors need a way to get there.

📄 Pagination

For the main query, pagination is one call. the_posts_pagination() reads max_num_pages and the current page from $wp_query and prints an accessible navigation block with page numbers. Add it to index.php, after the Loop and inside the if, so empty lists get no pagination:

<?php
/**
 * The main template: the blog home, archives and search results.
 *
 * @package pagesco-classic
 */

get_header();
?>
<header class="page-header">
	<?php if ( is_home() ) : ?>
		<h1><?php esc_html_e( 'News from the shop', 'pagesco-classic' ); ?></h1>
	<?php elseif ( is_search() ) : ?>
		<h1><?php /* translators: %s: the search terms. */ printf( esc_html__( 'Search results for: %s', 'pagesco-classic' ), esc_html( get_search_query( false ) ) ); ?></h1>
	<?php else : ?>
		<?php the_archive_title( '<h1>', '</h1>' ); ?>
		<?php the_archive_description( '<div class="archive-description">', '</div>' ); ?>
	<?php endif; ?>
</header>

<?php
if ( have_posts() ) {
	while ( have_posts() ) {
		the_post();
		get_template_part( 'template-parts/content' );
	}

	the_posts_pagination();
} else {
	get_template_part( 'template-parts/content', 'none' );
}

get_footer();

Page 1 is the current page (aria-current="page", not a link), page 2 is a link, and so is "Next". The visually hidden heading tells screen reader users what the links are. Now follow it, and try one page too far:

curl -s http://localhost:8080/page/2/ | grep -o '<title>.*</title>\|<h2 class="entry-title"><a [^>]*>[^<]*'
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/page/3/

Output

<title>Pages &amp; Co. &#8211; Page 2</title>
<h2 class="entry-title"><a href="http://localhost:8080/welcome/">Welcome to the new Pages &#038; Co. website
404

Page 2 holds the one remaining post and WordPress added "Page 2" to the document title by itself. Page 3 does not exist, so WordPress answers 404 before your template runs. All of that works because the main query and the pagination agree: there is only one query.

For a secondary query, the template has to pass the numbers itself: paginate_links( array( 'total' => $query->max_num_pages ) ) prints the links, and the query must be created with 'paged' => max( 1, get_query_var( 'paged' ) ). That only makes sense for a list that is not the page's main content, and Common Mistakes shows why it is fragile.

⚠️ Common Mistakes

1. Paging a custom query in the template

A developer wants pages of two posts in the News archive and, instead of pre_get_posts, writes a category-news.php that ignores the main query and runs its own, with paged and paginate_links():

<?php
get_header();

$pagesco_classic_news = new WP_Query(
	array(
		'category_name'  => 'news',
		'posts_per_page' => 2,
		'paged'          => max( 1, get_query_var( 'paged' ) ),
	)
);

while ( $pagesco_classic_news->have_posts() ) {
	$pagesco_classic_news->the_post();
	get_template_part( 'template-parts/content' );
}

echo wp_kses_post( paginate_links( array( 'total' => $pagesco_classic_news->max_num_pages ) ) );
wp_reset_postdata();

get_footer();
curl -s http://localhost:8080/category/news/ | grep -o '<h2 class="entry-title"><a [^>]*>[^<]*\|<a class="[^"]*page-numbers" href="[^"]*">[^<]*' | sed 's/<h2[^>]*>//'
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/category/news/page/2/

Output

<a href="http://localhost:8080/book-club-dune/">Book club: Dune
<a href="http://localhost:8080/staff-picks/">Staff picks for the season
<a class="page-numbers" href="http://localhost:8080/category/news/page/2/">2
<a class="next page-numbers" href="http://localhost:8080/category/news/page/2/">Next &raquo;
404

What it means: page 1 looks perfect, with two posts and a link to page 2. The link answers 404. Before any template runs, WordPress runs the main query for /category/news/page/2/: ten posts per page (Settings > Reading), three News posts, so there is no page 2, and WordPress picks 404.php. Your category-news.php never gets the chance to run its own query. Fix: let the main query do the paging. In pre_get_posts, set posts_per_page for $query->is_category( 'news' ), keep the normal Loop, and use the_posts_pagination(). Delete the file:

rm wp-content/themes/pagesco-classic/category-news.php

2. A secondary Loop without wp_reset_postdata()

The shop wants a "More from the shop" box under each post, before the previous/next links. Add one line to singular.php, which loads a new template part just before the_post_navigation():

<?php
/**
 * A single post or page.
 *
 * @package pagesco-classic
 */

get_header();

while ( have_posts() ) {
	the_post();
	?>
	<article id="post-<?php the_ID(); ?>" <?php post_class(); ?>>
		<?php the_title( '<h1 class="entry-title">', '</h1>' ); ?>
		<?php if ( is_singular( 'post' ) ) : ?>
			<p class="entry-meta">
				<?php
				printf(
					/* translators: 1: publish date, 2: author name. */
					esc_html__( '%1$s by %2$s', 'pagesco-classic' ),
					'<time datetime="' . esc_attr( get_the_date( 'c' ) ) . '">' . esc_html( get_the_date() ) . '</time>',
					esc_html( get_the_author() )
				);
				?>
			</p>
		<?php endif; ?>
		<div class="entry-content">
			<?php the_content(); ?>
		</div>
		<?php if ( is_singular( 'post' ) && has_category() ) : ?>
			<p class="entry-terms"><?php esc_html_e( 'Filed under:', 'pagesco-classic' ); ?> <?php the_category( ', ' ); ?></p>
		<?php endif; ?>
	</article>
	<?php
	if ( is_singular( 'post' ) ) {
		get_template_part( 'template-parts/related-posts' );
		the_post_navigation();
	}
}

get_footer();

and write the part, template-parts/related-posts.php, with a secondary Loop over other posts from the same categories, but without the reset at the end:

<?php
/**
 * Up to two other posts from the current post's categories.
 *
 * @package pagesco-classic
 */

$pagesco_classic_related = new WP_Query(

		'category__in'        => wp_get_post_categories( get_the_ID() ),

	?>
	<aside class="related-posts">
		<h2><?php esc_html_e( 'More from the shop', 'pagesco-classic' ); ?></h2>
		<ul>
			<?php
			while ( $pagesco_classic_related->have_posts() ) {
				$pagesco_classic_related->the_post();
				the_title( '<li><a href="' . esc_url( get_permalink() ) . '">', '</a></li>' );
			}
			?>
		</ul>
	</aside>
	<?php
endif;

3. A pre_get_posts callback without guards

Someone wants "one post at a time" somewhere on the site and writes a must-use plugin with no checks at all:

<?php
add_action( 'pre_get_posts', 'pagesco_one_post_only' );

function pagesco_one_post_only( $query ) {
	$query->set( 'posts_per_page', 1 );
}

+----+------------+

+----+------------+

What it means: the site has four published pages (five with the Privacy Policy draft, and wp post list lists drafts too), but WP-CLI lists one, and get_posts() asked for all of them (-1) and got one. 4. A slug where an ID belongs

<?php
$pagesco_query = new WP_Query( array( 'cat' => 'news' ) );

echo implode( ', ', wp_list_pluck( $pagesco_query->posts, 'post_title' ) ), "\n";
wp eval-file mistake-cat.php
rm mistake-cat.php

Output

Hello world!, Book club: Dune, Staff picks for the season, Welcome to the new Pages & Co. website

What it means: all four posts, including Hello world! from Uncategorized, and no warning. cat expects category IDs; the string 'news' is not a number, so WordPress drops the filter and returns every post. Several arguments come in pairs like this (cat / category_name, author / author_name, p / name), and none of them complains about the wrong kind of value. Fix: 'category_name' => 'news' for a slug, and when a query returns "too much", check the argument names against the WP_Query reference before anything else.

🛠️ Project: A Front Page with Several Loops

pagesco-classic already pages its news. Now give it what the block theme's front page has (Lesson 3.3): a welcome, a way into the shop's pages, and the latest news, all on one page, plus a working "More from the shop" box under each post. Allow about 40 minutes.

🛠️ Step 1: front-page.php with three sections (15 min)

In the hierarchy front-page comes first for the site's front page (Lesson 3.1). Because Settings > Reading shows the latest posts, the main query on / is the news list, already three per page thanks to your pre_get_posts callback, and /page/2/ uses this template too. So the template keeps the main Loop for the news and adds a secondary query for the pages. On page 2 and later (is_paged()) it shows only the news, with an h1. Create wordpress/wp-content/themes/pagesco-classic/front-page.php:

<?php
/**
 * The front page: a welcome, the shop's pages, and the latest news.
 *
 * @package pagesco-classic
 */

get_header();

if ( ! is_paged() ) :
	?>
	<section class="hero">
		<h1><?php esc_html_e( 'Good books, good company', 'pagesco-classic' ); ?></h1>
		<p><?php esc_html_e( 'An independent bookstore with a big reading corner, a small café and staff who love to talk about books. Open late on Thursdays.', 'pagesco-classic' ); ?></p>
	</section>

	<?php
	$pagesco_classic_pages = new WP_Query(
		array(
			'post_type'     => 'page',
			'post_name__in' => array( 'about', 'events', 'contact' ),
			'orderby'       => 'post_name__in',
			'no_found_rows' => true,
		)
	);

	if ( $pagesco_classic_pages->have_posts() ) :
		?>
		<section class="visit-us">
			<h2><?php esc_html_e( 'Visit us', 'pagesco-classic' ); ?></h2>
			<ul>
				<?php
				while ( $pagesco_classic_pages->have_posts() ) {
					$pagesco_classic_pages->the_post();
					the_title( '<li><a href="' . esc_url( get_permalink() ) . '">', '</a></li>' );
				}

❓ Common Questions at This Stage

Why is query_posts() so often in old tutorials?

For years it was the easy way to "change what a template shows": it replaced the global $wp_query with a new query. But the original main query had already run (wasted work), pagination and conditional tags still came from the old one in parts of WordPress, and forgetting wp_reset_query() afterwards broke the rest of the page. Its own documentation now tells you not to use it. Translate old code: a change to the main list becomes pre_get_posts; an extra list becomes new WP_Query with wp_reset_postdata().

Pagination on a static front page uses page, not paged?

Yes, one of WordPress's oldest quirks. When Settings > Reading shows a static page as the front page, the page number of /page/2/ arrives in the query variable page, while every other list uses paged. Code that paginates a secondary query on such a front page reads both: max( 1, get_query_var( 'paged' ), get_query_var( 'page' ) ). Pages & Co. shows the latest posts on the front page, so the_posts_pagination() handles it for you.

How expensive is a WP_Query?

Usually one or two SQL queries (the posts, plus the counting query unless no_found_rows), then cached lookups for terms and meta, which you can switch off with update_post_term_cache / update_post_meta_cache set to false when you will not use them. Three or four small queries per page are nothing to worry about. A query inside a Loop that runs per post, posts_per_page => -1 on a growing list, or orderby => rand on thousands of posts are what slow sites down; Lesson 8.2 measures them.

Does the Query Loop block do pre_get_posts for me?

When its "inherit query from template" option is on, the block uses the main query, so your pre_get_posts callbacks apply to it as they do to a classic Loop. When it is off, the block builds its own WP_Query from its settings (Lesson 4.1's FAQ showed the code), and filters such as query_loop_block_query_vars change those. Module 6 builds blocks that run their own queries.

📝 Lesson Summary

🎓 Key Takeaways

  • Each request has one main query ($wp_query), built from the URL; every other list is a secondary query you create
  • new WP_Query( $args ) runs at once; Loop over it with $query->have_posts() / $query->the_post() and finish with wp_reset_postdata()
  • post_count (this page), found_posts (total) and max_num_pages drive pagination; no_found_rows skips the count for lists you do not paginate
  • pre_get_posts changes the main query before it runs; guard it with is_admin(), $query->is_main_query() and the query's own conditionals
  • the_posts_pagination() paginates the main query; paging a custom query in a template leads to 404s
  • get_posts() returns an array and leaves the global post alone; query_posts() belongs in old tutorials only
  • Argument pairs such as cat / category_name fail silently with the wrong kind of value
